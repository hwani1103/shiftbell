후속 최종 재점검 및 AK 권한 구현 — 2026-10-05

판정
브라질 포르투갈어 → 독일어 → 영어 → 힌디어 순서로 현재 Flutter/Android 전체 번역을 한국어 기능 의미·코드 도달 경로와 다시 비교했다. 1·2·3차의 완료 판정을 재사용하지 않았다. 후보를 먼저 기록한 뒤 기존 상세 변경 사유와 대조하고 후속 판정으로 연결했다.
외국어는 첫 출시다. 제공 기능만 설명하며 이전 한국어 사용/데이터별 예외를 제품 안내로 추가하지 않았다. 한국어 기능과 필요한 원문·사용자 자료를 보존했다. 커밋·배포·기기 설치는 수행하지 않았다.

개인 일정관리, 수면·회복과 수면 위젯, 앱 안 친구 공유, 원터치 알람, 한국 공휴일·음력, 한국어 전용 달력 테마 4종(initialBadge/eventChip/underline/editorial), 한국어 문의 채널.
외국어 근무표·팀표·근무 변경·근무별 알람·이력·메모·근무시간/OT·백업/복원·6종 테마·이메일 문의는 유지했다.
별도 공개 웹 달력/개인정보/소개는 외국어에서도 필요한 경로다. 앱 안 친구 진입의 제한을 웹 전체 제한으로 잘못 확장했던 회귀를 수정했다.

3차 판단과의 차이
fixedAlarmSkippedByOneTap의 “다른 알람” 일반화 4건을 철회·삭제했다. 시작 당시 표시 코드는 언어 직접 차단이 아니라 type=custom 충돌 조건이었다. 외국어 신규 정상 경로에서는 원터치를 만들지 못해 그 조건이 발생하지 않는 구조였다. 이번에는 해당 네 표시 위치에 명시적 한국어 조건도 추가했다. 원문/동작은 한국어 전용으로 유지한다.
스누즈가 실제 다른 근무 알람과 충돌하는 안내는 공통에 필요하므로 유지한다. 원터치를 다른 알람으로 다시 일반화한 안내를 만들지 않았다.
이전 미참조 목록의 모델 속성 이름(friendName 등), 고정 도움말 callback, 생성 API, 공개 웹 의존성, 직접 화면·시트·언어 변경을 함께 확인했다. 사용 경로 미확인이라는 이유만으로 삭제하지 않았다.
공통 스케줄 초기화/전체 삭제/근무 변경/복원 실패는 실제 외국어 결과만 설명한다. 한국어 전용 공유 실패 getter가 foreign 초기화에서 먼저 평가되는 회귀와 차단된 State의 initState가 DB를 먼저 읽는 회귀를 기능 검사로 발견하여 수정했다.
Firebase 한국 공휴일은 캐시 적용·조회 직전·응답 적용 직전에 언어를 확인한다. 한국어에서 이미 시작한 요청의 사후 취소 또는 실제 서버 0회 측정까지 성공했다고 주장하지 않는다.

리소스와 자동 대체
KoreanOnlyCopy.forLocale는 외국어 호출을 거절한다. common 한국어 template에서도 전용 키를 제거하여 generated foreign getter가 한국어를 대체하지 못하도록 했다.
Android는 korean_only.xml로 구분하고 실제 소비자를 한국어 기능 조건/KoreanFeatureStrings/외국어 중립 위젯 inflater로 제한했다.
5언어 common 키·ICU 변수/Android format 변수·요일·공통 근무명 검사를 유지했다. 누락 번역 보고는 {}다. 빈 문자열로 숨기지 않았다.
앱과 공개 웹은 releaseSupportedLocales/resolveReleaseLocale를 공유한다. 지원하지 않는 언어와 locale 없음은 영어로 해석하며 default 첫 ko locale 노출을 제거했다.
하드코딩 검색 목록과 도달 판정은 로그/주석/원본 데이터/한국어 기능/실제 UI를 구분한다. TextPainter 측정 표본은 표시 문구가 아니다. debug 광고 표시는 release에서 false다. 로컬 기술 진단 파일 자체에는 기존 한국어 원인 로그가 남으며, 이를 외국어 제품 UI나 진단 파일의 번역 완료로 계산하지 않는다.

AK 전체화면 권한 구현
AK와 AH/AJ 및 앞뒤 문서를 읽고 공통 네 권한(알림·오버레이·정확한 알람·전체화면 알림) 상태/UI를 구현했다.
OS의 granted/denied/unknown/notApplicable과 별도 알람 제어 채널 차단을 구별한다. API34+ canUseFullScreenIntent와 개별 설정 Intent, 현재 packageName/UID, Xiaomi/Redmi/POCO + 실제 OEM 관리 앱 유무, 표준 설정/앱 정보 fallback을 사용한다.
설정을 연 사실/안내를 읽은 사실을 허용으로 처리하지 않는다. 설정 복귀 시 상태를 다시 읽고 이전 비동기 결과·연타·설정 연쇄 실행·온보딩 중복 이동을 막는다. 온보딩/기존 배너/설정/도움말/복원은 같은 상태 구조를 사용한다.
한국어 포함 5언어로 설명을 제공했다. Xiaomi의 모든 OEM 권한을 표준 FSI API가 읽는다는 주장을 하지 않는다.
AGENTS.md와 tools/check_critical_release.ps1 및 권한_P0_회귀기준.txt에 P0로 고정했다. 향후 권한/언어 범위 변경에서 자동 검사와 실기기 검사 구분을 반드시 유지한다.

최종 검증
Flutter 기능 검사 101개 PASS. Native 권한/언어 Robolectric 12개 PASS. 이는 선택된 관련 회귀 묶음이며 저장소 모든 테스트 전체 실행의 의미가 아니다.
strict 한국어 전용 생성 + flutter gen-l10n PASS, 리소스 구조 검사 오류 0, 한국어 전용 원문 동일, untranslated {}.
전체 lib/test Dart 분석 오류 0/경고 0, 기존 스타일 info 654건. git diff --check PASS.
Android dev debug APK 및 공개 웹 JavaScript build PASS. Android dev release 최적화 빌드도 마지막 수정 후 PASS. 최종 APK/웹 산출물 해시와 로그는 검증_명세.json을 참조한다.
prod release는 실제 ADMOB_BANNER_ID 미주입으로 checkProdAdIds에서 차단됐다. 보호 검사를 우회하거나 test ID를 운영 빌드에 주입하지 않았다. 현재 운영 APK 생성 성공으로 표시하지 않는다.
웹 JS build는 성공했으나 Wasm 미지원(dart:html/js_util/기존 plugin) dry-run 및 CupertinoIcons font 경고가 있다. Wasm 빌드나 아이콘 실표시 검증을 완료로 처리하지 않는다.
초기 선택에 예전 reset 레이아웃/캡처 테스트가 섞여 실행된 오류가 있었다. 당시 이를 사용자에게 알렸고 후속 선택에서 제외했다. 기능 전용 schedule_reset_scope_test로 대체했다. 그 초기 실행을 레이아웃 검증 완료로 기록하지 않으며 이번 최종 검사에는 크기/배율/캡처 검사가 없다.
초기 실패는 (1) 잘못된 기존 파일명 (2) foreign eager ko-only getter (3) 차단 화면 initState의 DB 초기화 (4) Windows stderr warning 오판정이었다. 파일명/조건/래퍼/실제 exit code 처리로 해결했다. 이후 최종 묶음이 통과했다. lib/test 대신 build의 과거 소스 복제까지 분석한 초기 오류는 현재 제품 소스 오류로 합산하지 않았다.

문구 확정 가능 여부 및 남은 문제
현재 제공 기능·코드 의미·번역 변수·리소스 범위를 기준으로 문구를 후속 기능 검증의 고정 기준으로 사용할 수 있다. 현지 사용자 감수/이해도, 실제 OS 설정명의 모든 현지어 문자열까지 확정했다는 의미는 아니다.
실기기 잠금 알람·설정 off/on 복귀·설정 중 프로세스 종료/재시작·런처 수면 위젯의 실제 제거/갱신·공유 웹 서버 조회·Firebase 실제 네트워크 수 측정은 NOT_RUN이다. 기존 AH/AJ 관찰을 이번 새 코드의 PASS로 이월하지 않았다.
Samsung API34+, API30/33, 확보 가능한 Xiaomi의 실제 권한/잠금 알람 검사는 출시 전 P0다. 레이아웃 검증은 사용자 요청에 따라 이번 완료 범위에서 제외한다.
운영 광고 ID를 안전한 최종 배포 절차로 주입한 뒤 prod release를 다시 만들어야 한다. 운영 배포는 이번 요청 범위가 아니다.
보고 후 컴퓨터 종료는 사용자의 명시적 요청이다. 모든 파일/원장 저장 및 실행 중 검사 종료 뒤 지연 종료를 예약한다. 예약 결과는 최종 답변에 별도 보고한다.

ShiftBell 제조사별 핵심 기능 최종 테스트 계획
작성일: 2026-10-06 KST
상태: 계획 작성 완료. 이 계획으로 유료 예약/설치/테스트를 시작한 상태는 아니다.

대상 국가
미국, 영국, 남아공, 필리핀, UAE, 독일, 브라질, 인도.
기능 범위는 해외판 공통 핵심 기능이다. 한국어 전용 수면/일정관리/공유는 제외한다.
제품 소스 수정 없이 검증하고, 문제가 나오면 재현 조건과 로그를 남긴다.

읽는 순서
1 제조사 우선순위 → 2 핵심 기능 목록 → 3 과거 결과 대조 → 4 실제 남은 작업 → 5 연결 시간/비용 → 6 실행 전략/판정.

1. 제조사 우선순위

1순위 Xiaomi / Redmi / POCO 대표: Xiaomi 14, Android15
- 새 네 권한 온보딩의 직접 동기였던 제조사다. 기존 기본 기능 전체검사는 반복하지 않는다.
- 새 권한 안내→제조사 설정→실제 허용→복귀, 잠금 전체화면에서 끄기/+5분을 최우선으로 끝낸다.
- 현재 확인된 스트리밍 모델은 Xiaomi14(houji/35)이다. 다른 Redmi/POCO를 검증한 것으로 기록하지 않는다.

2순위 vivo / iQOO 대표: 접근 가능한 Global/GMS 또는 인도판 Android14+
- 인도/필리핀/UAE 대상에서 중요하고, 실제 앱 테스트가 전혀 없다.
- 기기에 따라 Funtouch/OriginOS가 다르며 OPPO 결과로 대체하지 않는다.
- 현재 프로젝트 카탈로그에는 예약 가능한 모델이 없다. 발견되기 전에는 유료 연결 시간을 배정/사용하지 않는다.

3순위 Infinix 대표: NOTE50 Pro+ / Android15
- 필리핀 보완, 별도 XOS 환경. 현재 제휴 카탈로그에 모델이 있다.
- 실제 예약/지역 ROM/제휴 조건 확인이 필요하다. TECNO/itel PASS로 확장하지 않는다.

4순위 HONOR 대표: Global/GMS, Android14+
- 남아공/UAE 보완, 별도 MagicOS 환경.
- Lab 표시는 있으나 구체적 예약 모델은 아직 미확인. 접근 가능해진 뒤 진행한다.

5순위 Motorola 대표: 기존 moto g34 5G / Android14
- 브라질 중요도가 높다. 기존 기본 기능 증거를 유지하고 새 권한 및 후속 보강만 검사한다.
- 기존 기기를 재사용하면 모델 차이라는 변수를 줄일 수 있다.

6순위 OPPO 대표: 기존 A38 / Android14
- 인도/필리핀/UAE 중요. 기존 기본 기능 증거를 유지하고 새 권한/후속 보강만 검사한다.
- realme/OnePlus는 추가 예외가 없으면 이번 첫 묶음에서 후순위다. realme T/S/Go 계열까지 동일 OS로 단정하지 않는다.

조건부 Google Pixel
- Pixel8a/Android15의 기본 기능·표준 전체화면 설정 경로는 이미 확인했다.
- 단순히 브랜드 수를 늘리려고 같은 검사를 추가하지 않는다.
- 공통 코드 문제의 대조, 새로운 Android API의 실측 또는 다른 제조사에 없는 조건이 필요할 때만 연결한다.

실제 예약 순서
- 위 목록은 위험/미검증 환경 우선순위다.
- 당장 가능한 순서는 Xiaomi → Motorola → OPPO → 접근 가능한 Infinix가 현실적이다.
- vivo/HONOR가 확보되면 위 우선순위로 끼워 넣는다. 모델 탐색·계정 준비 때문에 다른 기기를 예약해 놓고 기다리지 않는다.
- 한 브랜드당 우선 한 대. Android 버전/ROM/절전 차이가 입증되면 그때 추가 모델을 선정한다.

Samsung은 유료 스트리밍 대상에서 제외
- 사용자 보강 기능 테스트 OK 보고와 기존 실측 증거를 유지한다.
- 사용자 예정 레이아웃 기기: Galaxy S26 Ultra, Flip8, Fold8, Fold8 Ultra, SRTL 4대.
- 이번 계획은 레이아웃을 검사하지 않는다.
- 이 네 형태로 앱 레이아웃의 큰 범위를 검증하는 판단은 합리적이다. 다만 다른 제조사의 글꼴/글자 배율/인셋/설정 화면까지 전부 동일하다고 보장하지는 않는다.
- 현재는 그 이유로 해외 제조사별 전체 화면 검사를 추가하지 않는다. 기능 버튼의 실제 동작·설정 목적지·제어 가능 여부 확인은 기능 검사로 유지한다.

2. 실기기 핵심 기능 전체 목록 — 아직 과거 결과를 빼기 전

P01. 네 권한의 실제 상태와 개별 설정 진입/복귀
- 알림 표시, 다른 앱 위에 표시, 정확한 알람, 전체화면 알림.
- 최초 설치 상태를 먼저 저장. granted/denied/unknown/notApplicable을 구분한다.
- 허용된 것은 재요청하지 않으며 설정 열기만으로 완료 처리하지 않는다.
- 항목마다 앱이 연 화면이 해당 앱/권한인지 확인. 허용하지 않고 뒤로 돌아오기와 허용 후 돌아오기를 각각 확인한다.
- 한 번에 설정 화면 하나만 연다. 앱 resumed 후 상태/배너가 실제 상태와 맞아야 한다.
- USE_EXACT_ALARM으로 설치 시 허용되는 기기는 거부 상태를 억지로 만들지 않는다. 다른 권한 방식의 거부/설정 유도는 별도 조건으로 판정한다.

P02. 제조사 추가 제한/설정 안내
- Xiaomi: Other permissions → Open new windows while running in the background → Always allow의 실제 목적지/문구/허용 전후 확인.
- 표준 전체화면 상태와 OEM 동작의 관계를 함께 기록한다. 표준 API만으로 모든 비공개 OEM 상태를 읽었다고 주장하지 않는다.
- 실제 앱 버튼으로 진입한다. adb로 설정 Activity만 연 성공은 앱 버튼 성공으로 대체하지 않는다.
- OEM 설정 실패 시 앱 정보 fallback이 실제 도달 가능한지 확인 가능한 조건에서 검사한다. 실패를 만들기 위해 시스템 앱을 제거/변조하지 않는다.
- 앱 언어와 OS 설정 언어가 다른 한 조건을 포함한다. OEM의 ko/de/pt/hi 정확한 실측 문구는 관찰한 언어만 확정한다.

P03. 앱 알림 차단과 알람 제어 채널 차단의 구분
- 앱 알림은 허용한 채 실제 울림 제어 알림이 쓰는 채널을 차단한다.
- 앱 전체 허용 표시와 별개로 채널 문제가 표시되어야 한다. 복구 후 경고가 해제되는지 확인한다.
- 채널 화면 이동/중요도가 설정됐다는 사실과 실제 알림 표시 성공을 분리한다.

P04. 설정 도중 앱 종료/외부 권한 철회/기존 사용자 복귀
- 설정에서 아무것도 변경하지 않고 돌아오기, 앱을 종료했다 다시 들어오기, 연타/연속 resume.
- 기존 근무표 사용자가 설정을 다녀와도 온보딩 초기화/자료 소실/잘못된 화면 이동이 없어야 한다.
- 등록 후 권한을 철회했을 때 재진입 상태와 제어 방법 확인.

A01. 실제 잠금 알람 울림과 끄기
- 실제 UI로 근무/알람 하나를 등록 또는 수정하여 예정 시각을 확인한다.
- 앱을 백그라운드로 보내고 화면 끄기/PIN 잠금. OS 수신/재생과 AlarmActivity 표시를 별도로 확인한다.
- 실제 Dismiss를 누르면 소리/진동/진행 상태/울림 알림·화면이 종료되고 이력/DB/OS 예약이 맞아야 한다.

A02. 잠금 화면 +5분과 자연 재울림
- 실제 +5분 버튼 → 현재 울림 종료 → 정확히 5분 뒤 예약 → 시계 변경 없이 자연 재울림 → 실제 끄기.
- 5분 대기는 압축/시계 점프로 대체하지 않는다. 그 사이 다음 알람/배너/예약 정보를 수집하되 다시 벽시계를 변경하지 않는다.

A03. 알림/오버레이 모두 거부 또는 등록 후 철회된 경우
- 화면/알림 제어가 제한돼도 앱에 들어오면 울림 제어 카드로 끄기/+5분이 가능해야 한다.
- 별도 회차에서 1분 자동 종료를 끝까지 관찰한다. 종료 이력, MediaPlayer/진동 해제, 울림 상태/DB 제거 확인.
- 앱 재진입/화면 이동이 독립 종료 deadline을 연장하지 않아야 한다.
- 실제 잠금 UI가 없는 조건과 UI가 정상 표시된 조건을 구분한다.

R01. 근무표 변경 후 예약 갱신
- 가까운 미래 근무/알람 하나를 실제 UI로 수정/취소한다.
- 오래된 예약이 제거되고 새 예정 시각/DB/OS 예약이 일치하는지 확인. 취소한 알람이 원래 시각에 울리지 않는지 짧은 간격으로 관찰한다.
- 순수 달력 편집/모든 근무 패턴 조합은 여기서 반복하지 않는다.

R02. 앱 비활성 상태의 자연 자정 롤링 갱신
- 시험 시간대를 자정 직전으로 미리 설정하고 앱을 백그라운드로 보낸다.
- 알람이 울리기 전에 시계 설정을 끝낸다. 자정 경계/울림/5분 대기 중에는 변경하지 않는다.
- 갱신으로 다음 구간 예약이 추가되고 개별 skip/타입 예외가 보존되며 미래 DB/OS 예약이 일치해야 한다.
- 하루를 과금하며 기다리지 않는다. 자정 2~3분 전부터 자연 통과하는 조건을 만든다.
- 이 조건의 PASS는 하루 전체 절전이나 실제 달력상 24시간 대기를 검증한 뜻은 아니다.

R03. 재부팅 후 앱을 열지 않고 예약 복원/울림
- 재부팅 전 알람을 저장하고 실제 새 boot ID/uptime 초기화를 확인한다.
- 첫 잠금 해제 후 앱을 열지 않은 상태에서 예약 복원 및 가까운 알람 울림 확인.
- 최초 잠금 해제 전 Direct Boot는 별도 사례다. 잠금 해제 후 PASS를 그 사례로 전용하지 않는다.
- 클라우드에서 재부팅 시 ADB/예약이 반환되거나 복구가 안 되면 환경 제한/NOT_RUN으로 남긴다. 다른 제조사의 결과로 PASS 처리하지 않는다.

R04. 짧은 백그라운드/Doze 표본
- 앱을 홈으로 보내거나 최근 앱에서 치운 조건과 force-stop을 구분한다.
- 가능하면 실제 IDLE 진입 증거를 확보한 뒤 울림/자동 종료 확인.
- IDLE 진입 실패 시 Doze PASS로 기록하지 않는다. 강제 force-stop 이후 알람 중단을 정상 백그라운드 실패와 혼동하지 않는다.
- 장시간 절전/제조사 자동시작은 무료 USB/대여/테스터의 장시간 관찰로 보완한다. 유료 스트리밍에 몇 시간 대기를 배정하지 않는다.

W01. 홈 위젯의 실제 갱신 — 여유 항목
- 신규 제조사에서만 위젯 한 개 추가 후 근무 변경 또는 날짜 경계의 갱신 확인.
- 위젯 디자인/전체 테마/여러 크기 레이아웃은 제외.
- 알람/권한/갱신 증거가 남았는데 이 항목부터 진행하지 않는다.

3. 과거 결과 대조 — 유지/중복 제외/아직 남음

Samsung
- 사용자 보고 보강 기능 OK + 기존 실기기 기록 유지. 네 권한 새 구현의 P0 토글/복귀는 별도 결과가 있으면 그 증거를 연결한다.
- 현재 기록만으로 최신 네 권한 전체 수동 P0 통과를 추정하지 않는다. 필요한 확인은 USB/SRTL 기능 검사로 처리해 유료 시간에서 제외한다.

Xiaomi14/Android15: AG/AH
- 유지: 자연 자정 갱신/예외 보존/DB-OS 정합성, 두 권한 거부 자동 종료, 앱 내 끄기/+5분/자연 재울림, 시계 되돌림에도 독립 종료, OEM 허용 뒤 잠금 전체화면 표시, 오버레이 X 종료.
- 제외: 같은 자정/1분·3분 종료/앱 내 스누즈를 기존 조건 그대로 처음부터 재시험하는 전체 검사.
- 남음: 새 P01~P04, 최종 후보의 정상 PIN 잠금 Dismiss 및 +5분/재울림(A01/A02). 기존 잠금 Dismiss는 성공 이력 미확보다.
- 새 최종 후보에서 짧은 A03 안전 확인은 P0 변경과 연결되므로 포함한다. 기존 독립 타이머 스트레스/시계 되돌림은 다시 반복하지 않는다.

Motorola G34/Android14: AD
- 유지: 자연 자정 갱신/예외/예약 정합성, 기존 오버레이 거부 자동 종료, 알림 +5분 자연 재울림, 잠금 전체화면 실제 Dismiss.
- 당시 후속 독립 종료/앱 내부 제어는 APK에 없었다. 두 권한 동시 거부 fixture는 무효였다.
- 남음: P01/P03/P04와 새 A03(자동 종료/앱 내부 제어). P02 Xiaomi 안내는 해당 없음.
- 기존 정상 잠금/스누즈/자정 전체 회차는 반복 제외. 새 권한 설정 이후 짧은 실제 잠금 울림→Dismiss 한 회차는 연결 확인으로 포함한다.

OPPO A38/Android14: AF
- 유지: 자정 갱신/예외/예약 정합성, 알림 +5분/재울림/오버레이 X, PIN 잠금 Dismiss, 기존 두 권한 거부 자동 종료, 영어 위젯.
- 당시 후속 독립 종료/앱 내부 제어는 APK에 없었다.
- 남음: 새 P01/P03/P04와 A03의 후속 앱 내부 제어/독립 종료. 새 권한 이후 실제 잠금 울림→Dismiss 한 회차.
- 기존 자정/자연5분/위젯 전체 회차 반복 제외.

Pixel8a/Android15: AF/AJ
- 위 OPPO 기본 범위 및 일반 앱 UID의 개별 FSI 설정 Intent 성공 유지.
- 최신 앱 온보딩 버튼/후속 제어 구현의 실기기 PASS는 아니다.
- 첫 유료 묶음에는 추가하지 않는다. 표준 코드의 새 앱 버튼/상태는 삼성 USB + Motorola에서 대표 검증하고 제조사별 실패 시 대조 기기로만 사용한다.

vivo/Infinix/HONOR
- 앱 실기기 검증 없음. 카탈로그/기기실 존재는 PASS가 아니다.
- 신규 대표 OS마다 P01/P03/P04, 실제 발견된 P02, A01~A03, R01/R02를 포함한다.
- R03 재부팅과 R04 실제 Doze는 가능한 환경에서 남은 시간/별도 보완 단계로 진행한다. 전체 최초 검증은 이 조건의 미수행 여부까지 적어 보고한다.
- 삼성/Xiaomi 등의 성공을 이 세 제조사에 이월하지 않는다.

4. 과거 결과를 뺀 최종 실행 묶음

묶음 X: Xiaomi 변경부 + 미완료 잠금 제어 / 예상 22~26 device-minutes
0~3분: 연결/설치, APK 해시/제조사/OS/ROM/시각 기록, 최초 권한 상태.
3~10분: 앱 버튼으로 네 권한 확인/변경 없음/허용 복귀, Xiaomi OEM 설정/실효 FSI, 앱 재진입.
10~13분: 채널 차단/복구, 권한 외부 철회/복귀, 기존 자료 유지, OS와 앱 언어 불일치 한 조건.
13~21분: 실제 PIN 잠금 알람 → Dismiss 한 회차, +5분 → 자연 재울림 → Dismiss 한 회차. 스누즈 대기 중 예약/상태 증거 수집.
21~24분: 두 권한 철회 조건의 앱 내 끄기 및 별도 1분 자동 종료 짧은 확인. 완료한 경우 즉시 반환.
24~26분: 지연 여유/핵심 로그 회수/반환 확인.
구간은 예산 배치이며 각 단계 완료 시 앞당긴다. OEM 경로 탐색이 지연되면 잠금 제어를 먼저 확보하고 남은 항목은 NOT_RUN으로 남긴다.

묶음 M: 기존 Motorola 변경부 / 예상 10~12 device-minutes
- 연결/설치 2~3분.
- 새 네 권한 실제 앱 경로·허용/미변경 복귀·채널·외부 철회 4~5분.
- 새 권한 후 잠금 울림/Dismiss 및 두 권한 거부의 앱 내 끄기/1분 자동 종료 3~4분.
- 기존 자정/자연5분/위젯/모든 달력 화면은 반복하지 않는다.

묶음 O: 기존 OPPO 변경부 / 예상 10~12 device-minutes
- M과 같은 최소 항목. Xiaomi 전용 도움말이 불필요하게 뜨지 않는지 기능적으로 확인.
- 기존 두 권한 거부 타이머/자정/자연5분/위젯 전체 반복 대신 후속 제어 및 권한 연결 확인에 집중.

묶음 N: 신규 vivo/Infinix/HONOR / 각각 예상 24~28 device-minutes
- 연결/설치/ROM/초기 상태: 2~3분.
- 실제 권한 설정/복귀/제조사 제한/채널: 5~7분.
- 실제 UI 등록/변경 후 예약, 앱 비활성 자연 자정 갱신: 3~4분.
- 잠금 실제 울림/끄기, +5분 자연 재울림: 7~8분.
- 두 권한 거부 앱 내 제어/1분 자동 종료: 3~4분.
- 반환 여유 및 가능한 재부팅 또는 실제 Doze: 남은 범위. 재부팅과 Doze를 모두 끝낸다는 시간 보장은 하지 않는다.
- 기기마다 갱신/스누즈를 하나의 자연 자정 시나리오로 구성하여 겹치는 대기 시간을 줄인다. 상태를 바꾸면 시나리오가 깨지는 설정 변경은 대기 중 하지 않는다.

공통 필수 보완: 무료 USB/SRTL 또는 별도 접근 가능한 실제 기기
- P0 회귀기준의 API30/API33/API34+ 상태/설정 경로: API34+는 위 묶음, API30/33은 접근 가능한 실제 기기에서 짧은 권한 검사(각 5~8분 예상). 브랜드마다 반복하지 않는다.
- 현재 삼성 예정 4대가 API30/33 환경을 제공한다는 전제는 하지 않는다. 확보 전에는 해당 API 항목을 NOT_RUN으로 유지한다.
- API34 미만 Xiaomi OEM 도움말/실제 추가 설정은 해당 기기 확보 시 별도 짧은 검사(5~8분 예상). Xiaomi14/15 성공으로 대신하지 않는다.
- 재부팅 복원 및 밤새 절전은 무료 장시간 실기기에서 관찰한다. 실제 재부팅 환경을 확보할 수 없으면 남은 출시 리스크로 보고한다.
- 자동/호스트 회귀 기준은 기존 tools/check_critical_release.ps1을 따른다. 소스 변경이 없으면 계획 작성만으로 다시 실행하지 않는다. 변경이 있으면 필요시 -Build까지 완료한 뒤 기기를 예약한다.

6. 시간을 아끼면서도 증거를 보존하는 실행 전략

연결 전에 무료로 끝낼 일
1) 후보 APK를 하나로 동결하고 크기/SHA256/버전/flavor/소스 대응을 기록한다.
   기존 조사 APK: app-dev-release.apk 85,078,340 bytes,
   SHA256 16d710a45ed60c03ceaef3fe950391f3325ed71057766e8931a08f139ef7135e.
   이후 튜닝/권한/알람 코드가 바뀌었다면 이 파일을 무조건 최신으로 사용하지 않는다. 기존 빌드가 최신과 일치하는지 확인하고 필요한 빌드/회귀를 예약 전에 끝낸다.
2) 필요한 CLI/ADB/로그 수집/기존 시험 자료를 준비하고 제조사 카탈로그/가용성을 조회한다. 6GB PC에서 연결 중 빌드/에뮬레이터를 병행하지 않는다.
3) 시험 근무표/가까운 알람/자정 경계/1분 종료/skip·타입 예외 데이터를 미리 정한다.
   합성 DB를 쓰는 롤링 검사는 앱 정지/SQLite WAL 반영/주입 후 조회를 확인한다. 저장 실패 fixture를 앱 실패로 판정하지 않는다.
   적어도 등록/수정/권한/끄기/스누즈는 실제 앱 UI로 수행한다. 시험 DB 주입만으로 사용자 등록 흐름 PASS를 만들지 않는다.
4) 기존 검증 원장과 비교하여 해당 APK에 영향을 받은 항목만 선택한다. 알람/갱신 로직 변경이 발견되면 해당 과거 PASS를 지우지 말고 재검증 필요 상태를 추가한다.

연결한 뒤
- 반드시 remote localhost serial과 기기 제조사/모델을 확인한다. USB Samsung을 기본 adb 대상에 맡기지 않는다.
- 권한 허용은 실제 사용자 화면으로 한다. pm grant/appops set은 최초 기본값/온보딩 허용의 증거로 사용하지 않는다.
- 권한 변경 전후 스냅샷, native 수신/재생/종료/RingDeadline, 이력/DB/OS 예약, 실제 제어 화면·버튼 결과를 최소 증거로 남긴다.
- 캡처는 기능 증거용이며 레이아웃 비교/글꼴 품질 판정/테마 전수 검사가 아니다.
- 알람 대기 시간에는 같은 조건의 로그/예약/이력을 수집한다. 5분을 기다리기 싫다고 시계를 바꾸지 않는다.
- 새 제조사의 자정은 시작 전에 23:58 전후로 준비하여 자연 경계와 울림/종료를 같은 회차에 결합한다.
- 재부팅으로 연결이 사라지면 이전처럼 여러 재시도에 시간을 쓰지 않는다. 2~3분 안에 상태가 확정되지 않으면 환경 제한으로 남기고 예산 내 다음 핵심 항목을 진행할 수 있는지 판단한다.
- 문제가 나오면 한 번 재현/로그 확보 후 범위를 좁혀 기록한다. 코드 수정/재빌드로 시간을 소비하지 않는다.

판정과 보고
- PASS/FAIL/NOT_RUN/환경 제한/무효 fixture를 구분하고 APK 해시·OS·ROM·권한 조건·알람ID·시각·증거 경로를 연결한다.
- OS 수신/MediaPlayer 활성은 실제 스피커 청취/진동 촉감과 구별한다. 화면 표시/버튼 실제 종료는 각각 확인한다.
- 동작 성공은 검사한 조건의 결과다. 모든 모델/ROM 또는95%/100% 확률로 환산하지 않는다.
- 종료 보고에는 이번 실제 총 device-minutes, 반환 완료, 과거 결과 유지 항목, 이번 추가 PASS, 미수행 조건, 재현된 문제를 함께 적는다.
- 기존 1·2·3차 및 후속 원장은 보존하며 이 계획/새 결과를 별도 연결한다.

접근 문제가 이어지면 출시국용 실기기 보유 협력 테스터
- vivo/HONOR 각각 한 명, Android14+ Global/GMS 또는 해당 출시국 ROM의 기기부터 확보한다. 기기 구입 없이 기기 대여/보유자 협력으로 검증하는 대안이다.
- 동일 후보 APK를 설치하고 모델/OS/ROM/앱 해시·버전을 기록한 뒤 핵심 기능 체크리스트와 앱 진단 로그/영상으로 수동 판정한다.
- 우선 테스트: 실제 권한 설정/복귀, 화면 꺼짐·잠금 알람/끄기/+5분 자연 재울림, 두 권한 거부 앱 내부 제어/자동 종료, 근무 변경·자정 갱신.
- 테스터의 PC에 USB로 연결하여 승인된 원격 환경에서 ADB 접근까지 확보되면 예약/이력/OS 로그를 더 구체적으로 조사할 수 있다. 일반 PC 원격 제어만으로 현재 Codex 도구가 자동 연결된다고 보장하지 않는다.
- ADB가 없어도 보유자가 실제 울림/제어와 앱 진단을 확인하는 수동 검증은 가치가 있다. OS 내부 상태의 미확인 항목은 구분해 남긴다.
- 하루 절전/재부팅/스피커 청취·진동 촉감은 이 보유 기기에서 클라우드보다 더 직접 확인할 수 있다.

2. 사용자 요구에서 확정된 공통 설계 의도
시스템 글꼴 설정은 앱 글자 크기에 영향을 주지 않는다. 앱의 크기 대응은 실제 창/셀 폭으로 결정한다.
대형폰의 가로 여백·정보 관계를 좁은 폰에서도 유지하면서 글자만 비례 감소한다.
모델명으로 분기하지 않는다. 화면 너비·높이·셀의 가용 영역을 기준으로 한다.
글자 수에 따른 배율이 메모 개수에 따라 달라지지 않게 하고, 6글자 표기를 먼저 확보한다.
일반 테마의 1~4글자 근무명은 같은 크기, 5~6글자는 같은 작은 크기를 쓴다.
다이어리만 1~2, 3~4, 5~6의 세 구간을 쓴다. 구간 최대 길이로 측정해서 짧은 문자열도 같은 크기를 쓴다.
글자를 셀 경계에서 반쪽으로 자르거나 '...'를 덧붙이지 않는다. 완전한 글자 단위로 표시한다.
근무명은 식별 우선, 날짜는 탐색 우선, 공휴일·음력·메모는 동등한 보조 정보라는 시각적 역할을 유지한다.
공휴일과 메모는 보통 문구 기준으로 한 줄에 한국어 6글자를 최대한 확보한다.

특히 앱에 실제로 반환되는 가로 폭이 작을 때는 모든 문구의 6글자를 강제하느라 글자를 과도하게 줄이지 않는다.

일반 문구 가독성, 완전한 글자 표시, 실제 셀 여백의 균형을 우선한다.
다크그리드 날짜 옆은 두 자리 날짜 기준 최소 5글자.
음력과 공휴일 크기는 같은 테마 안에서 맞춘다. 메인에서 음력 고정/공휴일 확대라는 별도 요구는 예외로 유지한다.
메모 간격은 정보 묶음 내부의 작은 간격이다. 공휴일→첫 메모와 마지막 메모→셀 경계는 그보다 큰 외부 간격이다.
색상은 근무명 식별을 방해하지 않는다. 오늘 표시는 날짜 영역에서 구별한다.

3. 비율의 기준과 측정법
W = 실제 셀 폭, H = 실제 셀 높이, SW/SH = 전체 앱 창의 폭/높이.
폰은 7열이며 좌우 달력 바깥 여백을 뺀 폭/7이 W다. 달력은 요일 행을 뺀 가용 높이/6이 H다.
ScreenUtil의 360×780 설계 단위와 실제 논리 픽셀을 혼동하지 않는다.
S26 Ultra 연결 기기: SM_S948N, 물리 1080×2340, 표시 밀도 override 420.
따라서 창은 약 411.43×891.43 dp이며, 테스트는 411×891을 사용한다.
텍스트 fontSize/H는 글꼴 잉크 높이/H와 다르다. 실제 글꼴의 렌더링 사각형을 함께 기록한다.
근무명 크기 = 명목 크기 × 테마 고유 배율 × 구간 배율 × 구간 최대 문자열의 폭/높이 제한 배율.
6글자 보조 텍스트 = min(명목 크기, (가용 폭 - 최소 여백) / 6글자 기준 실제 글꼴 폭에 따른 크기).
메모는 안쪽 좌우 2 dp씩 보호하며, 0.5 dp의 분수 픽셀 오차 여유를 추가한다.
좁은 폭에서 글자별 크기를 바꾸지 않고, 셀 폭에 맞춘 공통 크기를 사용한다.
세로가 짧아 정보가 넘칠 때만 전체 셀 캔버스를 축소한다. 가로가 좁다는 이유만으로 날짜를 밀지 않는다.

5. 화면 기준의 확대/유지 정책
일반폰: 폭에 따라 설계 단위가 조정되어 날짜·글자·칩의 폭 관계를 유지한다.
텍스트는 SW 대비 규모가 기본이며 SH 증가만으로 커지지 않는다. 긴 화면의 여유는 셀과 간격으로 배분한다.
요일 영역 높이는 약 28 설계 높이이며, 글자를 키워도 행을 늘리지 않는다.
OT/주별근무시간은 단일 줄로 압축. 확보한 높이는 6개 달력 행에 배분한다.
Fold 내부/태블릿: 기존 별도 wide 셀 구조는 유지한다. 단순 폰 7열의 모든 요소를 화면 폭에 비례 확대하지 않는다.
날짜·근무명 같은 식별 텍스트는 가독성 상한을 유지하고, 추가 공간은 메모·정보 영역과 열 배치에 먼저 쓴다.
앞으로 SRTL 검토에서 실제 반환된 dp와 캡처를 함께 기록한 뒤 wide 상한을 승인한다.
이번에 폰 후보를 확정하지 않은 상태에서 Fold 후보를 승인된 취향으로 간주하지 않는다.

6. 여백과 밀도의 승인 경계
최소 가로 여백: 마지막 글자의 잉크가 카드/셀 테두리에 닿지 않음, 메모 내부 보호 여백 각 2 dp, 폭 검사 오차 0.5 dp.
단문 근무명: 글자 수가 달라도 구간 크기 유지. 4글자 기준 상하가 약간 타이트하되 글꼴 잉크가 칩 밖에 나오지 않음.
장문 근무명: 6글자 전체 식별이 우선. 단문보다 작아질 수 있으나 같은 구간 내 크기는 동일.
답답함 경계: 글자 잉크/테두리 접촉, 날짜와 근무명/공휴일 겹침, 세 번째 메모 잘림은 자동 실패.
널널함 경계: 같은 크기의 빈 공간이 반복되어 정보가 지나치게 흩어지는지는 사용자 캡처 판단 필요.
'조금 더 크게'의 1차 후보: 근무명 +6%, 메인 공휴일 +3.3%, 원 지름 +7.1%, 이벤트 날짜 +10%.
이 수치를 승인된 선호 허용범위로 단정하지 않는다. 승인 시 실제 렌더링 비율/최소 여백과 이유로 다시 기록한다.

7. 후속 승인 기록
2026-10-07: 최초 지시 반영 후보 작성. 사용자의 UI 결과 승인 대기.
레이아웃 검사 결과와 실기기 캡처는 같은 폴더의 작업 원장 및 build/layout_review_2026_10_07에 연결한다.
캘린더 승인 후 설정, 온보딩, 전체근무표, 모든 버튼/팝업/안내 화면을 한 번 더 훑도록 사용자에게 알린다.
검토 마커는 테마 확정 후 삭제한다. 삭제 뒤 다시 dev debug로 확인한다.
선호 규칙의 추가 수치 해석 (2026-10-07, 승인 전)
구간 최대 문자열의 잉크 예산은 칩 가용 폭에서 1 설계 폭을, 가용 높이에서 0.4 설계 높이를 더 남긴다.
이것은 전체 padding이 아니라 글꼴 반올림으로 경계에 닿지 않게 하는 추가 안전 여유다.
폰 셀 폭 약 50~57 dp에서 메모 보호 여백 각 2 dp는 셀 폭의 약 3.5~4.0%씩이다.
일반 칩 가로 패딩 2 설계 폭씩은 셀 폭의 약 4%씩, 다이어리 1 설계 폭씩은 근무 영역 폭의 약 3~4%씩이다.
음력/공휴일/메모의 목표 관계는 같은 보조 정보 크기지만, 실제 한 줄 글자 수가 확보되어야 할 때 공통 폭 예산을 우선한다.
4글자 근무명이 들어가는 구간 크기는 해당 최대 문자열로 측정하여 1~3글자도 같은 크기를 사용한다.
5~6글자 크기 차이는 고정 %를 선호한다고 단정하지 않는다. 같은 여백 안에서 전체 이름을 보존하는 폭 제약의 결과다.
정보가 셀 안에서 위/중간/아래에 배치되는 우선순위와 외부 간격의 대칭이 개별 fontSize 절대값보다 우선한다.
기기 세로가 길어도 텍스트를 세로 비례 확대하지 않는 대신 셀 높이와 탄성 간격에 배분한다.
현재 UI 후보의 승인 여부 및 추가 수정은 이후 별도 행으로 계속 누적한다.

달력 셀·근무명 칩·보조 정보 자동 맞춤 설계 기준
작성: 2026-10-08 / 연결 ID: A09
상태: 코드·기존 캡처 조사 및 후속 설계. 제품 코드 적용·새 실기기 검증·사용자 최종 화면 승인 전.

0. 이번 요청과 최신 정정
사용자 목적: 영어 및 폴더블마다 글자 수별 크기를 일일이 지정하지 않고,
셀의 실제 가용 공간과 최소 여백으로 근무명·메모를 자동 배치한다.
사용자 추가 정정: 짧은 이름이 칩의 빈 공간을 전부 채우는 것은 아니다.
칩 세로 크기가 고정이므로 2글자와 4글자가 같은 글자 크기일 수 있다.

핵심 규칙:
  칩의 높이와 상하 여백 → 글자의 공통 최대 크기
  실제 이름의 가로폭 → 최대 크기 유지 또는 필요한 만큼 축소
  이름이 짧아 좌우에 공간이 남아도 세로 기준 최대 크기를 넘겨 키우지 않는다.
  이름 길이 때문에 칩 높이·날짜 위치·메모 기준 크기를 바꾸지 않는다.

예: 최대 크기가 12이고 글자 가용 폭이 50일 때,
12 크기의 2글자 폭 24, 4글자 폭 48이면 둘 다 12로 표시한다.
같은 크기의 긴 이름 폭이 72라면 약 12×50/72=8.33부터 다시 측정한다.
이 숫자는 원리 설명용 가정이며 실제 글꼴 측정값이나 승인된 크기가 아니다.
영문 i와 W, 한글, 힌디어는 실제 폭이 다르므로 글자 개수로 이 계산을 대체하지 않는다.

기존 문서의 1~4/5~6, 다이어리 1~2/3~4/5~6 규칙은 당시 구현·검토 이력이다.
새 자동 맞춤 설계에서는 해당 구간을 새로 만들지 않는다. 현재 앱은 아직 기존 계산을 사용한다.
아래 [요구]는 사용자가 말한 방향, [관찰]은 확인한 코드/과거 자료,
[초안]은 구현·SRTL 확인을 위한 제안이다. 초안 숫자를 사용자 승인으로 취급하지 않는다.

2. 변수와 측정 단위
W,H: LayoutBuilder가 실제 날짜 셀에 준 논리 픽셀(dp) 폭/높이.
SW,SH: 실제 앱 창 크기. 물리 해상도, 광고/탭/상태줄 포함 높이와 구분한다.
I: 셀 바깥 여백/테두리, Cw,Ch: 실제 칩 배경의 폭/높이.
PL,PR,PT,PB: 배경 경계에서 텍스트 측정 영역까지의 총 안쪽 여백.
Aw=Cw-PL-PR, Ah=Ch-PT-PB: 텍스트 가용 영역.
Tw(t,f),Th(t,f): 실제 이름 t를 크기 f로 렌더링할 때의 폭/한 줄 높이.
Fs: 실제 이름의 최종 글자 크기, Fcap: 이 칩에서 허용하는 공통 최대 글자 크기.
Fref: 메모 등의 기준이 되는 근무명 최대 크기(해당 날짜의 Fs와 구분).
Fm,Fa,Fd: 메모, 한국어 공휴일/음력, 날짜 숫자의 기준 글자 크기.
Lm,La,Ld: 해당 스타일의 실제 한 줄 높이. fontSize 자체와 다르다.

테두리·부모 Padding·helper 내부 Padding은 총 여백에 한 번씩만 포함한다.
그림자와 둥근 모서리는 외부 간격/안전 영역으로 따로 기록한다.
키보드로 잠깐 줄어든 공간 때문에 달력의 영구 기준을 바꾸지 않는다.
배율은 앱의 시스템 글꼴 고정1.0 정책을 유지한다. 기존 테마 고유 확대는 최종 f에 한 번만 반영한다.
화면별 비율 Ch/H,Fs/W,Fs/SH 등은 결과를 비교하는 지표이지 모두를 구동하는 독립 공식이 아니다.

3. 셀 → 칩 크기: 폭을 기준으로 완만하게 확대하고 높이 예산으로 제한
[요구] 이름이 바뀌어도 같은 화면·테마의 칩 높이는 일정하다.
접힘/펼침으로 셀 크기가 바뀌면 다시 계산한다. '고정'은 모든 기기에서 같은 dp라는 뜻이 아니다.
근무/메모/공휴일이 없는 날도 같은 행의 기준 슬롯을 유지한다.

[초안] 기준 셀 폭 W0=56dp. 비교 가능한 폰의 기준 칩 높이를 C0로 보관한다.
작은 폭: s=W/W0
큰 폭: s=min(1.35, 1+0.4×(W/W0-1))
  Cpref=C0×s
세로가 긴 좁은 셀이라고 칩/글자를 키우지 않는다.
폭이2배여도 칩 높이는 최대1.35배의 초안으로 시작하며 추가 면적은 메모/배치에 쓴다.
W0,0.4,1.35는 조정 가능한 초안이며 실기기 승인 후 프로필에 확정한다.

테마별 최초 C0 참고 후보(dp, 코드 대입/최종 승인 전):
  메인20 / 심플 라인18 / 소프트카드19 / 다크그리드16 / 이벤트16 / 다이어리20 / 해외 신테마19.
현재 실기기 칩 배경의 최종 승인 실측을 확보하면 이 참고값을 그 값으로 교체한다.
과거 badge 내부 높이를 배경 높이와 동일하다고 간주하여 복사하지 않는다.

Cw는 테마 모양으로 정한다:
  메인: 셀 안쪽 폭에서 기존 바깥 간격을 뺀 폭.
  심플 라인: 셀 안쪽 전체 폭. 소프트카드: 카드 안쪽 전체 폭/상단 곡률 연결 유지.
  다이어리: 상단 유효 폭의 날짜35:근무65 출발. 날짜가 실제로 안 들어갈 때만 분할 조정.
  Soft Mosaic: 카드 안쪽 폭에서 좌우 칩 외부 간격을 뺀 폭.
  Periwinkle: 연결된 구간 전체 폭-양 끝 외부 간격. 각 날짜 셀은 자기 조각만 그린다.
  연결 구간 길이는 Cw에만 영향을 주고 Ch/Fcap을 추가 확대하는 이유로 쓰지 않는다.

높이 제약은 셀 배치별로 계산한다:
  세로 적층: H필요 = 위아래 외부 여백+Ch+날짜 슬롯+한국어 보조 슬롯+메모3행+고정 간격.
  다이어리: 상단=max(날짜 슬롯,Ch), 그 아래 보조 슬롯/메모를 더한다.
  wide: 상단 근무 밴드+max(날짜/보조 정보 열,메모3행 열)+외부 여백.
  main Stack: 슬롯 합계뿐 아니라 실제 날짜 사각형과 위/아래 사각형의 비겹침까지 검사한다.
한국어는 빈 날에도 공휴일/음력 슬롯 유지. 해외는 해당 이름 슬롯을 예약하지 않는다.

공식으로는 Ch=max{h | 0<h≤Cpref, H필요(h)≤H}.
H필요(h)는 해당 h에서 공통 Fref/메모 크기/최소 간격을 다시 계산한 필요 높이다.
가능한 h가 없거나 읽을 수 없을 만큼 작으면 값0으로 그리지 않고 배치 재검토 대상으로 둔다.
다른 요소의 예산 R이 이미 고정된 단순 적층에 한해서 Ch=min(Cpref,H-R)로 단순화할 수 있다.

산술 예시(C0=20, 다른 영역 R=48 가정; 실제 테마 측정값 아님):
  셀50×100 → 폭 기준17.86, 높이 한도52 → 칩17.86dp.
  셀56×90  → 폭 기준20.00, 높이 한도42 → 칩20.00dp.
  셀100×70 → 폭 기준26.29, 높이 한도22 → 칩22.00dp.
  셀100×120→ 폭 기준26.29, 높이 한도72 → 칩26.29dp.
즉 넓고 낮은 셀은 세로 예산에 제한되고, 긴 셀의 추가 높이가 칩에 무한 배분되지는 않는다.

배치 계산 순서:
  ① Cpref와 날짜/보조/메모의 기준 크기로 공간 예산 산출.
  ② 부족하면 탄성 바깥 간격을 정해 둔 최소값까지 줄임.
  ③ 여전히 부족하면 Ch와 참조 크기를 함께 낮춰 전체 예산을 다시 평가.
     매번 같은 테마의 최대3메모 조건으로 계산하여 이름/메모 유무가 칩을 움직이지 않게 함.
  ④ 세로 적층이 지나치게 작아지는 넓고 낮은 셀은 기존 wide의 좌우 배치를 사용.
  ⑤ 어느 배치에서도 읽을 크기가 안 나오면 '공간 부족/사용자 검토'로 기록.
     min/max를 뒤집어 음수 높이를 만들거나 overflow를 ClipRect로 숨긴 결과를 통과시키지 않음.
첫 적용은 기존 폰/wide 경로를 유지한다. 경계가 문제인 경우에만 양쪽 배치의 실제 공간을 비교해 보완한다.

4. 칩 → 근무명 크기: 상한 고정, 넘칠 때만 축소
[요구] 최소한의 상하좌우 여백은 확보한다. 짧은 이름을 가로로 늘이거나 칩을 채우도록 강제하지 않는다.
[초안] 일반 사각 칩에서 각 방향의 총 안전 여백 출발값:
  PL=PR=clamp(0.03×Cw,1.0,2.0)dp
  PT=PB=clamp(0.06×Ch,0.8,1.6)dp
  측정 오차 예산: 전체 가용 폭/높이에서 각각 추가0.5dp 제외.
  왼쪽 패턴 변경 띠처럼 실제 장식이 텍스트 영역을 침범하면 그 폭만 별도 차감.
여백의 목적은 구분과 잘림 방지이며, 글자 수가 많다고 0으로 없애지 않는다.
위 비율은 줄 상자 기준이다. 실제 보이는 잉크의 상하 공백은 글꼴 ascent/descent에 따라 다르다.
목표 줄 상자 점유는 대략 칩 높이의82~88%에서 시작하되, 잉크가 가장자리에 닿으면 실패다.
힌디어 결합부호/독일어 움라우트/포르투갈어 악센트를 감추는 강제 작은 strut나 클리핑을 사용하지 않는다.

Fcap = min(테마의 시각적 상한, 세로 가용 영역에 정상 한 줄이 들어가는 최대 f).
  시각적 상한은 칩 높이가 큰 경우 날짜/보조 정보와의 균형을 지키는 테마 매개변수다.
  첫 초안은 세로 제한을 중심으로 맞추고, 사용자 캡처에서 과대하다고 판단되는 경우 상한을 확정한다.
  같은 셀 크기/테마/언어·글꼴에서는 모든 이름에 공통이다. 2자용/4자용 상한을 따로 만들지 않는다.
  대표 한글·Latin·해당 언어의 상하 부호 샘플로 줄 높이를 확보하고 실제 이름도 다시 검사한다.

Fs(t) = max{ f | 0<f≤Fcap,
                 Tw(t,f)≤Aw-0.5,
                 Th(t,f)≤Ah-0.5,
                 한 줄이며 전체 이름이 들어감 }.
  Fcap에서 맞으면 즉시 그 크기로 사용. 폭이 남아도 더 키우지 않는다.
  안 맞을 때만 실제 문자열을 TextPainter로 측정해 이분 탐색한다.
  폭 비율 곱은 시작 추정값으로만 쓰고 최종 크기에서 다시 측정한다.
  폰트·fallback·weight·height·letterSpacing·locale·direction·textScaler를 실제 Text와 일치시킨다.
  최종 줄 상자를 가로/세로 중앙 정렬한다. 글자의 가로/세로를 서로 다른 비율로 늘이지 않는다.
  이모지/결합문자는 grapheme 경계로 취급하며 문자열을 저장 단계에서 바꾸지 않는다.

현재 근무명 입력 계약은 한글 포함6글자/그 외16글자다(shift_name_limits.dart).
작은 칩에서 긴 영문16글자의 전체 표시, 큰 글자, 한 줄 고정은 항상 동시에 달성할 수 없다.
기존 전체 이름 한 줄 축소를 기본으로 유지하되, 8dp 미만은 최초 검토 경고선으로 기록한다.
이 경고선은 출력을8dp로 강제해서 overflow시키는 하한이 아니며 승인된 가독성 기준도 아니다.
이런 경우 실제 화면을 보고 배치/폭을 조정한다. 자동 약칭·줄바꿈·입력 제한 변경은 이번 규칙에 포함하지 않는다.

5. 근무명 → 공휴일·음력·메모 크기 관계
[요구] 근무는 식별, 날짜는 탐색, 메모/음력/공휴일은 보조 정보다.
이름이 길어 Fs가 줄었다고 해당 날짜의 메모까지 작아져서는 안 된다.
  Fref=해당 셀 구조의 공통 Fcap
  Fm_nom=rM×Fref, Fa_nom=rA×Fref
  Fm은 최종 Fs가 아니라 Fref를 참조한다.
긴 근무명의 실제 Fs보다 메모가 커질 수 있다. 이를 막으려고 모든 메모를 함께 줄이지 않는다.

[초안: 출발 비율/기존 예외]
메인: rM 약0.70~0.80, 공휴일은 메모와 같게. 기존 음력 고정/공휴일 확대 예외는 비교 후 조정.
심플 라인: rM 약0.70~0.80, 보조 정보는 메모와 같거나 약0.94배(현 후보8.5/9.0 관계).
소프트카드·다이어리: 보조 정보=메모, rM 약0.65~0.80.
다크그리드: 메모 기준은 위 범위, 날짜 옆 보조 정보는 좁은 별도 폭에서 보통5글자 기준.
이벤트: 공휴일=음력=메모의 크기/칸 간격 통일. rM 약0.75~0.85에서 시작.
신규 해외2테마: rM 약0.80~0.92에서 시작. 휴일명/음력 셀 슬롯은 없음.
위 범위는 코드에 랜덤 선택하는 값이 아니다. 기준폰에서 한 값을 골라 기록하고 전체 창에 동일 적용한다.
현재 명목 크기를 그대로 비율로 나눈 값은 내부 배율/축소 때문에 실제 시각 비율과 다를 수 있다.

최종 보조 정보 크기:
  Fm = min(Fm_nom, 보통 한국어6글자 폭에 맞는 크기[한국어], 3행의 세로 예산에 맞는 크기).
  Fa도 자기 영역에서 같은 방법으로 계산. 동등 크기 테마는 두 영역의 공통 가능한 크기를 사용.
한국어의 기준 문구: 부처님오신날, 첫째메모여섯 등 실제 문구 집합.
폭이 큰 모든6글자를 강제하지 않는다. '와와와와와와' 등은 완전한5글자 허용이라는 기존 지침 유지.
해외는 'W 6개' 같은 임의 글자 수로 공통 크기를 과도하게 줄이지 않고 실제 언어 샘플을 비교한다.
단일 메모가 길다는 이유로 그 메모만 무한 축소하지 않는다. 정한 공통 크기로 완전한 문자까지 표시한다.
메모/보조 정보의 말줄임표·반쪽 글자 금지, 상세 화면의 전체 내용 보존.
힌디어는 코드포인트 개수가 아닌 실제 조합된 글자를 측정한다.

메모 수 정책:
  폰의 기본 글자 크기는0/1/2/3개에 관계없이 일정. 3개를 담을 수 있는 기준으로 설계.
  넓은 셀의 기존 '적은 메모 확대'는 별도 프로필로 유지/검토할 수 있다.
  그 경우 Fm(N)=min(개수별 선호 상한×Fref, N행 높이 예산)이며 이름 길이와는 독립이다.
  폰→wide에서 기존2.25배 같은 수치를 자동으로 새 기준으로 승격하지 않는다.

6. 메모 칩의 내부 여백과 묶음의 바깥 간격
내부 패딩, 메모끼리 간격, 메모 묶음 바깥 간격은 다른 값이다.
배경이 없는 심플 라인/소프트카드에 새 메모 배경을 자동 추가하지 않는다.

[초안: 배경이 있는 일반 메모]
메모 배경 폭 Mw = 해당 영역 폭-테마별 외부 좌우 간격.
내부 좌우 총 보호 여백(한쪽) Pmx=clamp(0.03×Mw,1.0,2.0)dp.
내부 상하 보호 여백(한쪽) Pmy=clamp(0.06×Lm,0.5,1.0)dp.
메모 배경 높이 Mh=Lm+2×Pmy+안쪽으로 그리는 테두리 높이.
테두리 안쪽 여백과 helper의 보호 여백을 중복 적용하지 않는다.
칩의 색이 구분되면서 글자 바로 위아래의 빈 공간을 얇게 유지한다.
고정된 큰 메모 슬롯이 필요한 테마는 Mh를 슬롯에 맞추고 텍스트를 중앙 정렬하되,
그 여유가 모두 글자 확대 예산인 것으로 해석하지 않는다.

간격의 초안(실제 한 줄 높이 Lm 기준):
  메모끼리 Ginner ≈0.03~0.08×Lm.
  보조 정보→첫 메모, 마지막 메모→셀 끝 Gouter ≈0.15~0.25×Lm.
  일반 원칙: Gouter≥Ginner, 대칭형은 위·아래 Gouter를 같게.
  남는 공간은 테마의 기존 앵커/탄성 간격으로 배분. 모든 요소 사이에 균등분배하지 않음.
배경 없는 심플 라인은 실제 줄의 leading도 간격에 포함해 보며 기존0.15.h를 급격히 벌리지 않는다.
소프트카드는 현행 상단 묶음/하단 여유를 보존한다. 일반 대칭 규칙을 강제하지 않는다.
메인은 날짜의 중앙 위치/기존 메모 수별 이동과 충돌 없는 하단 묶음을 우선한다.
이벤트는 예외: 아래 영역을4등분, 보조 정보와 모든 메모 사이를 동일한 작은 간격으로 둔다.
  각 칸 높이=B/4, 배경은 그 안에서 기존처럼 매우 얇은 상하 간격을 제외한 높이.
  메모가0~2개여도 공휴일/메모 슬롯의 경계가 이동하지 않는다.
해외 신규2테마의 현행 gap=3×unit, 첫 메모 위2×gap은 현재 구현값이다.
  이를 위의 촘촘한 간격으로 바꾸는 것은 후속 영어 화면 튜닝 후보이며 이번에 자동 승인하지 않는다.

7. 날짜·요일·기타 모양의 보존
날짜 크기는 별도의 기준값/실제 날짜 슬롯에 맞춘다. Fs나 메모 문자열에 연동하지 않는다.
날짜를 현재보다 키우거나 위치를 바꾸는 것은 해당 테마의 기존 승인 방향과 함께 비교한다.
요일 글자는 기존 한 줄 높이를 늘리지 않는 범위에서 맞춘다.
오늘 윤곽선·근무색·상단 모서리 연결·변경 근무 띠·다중 선택 표시를 자동 맞춤 때문에 바꾸지 않는다.
컬러뱃지는 원 지름과 이니셜 한 글자 전용으로 처리한다. 전체 근무명을 원 안에 넣는 규칙으로 변경하지 않는다.
미니멀언더라인/매거진은 기존 튜닝 제외 방침 유지. 근무명이 없는 표시에 칩을 새로 만들지 않는다.
해외 공휴일은 날짜 숫자와 상세 팝업의 이름으로 표시한다. 셀에 한국어 휴일명 줄을 추가하지 않는다.

8. 구현을 복잡하게 만들지 않는 적용 단위
권장 최소 구성:
  A. 공통 한 줄 이름 맞춤 함수: 실제 영역+스타일+문자열 → 최대 크기에서 축소한 크기.
  B. 테마 매개변수: 기준 칩 높이, 폭/외부 간격, 내부 여백, 시각 상한, 보조 정보 비율, 묶음 배치 방식.
  C. 기존 각 셀 위젯: 배경/색/날짜 순서 유지, A/B의 계산 결과만 사용.
글자 수별 if와 기종명별 if를 추가하지 않는다. 캐시는 동일 이름·스타일·locale·실제 영역에만 재사용한다.
폴더블 크기 변경/글꼴 준비 완료/테마 변경 시 재계산한다. 캐시에 이전 펼침 폭을 남기지 않는다.
FittedBox, 전체 셀 캔버스 축소, 내부 테마 배율을 겹쳐 넣어 최종 크기를 추적하기 어렵게 하지 않는다.
전체 셀 축소가 남는 경로는 화면에 그려진 최종 배율까지 계측하고, 이차 축소 여부를 별도로 기록한다.
Periwinkle painter도 같은 측정 함수를 사용하되 연결 구간 전체 폭과 공통 Ch를 전달한다.
공개 공유 웹에 이 새 정책을 자동 확대 적용하지 않는다. 글로벌 앱의 일정 공유 제외 범위도 유지한다.

9. SRTL 검토 순서와 기록 양식
① 영어 기준폰의 추가 레이아웃 요청/새2테마 방향을 정리한 뒤 공통 계산을 적용.
② 호스트에서 실제 글꼴을 사용해 폭/높이 조합과0~3메모를 확인. 정사각 테스트 폰트 결과만 믿지 않음.
③ Fold8 / Fold8 Ultra / Flip8 연결 시 실제 반환된 모델·OS·창 dp·표시 밀도를 기록.
   모델 이름으로 치수/접힘 동작을 추정하지 않는다. 실제 사용할 수 있는 표시 상태별 확인.
④ 각 기기에서 한국어→영어, 테마별로 현재/조정 캡처와 핵심 치수를 사용자에게 제시.
   접힌 화면·펼친 화면, 해당되는 가로 화면과 화면 전환 직후를 확인한다.
   Flip의 외부 커버 알람은 달력 셀 튜닝과 별도이며, 기존 기능 근거를 활용한다.
⑤ DE/PT-BR/HI는 같은 규칙으로 실제 근무명/메모/결합부호를 넣어 검사하고 캡처 묶음 제시.
⑥ Flip4는 마지막 커버 화면 확인. 별도 전수 기능 검사를 다시 시작하지 않는다.

샘플:

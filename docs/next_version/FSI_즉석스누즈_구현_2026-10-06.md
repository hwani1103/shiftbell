## B 구현 내용

### 동작과 소유권

- `RingingAlarmTracker`가 `(alarmId, round)`의 선택 분과 revision을 소유한다. 새 울림·재울림은 5분/0으로 시작하며 5·10·15·20·25·30만 허용한다. 동일 프로세스의 화면 교체·언어 변경에는 유지하고 종료 때 비운다. 저장된 이전 프로세스 회차만으로 울림을 다시 시작하지 않는다.
- `RingSnoozeController.adjust`는 선택값 저장, 현재 뷰와 기존 7777 표시 갱신만 한다. 소리·진동·DB 예약·OS 예약·자동 종료 deadline·복원 epoch를 변경하지 않는다.
- 실행은 버튼에 표시되어 있던 immutable snapshot의 분을 사용한다. 화면의 최신 선택값을 나중에 읽어서 옛 버튼의 실행 시간을 바꾸지 않는다. 동일 회차의 옛 `+15m` 토큰은 최신 선택이 30이어도 15분으로 실행하며, 종료된 회차의 토큰은 거부한다.
- 클릭/알림 receiver 진입 시각 + 선택 분을 계산하고 기존 저장 단위에 맞춰 **다음 정수 초로 올림**한다. 따라서 목표 시각은 처리 시점 + N분에서 0~999ms 늦을 수 있지만 초를 버려 일찍 울리지 않는다. DB date와 AlarmManager에는 같은 목표 epoch를 사용한다.
- `claimRingEnd`를 한 번 통과한 실행만 stop → UI 정리 → DB transaction → OS 예약 → 결과 안내를 진행한다. 성공/실패 모두 `finishTransition`을 finally에서 한 번 호출한다. UI는 메인 스레드, DB/OS 최신성은 기존 `AlarmWakeScheduler.scheduleIfCurrent` 관문을 이용한다.
- 다른 알람과의 충돌은 **같은 절대 분**으로 비교한다. 날짜 문자열 앞부분 비교를 제거해 날짜·월·연 경계와 DST 반복 시각을 구분한다. 충돌 시 기존 상대 알람 유지/현재 알람 종료/충돌 이력·안내라는 기존 정책을 보존한다.

### 화면·알림

- `SnoozeControlsBinding`을 전체화면, 오버레이, 앱 내부 카드, 커버에 연결했다. − / +Nm / +와 별도 끄기를 표시하고 동일 회차의 변경을 기존 뷰에 반영한다. 5/30 경계 버튼은 비활성화한다.
- 커버는 안전영역에 따라 두 줄 또는 한 줄로 배치하고 작은 화면에서 장식 시계를 먼저 줄인다. 제어 버튼은 48dp 이상을 유지한다. 필요한 안전영역(160×96dp 또는 208×48dp)이 없는 기기는 별도 실제 지원 판단 대상이다.
- `RingControlNotification`의 v2 URI는 ID/round/revision/동작/실행 분을 포함한다. explicit receiver + immutable PendingIntent이며 URI와 extras의 일치도 검증한다. 앱 Activity를 경유하는 알림 trampoline은 추가하지 않았다.
- 펼친 알림: custom big content에 − / 선택 시간 / +. 표준 액션은 +Nm / 끄기 두 개. 접힌 알림: 표준 contentText에 선택 분 표시. custom collapsed/headsup view는 추가하지 않았다.
- 선택·언어 갱신은 기존 7777의 ID/채널/when을 유지하고 FSI를 제거해 조용히 notify한다. 숫자 변경에는 cancel→notify, Activity 재생성, 오버레이 제거/추가를 하지 않는다. 커버 채널 진입·이탈은 별도 경계다.
- A의 FSI 수정은 B에도 포함된다. 500ms 보조 경로는 잠금 여부를 다시 확인하며, 같은 회차 Activity가 이미 표시된 경우 잠금 해제 상태에서도 오버레이를 추가하지 않는다.
- 기본 채널명·그룹·category·localOnly와 직접 Activity 보조 경로를 유지했다. **B의 스타일은 기존 BigTextStyle에서 DecoratedCustomViewStyle로 변경됐다.** 삼성 시스템 스누즈 회피 효과가 그대로일지는 실기기 검사가 필요하다.
- ko/en/de/pt-BR/hi native 리소스에 분 변수/조절 접근성/실패 안내를 추가했다. 기존 고정 5분 리소스는 호환 경로를 위해 보존했다. Flutter common ARB와 한국어 전용 리소스 경계는 바꾸지 않았다.

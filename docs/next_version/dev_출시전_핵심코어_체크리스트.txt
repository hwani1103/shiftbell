교대시계 dev 출시 전 핵심 코어 체크리스트
최종 갱신: 2026-10-08 KST | 상태: 기능 출시 판정 대조 완료·잔여 검증 유지 / 제조사 조사는 도움말 고지 방향으로 마감 / 최근 설정·수면·진단 공유 반영 / 최종 핫리로드분은 R04 통합대기

이 문서가 이번 dev 출시의 유일한 현행 작업판이다.
다음 세션도 여기서 시작하고 여기의 상태를 갱신한다. 두 원본 보고서는 당시 증거로 보존한다.
교대시계_최신문서.txt는 제품 계약·상세 구현·이력의 바이블로 유지한다. 일상적인 작업 선택과 출시 판정에 다른 계획서를 다시 읽을 필요는 없도록 필요한 잔여와 기준을 아래에 모았다. 원본 로그는 근거를 확인할 때만 연다.
선행 결과: A01/A03 수정, U02 공휴일, U03 광고 지연 방어·필수 자동 검사·dev 빌드 완료. Samsung USB 자연+5/+15·이력·실제 파일 복원/중단 복구, Fold8 SRTL DB23→29 직접 이관 PASS. 이후 Streaming과 A09 설정/부가 기능 후속도 완료 범위를 아래에 연결했다. 제보자 prod 로딩 환경은 미재현이며, 이번 기능 판정 조사에서 제품 수정·검사 실행·빌드·기기 조작·배포는 하지 않았다.
현재 출시 PASS 아님. 이 목록 완료와 사용자의 전체 출시 준비 완료는 별개이며, 마지막 개인 목록 확인까지 필요하다.

1. 현재 위치와 다음 순서

10/8 기능 출시 판단(현재 코드·검사 증거·원본 문서·관련 사용자 대화 대조):
- 핵심 알람/연장·근무표·DB29/백업에서 새 출시차단 결함이나 추가 구현 필수 기능은 이번 대조에서 발견하지 못했다. 다만 아래 실측/운영 경계가 열려 있어 기능 검증 전체 PASS 또는 그대로 출시 OK로 판정하지 않는다. 미실시는 결함 확정과 다르다.
- A02: 사용자가 제조사 검증은 최종 도움말 정리로 갈음하고 그대로 출시하는 방향을 제시했다. 추가 Streaming/동일 Infinix 조사는 자동 재개하지 않는다. 원격 FAIL·일반 판매기기 적용범위 미확정·미검증 제조사는 증거대로 보존한다.
- 남은 기능 검증 ① A03 실제 UMP 폼 동의/거부/철회와 광고 갱신 ② A05 구 API 권한 거절/복구 및 복귀 경합 ③ A06 신규 설치 기본값·언어 전환 중 활성 예약/공유 의도·pinned 수면 위젯 ④ A07 실제 지역 표시/목표 불변·한국 공휴일 원격 캐시/실패 재시도 ⑤ A08 보유기기 자연 장시간 Doze·미확보 물리 체감/커버 조작 경계. 완료 근거가 있는 조합을 반복하지 않고 해당 행의 미확보 조건만 닫는다. 커버 화면 작업 때 기능 버튼 확인을 함께 할 수 있으나 순수 레이아웃 PASS로 대체하지 않는다.
- A10 공개 다국어 공유 웹의 최신 코드/공휴일 운영 반영·실제 링크·기존 PWA 갱신도 기능 잔여다. 운영 배포/최종 검사는 출시 마감에 묶을 수 있지만 APK의 빌드 성공으로 완료 처리하지 않는다.
- 사용자 범위 정정 및 후속: 제조사 안내·진단 로그·도움말은 다른 세션에서 수정했고, 이후 사용자 요청으로 외국어 반영을 독립 대조했다. 한국어 전용이던 진단 공유/제조사 안내는5언어 공통으로 보완됨을 확인했다. 이 항목을 기능 미결로 중복 배정하지 않으며 상세 검토는 A06/A09, 최종 APK 연결은 R04에서 관리한다.
- 최근 A06/A09의 새 설치 탭 숨김/기존 선택 보존, 자동 수면 추정 최소5시간, 부가 탭 활성화/최초1회 안내는 구현·해당 자동/USB 근거가 있다. 동시 작업 중인 도움말/진단 공유 등의 최종 통합 검사·APK 포함은 해당 세션 결과를 받은 뒤 R04에 연결한다. 자동 수면 5시간 요청을 수동/위젯 최소시간 변경이나 새로운 실시간 수면 시험 요청으로 확대하지 않는다.
- U03은 광고 지연 방어 PASS·제보 환경 조건대기, U02는 10/7 확인된 공식 날짜 구현 완료·향후 발표 데이터 보충이다. 새 증거 없이 기능 재개발/전체 실기기 재시험을 배정하지 않는다.
- 기억할 사용자 목록: U01 1줄/3줄 위젯, R01 상세 업데이트 안내/버전/latestVersionCode 판단은 마지막 레이아웃·출시 마감에 유지. U04 대시보드 노트는 위치/세부 요구 미확보, U05 글로벌 보완·주말 표시/외국어 테마와 R03 국가/등록정보/이미지·R05 개인 목록도 유지. 확인한 관련 대화와 프로젝트 문서에서는 이 ID 밖의 새 필수 약속을 찾지 못했다(사용자의 별도 개인 노트 전부를 확인했다는 뜻 아님).
- 다음: 위 기능 잔여를 필요한 조건별로 마감 또는 명시적 범위 결정을 남김 → 사용자 레이아웃/위젯/안내 → R04 최종 dev 통합·명시 요청 후 prod/Play → R05 출시 판단. 이번에는 조사·문서 갱신만 수행했다. 상세 대조 원장: evidence/functional_readiness_2026_10_08.json.

- A01 공통 스누즈 약5초 지연은 코드 수정·호스트 회귀 및 Samsung·Pixel·Xiaomi·OPPO 자연+5 실측 PASS. A01 제조사 변경분 실측을 마쳤다. A02 Infinix 잠금 보류는 원인 지점 확인·해결 조건 미확정이다.
- A04 DB29 실제 선택 분·파일 복원·직접 이관은 이번 범위 PASS. A06 언어 전환의 미확보 경계, A09 최종 UI 등은 남았다.
- A03 광고 동의 반영은 mock 재현 후 수정, 실제 폼 시험 전이다. U03은 Fold8 비교를 마쳤고 제보자의 정확한 설치본/응답 환경만 추가 확인 조건으로 남겼다.
- U02 해외 공휴일은 발표된 날짜 반영·자동 검사 완료, 미발표 날짜·대표 화면 확인이 남았다. 추가 제작/결정: U01 위젯, U04 대시보드, U05 글로벌 보완, R01~R03 출시 운영.
- 제조사 잔여는 5절만 사용한다. 이미 끝난 기본 묶음을 기기마다 처음부터 다시 하지 않는다.
- 제조사 검사는 2절 고정 APK 기준이며 이후 설정/부가 기능 APK·핫리로드는 A09 근거로 구분한다. 현 작업 트리 전체가 2절 APK에 포함됐다고 가정하지 않는다. 최종 통합 산출물 승인은 R04다.

기존 진행 순서(①~⑤의 완료 범위는 재실행하지 않고 위 최신 판단과 각 ID를 우선):
최신 사용자 구분: 1단계 실기기 전 작업 → 2단계 연결 실기기 작업 → 3단계 Google Streaming 제조사 검사 → 기능 확정 후 4단계 사용자 레이아웃. 1단계와 이번 보유 Samsung USB/SRTL 검사 묶음은 마감했다. 조건 미확보 항목은 각 행에 유지한다.
① A00과 기능 범위의 미정사항 정리 → A01 공통 지연·A03 광고 및 언어·지역 등 코드로 가능한 구현과 자동 검사를 진행한다. U01 위젯과 R01 업데이트 안내는 사용자 결정으로 레이아웃 단계에 이관한다.
② 실기기가 있어야 원인을 확정할 수 있는 A02 Infinix 미완료 조합과 U03 Fold8 로딩만 좁게 사전 조사한다. 기존 로그부터 활용하고 필요한 연결만 한다. Infinix는 보류 지점은 확인했지만 해결 조건은 미확정이므로 이 조사 없이 수정 APK가 완성됐다고 가정하지 않는다.
③ 사전 조사 결과의 수정을 반영하고 필수 자동 검사/dev debug 빌드를 마쳐 기능 검증 APK·해시를 고정한다. 조사·수정·빌드 중 유료 연결을 유지하지 않는다.
④ 보유 Samsung에서 A04 백업/복원·실제 이력, A05/A06/A07 대표 조건과 필요한 A08/S1/S2를 한 검증 묶음으로 처리한다. 자연 대기 조건을 깨지 않는 범위에서 증거를 공유한다. 결함이 나오면 영향 수정 후 다음 제조사 연결 전에 후보를 다시 고정한다.
⑤ Google Streaming은 Pixel의 공통 지연 확인부터 → Xiaomi/Motorola/OPPO/realme의 남은 ID, 해결 후보가 준비된 Infinix를 검사한다. Samsung 결과를 포함해 7제조사별 기존 PASS+잔여를 마감한다. 한 기기 연결에서 잔여를 모아 처리하고 이미 끝난 전체 기능은 반복하지 않는다.
⑥ 기능·제조사 검증 뒤 A09 SRTL 폴드류/플립 레이아웃을 사용자 주도로 진행한다. 표시 변경은 영향 화면/터치만 확인하고, 알람·권한 로직을 바꾼 경우에만 해당 기능 검사를 다시 연다.
⑦ A10/R01~R03 웹·안내·정책·스토어 준비는 앞 단계와 병행할 수 있다. 최종 화면 이미지·기능 설명은 레이아웃 확정 뒤 마감 → R04 최종 산출물/Play 검증 → R05 사용자 개인 목록·출시 판단.
이 순서는 ‘한 번에 최대한 많이 진행, 기능 확정 후 사용자 SRTL 레이아웃’이라는 후속 사용자 지시를 반영한다. Fold8 로딩은 레이아웃이 아닌 성능 문제이므로 마지막까지 미루지 않는다. 후보가 달라지면 3절 영향 판정으로 결과를 연결한다.
직전 Streaming 마감 기록(후속 방향은 위 10/8 기능 판단 우선): Infinix 설정/API 조사와 사용자 요청 타 앱 대조까지 마감. 같은 X6856/XOS15.1.2.136 원격기기에서 Sleep as Android 일반알람의 서비스 직접시작/브로드캐스트 두 예약도 Hiber 보류, 앱 직접실행 뒤 지연수신. 적용할 해결책은 미확인. 사용자 지적에 따라 원격랩 설정/관리환경 영향은 미분리로 명시하며 일반 판매기기 전체의 한계로 단정하지 않는다. 다음은 일반기기(가능하면 같은ROM)에서 두 앱 단독·화면OFF·ADB미연결 비교 또는 제조사/랩의 공식 설명 확보; 같은 원격조건 추가 연결 계획 없음. 유료3회 합계47분29초/요금추정USD7.12·앱제거/반환·활성예약0. 도움말 고지 제안은 문구 협의대기·코드작성 금지 유지, Infinix 원격회차 FAIL을 PASS로 바꾸지 않는다. 기존 workspace30개 파일/source manifest 차이와 기존/동시 작업 보존·후속 후보 영향검토 필요. Samsung S2/S3·전체 출시 잔여 유지, 위젯·업데이트안내·본격레이아웃 마지막.
비용 순서 보완: 보유 Samsung 공통 검사와 무료 SRTL Fold8 성능·사용자 추가 이관을 유료 Streaming보다 먼저 마쳤다. 본격 레이아웃·위젯·업데이트 안내는 마지막 단계 유지. 유료 기기에서는 아래 비용 절차에 따라 정해진 시험·증거 수집만 하고, 분석·코딩·빌드 중에는 기기를 반환한다.
최신 USB/SRTL 마감: 사용자 응답을 받아 잠금 잔여까지 마쳤고 이후 Fold8 검사는 추가 사용자 조작 없이 완료했다. S26 원래 자료/설정 유지, SRTL 도입 시험 앱·파일 제거/설정 원복/예약0. PIN 변경·재부팅 없음. 미확보 조건을 이 결과로 PASS 처리하지 않는다.

3. 기존 PASS를 보호하는 작업 규칙과 원자적 변경 단위

상태: 미착수 / 진행 / 구현완료·검증대기 / PASS / FAIL / NOT_RUN / UNCONFIRMED(증거부족) / BLOCKED(선행조건) / DEFERRED(보류) / ACCEPTED_RISK(명시 수용) / N/A.
PASS에는 ‘자동·실기기·운영’ 종류와 적용 후보를 붙인다. 보류·수용·제외를 PASS로 바꾸거나 숫자에 합치지 않는다.

한 작업의 마감 단위:
1) ID 하나와 변경할 경계를 정한다. 기존 diff·사용자 데이터·해당 PASS를 보존한다.
2) 수정 전에 영향받는 완료 항목과 최소 재검증을 적는다. 관련 없는 수정은 같은 묶음에 넣지 않는다.
3) 수정 → 해당 경계 회귀 → 필요한 필수 실행기 → 검사 후보/해시 고정 → 필요한 실기기만 순서대로 한다.
4) 결과·원복·남은 한 줄을 같은 ID에 갱신한다. 새 결함이면 하위 ID를 만들고 선행 작업을 연결한다.
5) 다음 변경이 기존 전제에 영향을 주면 해당 항목만 ‘새 후보 확인대기’로 연다. 옛 PASS는 지우지 않는다.

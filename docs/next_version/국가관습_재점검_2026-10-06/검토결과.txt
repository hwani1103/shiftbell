- 주간 근로시간 계산 weeksCoveringMonth는 월~일 고정이다. 달력 일~토와 다르다.

3. 실제 발견한 후보 — 아직 제품 수정하지 않음
C01 출시 전 수정 우선: 공개 웹 달력 요일의 영어 혼입/주 시작 불일치
lib/widgets/friend_web_calendar.dart:277에서 ko_KR 이외를 en_US로 강제하며
startingDayOfWeek를 지정하지 않아 TableCalendar 기본 일요일로 시작한다.
별도 dowBuilder 없음. 실제 위젯 프로브에서 en_GB/de_DE/pt_BR/hi_IN 모두

앞선 최종튜닝 U09/U10은 오류/metadata를 고쳤지만 이 헤더는 놓쳤다.
수정 방향: 현재 locale와 주 시작 정책을 앱/웹/위젯 모두 일치시킨다.

C02 출시 전 수정 우선: DST 경계의 날짜별 근무시간·OT 집계
lib/services/work_hours_calculator.dart:26,63~71,87,183은 달력 날짜를
Duration(days:1/6/7), 즉 24시간의 배수로 더한다. 하루가 23/25시간인 구간에서
자정 유지에 실패한다. DateTime.add 공식 문서도 이를 명시한다(S07).
실제 computeWeekSummary에 timezone.TZDateTime을 입력해 Berlin/London/New_York
각각 봄·가을 총6경계를 재현했다. 3일×480분+날짜별OT10/20/30=1500분이어야 하나
봄은 마지막 날짜가 빠져 990분, 가을은 중간 날짜 중복/마지막 날짜 누락으로1490분.
이는 실제 합산 함수의 zoned DateTime 호스트 재현이다. 실기기 전체 UI 재현은 아님.
computeTotalWorkMinutes/computeOtDisplayEntries/weeksCoveringMonth도 같은
달력 순회 방식이라 연계 수정·검사가 필요. 월 합계 전체는 해당 시간대 기기에서 미측정.
수정 방향: 연/월/일 기준 calendar-day 순회(UTC 날짜 필드 또는 날짜 생성자)로
통일하고, 날짜 목록 자체를 비교해 누락·중복을 검사한다. 실제 경과시간 계산과 구분.
기존 ShiftSchedule의 패턴 인덱스는 Julian Day로 DST 영향을 피하고 있어 유지.
이 문제는 알람 시각 resolver가 실패했다는 뜻이 아니다.

C03 지역 기본값 보완: en_ZA/en_IN/en_AE가 en_US로 축약
release_locale.dart는 영어 지역을 en_US/en_GB 둘로만 나눈다. UAE가 mondayRegions에
없어 앱·native 위젯 모두 일요일. 공식 CLDR 현재값은 월요일.
실제 delegate 프로브: en_ZA/en_IN의 2026-04-05가 4/5/2026으로 표시된다.
남아공 CLDR 짧은 날짜 y/MM/dd, 인도 영어 d/M/y와 다름(S08).
en_ZA를 단순 en_GB로 바꾸면 주 시작까지 월요일로 바뀌므로 해결이 아니다.
수정 방향: 언어 번역, 지역 날짜/요일, 기기 시간형식을 분리해서 보존.
en_AE 날짜 자체는 CLDR 영어/아랍어 관습이 다를 수 있어 국가만 보고 D/M으로
강제하지 않는다. locale의 언어+지역과 사용자 선택을 함께 존중한다.

C04 선택 개선: 입력 12/24와 목록/울림 화면 24시간 고정
AlarmTimePicker는 Android DateFormat.is24HourFormat을 읽으며 복귀 시 갱신.
내부 저장은0~23으로 유지해 AM/PM 전환 때 실제 시각이 바뀌지 않게 한다.
next_alarm_tab.dart:356/624, all_alarms_history_view.dart:161,
InAppAlarmController/AlarmOverlayService는 HH:mm 저장값을 표시한다.
helpAlarmTemplatesBody도 목록24/입력기기설정을 명시한다. 따라서 기존 의도된
정책을 누락 번역 버그로 취급하거나 취향으로 되돌리지 않는다.
개선안: 공통 '기기 설정 따름/12시간/24시간'을 도입하고 입력·목록·울림·알림을
같이 적용하되 저장값 불변. 미국/필리핀/인도/UAE에서 특히 유용할 가능성(추론).

C05 선택 개선: 달력 주 시작과 근로시간 집계 주 시작을 각각 선택
월~일 고정 집계를 법정 OT/회사 급여주로 오인하지 않게 한다. 회사마다 다름(S09).
달력 순서를 바꿔도 근무 패턴·배정날짜·저장요일·알람은 바뀌면 안 된다.

4. DST 알람은 이미 구현 — 호스트 검증과 경계
AlarmWallTime.kt와 alarm_wall_time.dart:
- 없는 시각: 변동 폭만큼 뒤로(1시간 전환 때02:30→03:30).
- 두 번 오는 시각: 두 번째에 한 번. 동일한 실제 시각은 합침.
- 스누즈: offset 포함 실제 instant 보존. 시간대가 바뀌어도 5분은 실제5분.
- TIME_SET/TIMEZONE_CHANGED에서 AlarmGuardReceiver가 재예약 경로 실행.
기존 Dart DST12검사, native AlarmDstTest3/AlarmSnoozeDstTest8 및 추가15개
시각 사례로 기존 동작을 확인. 추가 사례에 Berlin 양쪽 전환, 미국 비DST2지역,
남아공/필리핀/UAE/브라질3지역/인도 포함. 실제 잠금 알람·여행 중 재예약 미검증.
국가별 새로운 DST 토글보다 기기 시간대/규칙 유지와 날짜 합산 정확성이 우선이다.
근로시간은 사용자가 정한 근무당 분수 합계다. DST 밤의 실근무가7/9시간인지,
급여가8시간인지 자동으로 판단하는 출퇴근/급여 엔진은 현재 없다.

5. 국가별로 가치가 있는 추가 기능 — 근거와 제품 판단 분리
미국: 회사의 집계 주 시작·주간/격주 기간 선택, 현지 시간대 표기/여행 정책 확인.
연방 공휴일을 모든 직장의 휴무로 처리하지 않는다. S09/S10. 기능 권장은 추론.
영국: 잉글랜드·웨일스/스코틀랜드/북아일랜드 공휴일 선택, bank holiday에도
근무를 유지하는 정책. S11. 영어를 전부 rota로 바꾸는 것은 불필요(기존 판정 유지).
남아공: 지역 날짜·24시간 기본값, 공휴일 일요일의 다음 월요일 반영(S12).
출시국을 이유로 종교/언어를 임의 추정하지 않으며 영어 지역 형식부터 보완.
필리핀: Regular/Special Non-working/Special Working 구분이 있는 선택형 공휴일
데이터(S13). 회사 근무/수당은 따로 설정. 자정 넘는 근무의 귀속 날짜 명확화는
8개국 공통 개선이며 특정 나라만 야간근무를 한다는 주장은 아님.
UAE: 월요일 달력 기본값, 기간 한정 근무표(라마단 등), 확정/예정 공휴일 구분.
공공기관 주말을 모든 민간·교대근무에 강제하지 않음. 달 관측 날짜는 공식 발표
갱신 필요(S14). 사용자 종교 자동 추정/자동 알람 정지/기도알람 자동 추가는 불필요.
독일: 주별(KW) 번호 선택, 주(Bundesland) 공휴일 선택, DST 집계 정확성.
KW는 CLDR week preference 근거가 있는 선택 기능이지 출시 필수 기능은 아님.
공휴일의 지역 차이는 S15. 일반근무/대기근무 수당을 국가만으로 자동 계산하지 않음.
브라질: 12x36 패턴 시작 템플릿은 현지 공공서비스에도 실제 사용(S16).
현 앱의 사용자 패턴·근무당 시간으로 상당 부분 구성 가능하므로 새 계산엔진보다
선택형 템플릿이 적합. 주/시 공휴일과 ponto facultativo 구별, 브라질 시간대 선택은
장기 후보(S17). Carnaval을 모든 사용자 법정 휴무로 고정하지 않음.
인도: en-IN 지역 형식을 힌디어와 별개로 보존, +05:30, 주/연방직할지별 공휴일(S18).
힌디어가 인도 전체 언어가 아니므로 영어 선택 유지. 종교 축제/주말을 국가만으로
모두 적용하지 않고 지역·회사 선택형으로 설계. 인도 전체 별도 달력 강제 불필요.

8개국 공통 우선순위
1) C01/C02 기능 결함 수정 및 C03 지역기본값 보완.
2) C04/C05 공통 설정으로 개인/회사 관습 수용. 언어와 지역 분리.
3) 필요하면 사용자 선택형 공휴일(국가+하위지역+표시언어+출처+확정상태+갱신일).
   공휴일은 표시용. 패턴/알람/휴무/수당을 자동 변경하지 않음. 한국 데이터 원문 보존.
4) 격주/반월 집계, 교대 패턴 템플릿, KW, 근무지 고정 시간대는 선택 개선.
현재 코드에서 국가별 급여/세금/야간가산/공휴일수당 자동계산을 새로 넣어야 한다는
근거는 없다. 이를 추가하면 회사·업종·계약별 별도 설계가 필요하다.

검증 상세는 검증_명세.json 및 로그 참조.
프로브의 PASS에는 '현재 결함을 재현했다'는 관찰 검사가 포함된다.
따라서 전체 PASS 숫자를 제품 출시 승인/결함 해결로 해석하면 안 된다.
후속 제품 수정 시 후보→이전 원장→회귀 검사 순서를 유지하고 AGENTS의
tools/check_critical_release.ps1 및 빌드 필요 시 -Build를 실행한다.
이번은 제품 변경이 없어 필수 전체 빌드를 반복하지 않았고 관련 기능만 검사했다.

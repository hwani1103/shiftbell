[B. 유지할 제품·기술 계약]

B1. 알람과 스누즈

- 선택 소유자는 RingingAlarmTracker의 (alarmId, round, minutes, revision). 버튼에 표시된 immutable snapshot으로 실행한다. 같은 회차의 오래된 +15 표시를 누르면15분을 실행하며 종료/새 회차 토큰은 거부한다. 프로세스 잔재로 죽은 울림을 재생하지 않는다.
- −/+와 전역값 저장의 live 갱신은 표시/선택만 바꾼다. 소리·진동·DB/OS 예약·울림 회차·최초 자동 종료 deadline은 바뀌지 않는다. 이미 예약한 스누즈 epoch도 설정 변경으로 소급 이동하지 않는다.
- AlarmGuardReceiver 재확인 주기, 다음 알람 화면 갱신 주기, 일정 입력5분 단위, 수면 감지 경계값은 스누즈 설정과 별개다. 검색된5분 문자열을 일괄 치환하지 않는다.
- 목표 epoch=ceilSecond(acceptedEpoch+N*60000). DB와 OS 예약은 같은 epoch. 다른 알람과 동일한 절대 분이면 현재 울림만 종료, 상대 예약 유지, 추가 스누즈 없이 충돌 안내. 1분씩 뒤로 미루는 정책은 철회됐다.
- claimRingEnd는 최초 유효 종료1개만 처리한다. DB transaction/OS 반영과 실패 안내를 구분하고 DB 실패·OS 실패·확인 불가·최신 행 교체를 성공 예약으로 표시하지 않는다. 사용자 권한 설정을 자동 연쇄 실행하지 않는다.
- 전역값 소유는 native DPS snooze_defaults/default_minutes, bridge 저장 성공 후 Flutter 표시. 누락/잘못된 값5, 저장 실패 시 이전 값 유지. 백업 default_snooze_minutes는 native에서 읽고 복원하며 구 백업은5. 생명주기/복원 중 울림과 설정을 혼동하지 않는다.
- 최초 일반 울림은 기존 채널/그룹을 유지하고 silent=false/GROUP_ALERT_ALL. C에서는 최초 FSI 전용 ONE_SHOT/IMMUTABLE 토큰과 본문 탭 토큰을 분리한다. 화면 표시/실제 조절 후 최초 토큰 실행권을 폐기하고 갱신에는 같은 폐기 토큰 metadata를 유지한다. 숫자/언어 갱신으로 새 FSI를 만들지 않는다. B의 ‘갱신에서 FSI 필드 제거’는 대체됐다.

4. ChatGPT로 홍보 이미지를 만드는 방법
============================================================

결론: 캡처는 앱에서 직접 찍고, ChatGPT에 디자인과 합성을 맡기면 됩니다.
Canva/Figma에서 따로 편집해야 하는 방식은 아닙니다.
ChatGPT 이미지 생성으로 배경/스타일을 만들고, 최종본은 원본 캡처를 그대로 합성하도록 요청하는 방식을 권합니다.
이미지 생성만으로 앱 화면 전체를 다시 그리면 날짜·버튼·근무명이 바뀔 수 있기 때문입니다.
원본을 새 캔버스에 합성할 때는 비율을 유지한 확대/축소를 허용하되 내부 내용은 바꾸지 않습니다.

준비할 파일
• 한국어/영어/브라질 포르투갈어/독일어/힌디어 실제 캡처 각 5장.
• 실제 앱 아이콘 PNG, 이 텍스트 문서.
• 캡처에는 최종 출시 UI를 사용하고 개인정보/시험 알림/키보드/디버그 표시는 촬영 전에 정리.
• 모든 언어에서 같은 월·근무 패턴·근무 색·조 수를 사용하고 근무명만 현지화.
  예: 주간/야간/휴무, Day/Night/Off, Dia/Noite/Folga, Früh/Nacht/Frei, दिन/रात/छुट्टी.
• 전체 화면을 캡처한 원본을 보관. ChatGPT에 채팅 미리보기 사진만 주지 말고 원본 파일을 첨부.

권장 파일명
ko-KR_01_calendar.png ~ ko-KR_05_dark.png
en-US_01_calendar.png ~ en-US_05_dark.png
pt-BR_01_calendar.png ~ pt-BR_05_dark.png
de-DE_01_calendar.png ~ de-DE_05_dark.png
hi-IN_01_calendar.png ~ hi-IN_05_dark.png
중간 번호: 02_pattern, 03_next_alarm, 04_teams.

진행 순서
① ChatGPT 새 대화에 이 문서, 실제 아이콘, 영어 1번 캡처부터 올립니다.
② 아래 요청문 A로 스타일 시안 한 장을 만듭니다. ChatGPT에서 이미지 생성 기능을 사용하면 됩니다.
③ 색상·제목 위치·여백이 마음에 들면 그 시안을 같은 대화에 남기고 디자인 기준으로 고정합니다.
④ 요청문 B로 원본 화면을 보존한 최종 1장을 만듭니다. ChatGPT의 코드 실행/파일 생성이 가능한 채팅에서 요청합니다.
⑤ 최종 1장이 괜찮으면 한 언어 5장씩 나누어 올리고 요청문 C로 반복합니다. 총 25장을 한 번에 처리하려 하지 않아도 됩니다.
⑥ 대화가 길어져 새 대화를 쓰면 완성된 마스터 1장+이 문서+그 언어의 캡처 5장을 다시 첨부합니다.
⑦ 파일을 내려받아 앱 화면 원본과 비교합니다. 제목·악센트·힌디어 글자와 모음 부호·근무명·날짜를 확인합니다.

크기와 디자인 기준
• 휴대전화 최종본: 1080×1920px, 세로 9:16, 불투명 RGB PNG. 5장 모두 같은 크기.
• 위쪽 배너는 전체 높이 약 15~20%. 큰 제목과 짧은 보조 문구만 넣습니다.
• 나머지에는 실제 캡처를 비율 유지해 배치하고 앱 내용이 읽히도록 최대한 크게 보여줍니다.
• 원본 화면이 길면 먼저 여백/제목 높이를 줄이고, 핵심 앱 내용은 임의로 잘라내지 않습니다.
• 제조사 스마트폰 실물 목업보다 얇은 둥근 프레임과 약한 그림자를 권합니다.
• 대표 그래픽은 별도 1024×500px. 휴대전화 1080×1920 이미지를 이 칸에 그대로 넣지 않습니다.
• 모든 제목을 억지로 한 줄에 넣지 않습니다. 독일어/힌디어는 자연스러운 두 줄을 허용합니다.

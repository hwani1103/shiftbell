# 진단 파일 해석 매뉴얼 (1.0.24~)

사용자가 설정 → **"문제 신고용 진단 파일"**을 누르면 `Download/ShiftBell/ShiftBell_Diag_yyMMdd_HHmmss.txt`가 만들어지고 공유 창이 뜬다(카카오톡·메일로 받으면 됨).
파일은 두 부분이다: **① 내보낸 순간의 상태 스냅샷** → **② 기록(오래된 것 → 최근, 최대 약 512KB)**.
이 매뉴얼의 목표는 증상을 **권한 / 제조사·OS 백그라운드 제한 / 앱 코드 결함** 중 하나로 가르는 것.

> 개인 내용(메모·일정 내용, 근무명, 친구 이름, 공유 코드)은 파일에 없다. 알람은 ID·시각·종류(1=소리+진동, 2=진동, 3=무음)만 나온다.

---

## 1. 먼저 볼 것 — 스냅샷 (파일 맨 위)

| 항목 | 정상 | 이상하면 뜻 |
|---|---|---|
| `app` | `com.hwani1103.shiftbell 1.0.24 (26)` | 버전이 옛날이면 업데이트 안내부터 |
| `installer` | `com.android.vending` | 다른 값이면 스토어 외 설치(서명 다름 가능) |
| `notifications` | `true` | `false` → **권한**: 사전 알림·울림 제어 알림 안 보임 |
| `alarmChannelImportance` | `4`(HIGH) 이상 | `0`/`1`/`2` → **권한**: 사용자가 알람 채널을 낮춤/끔 |
| `exactAlarm` | `true` | `false` → **권한**: 정확한 알람이 막혀 늦게 울리거나 안 울림 |
| `overlay` | `true` | `false` → **권한**: 다른 앱 사용 중 알람 화면이 안 뜰 수 있음(소리는 남) |
| `fullScreenIntent` | `true` | `false`(Android 14+) → **권한**: 잠금 화면 전체 화면 알람 불가 |
| `batteryOptimizationIgnored` | `true` 권장 | `false` + 알람 지연 → **제조사·OS 절전** 의심 |
| `backgroundRestricted` | `false` | `true` → **OS 제한**(설정 > 앱 > 배터리 "제한됨") — 알람 누락 주원인 |
| `standbyBucket` | `ACTIVE`/`WORKING_SET`/`FREQUENT` | `RARE`/`RESTRICTED` → **OS 제한**: 앱을 거의 안 연 것으로 분류돼 백그라운드 실행이 줄어듦 |
| `powerSaveMode` | `false` | `true` → 절전 모드 중(알람은 보통 울리지만 지연 가능) |
| 최근 프로세스 종료 사유 | `EXIT_SELF`, `USER_REQUESTED`(스와이프 종료) 정도 | `FREEZER`, `EXCESSIVE_RESOURCE_USAGE`, 잦은 `LOW_MEMORY` → **제조사·OS 제한** / `USER_STOPPED` → **사용자가 강제 중지**(모든 예약이 지워짐, CLAUDE.md ⚠️6) / `CRASH`·`ANR` → **앱 결함** |
| `lastAlarmRefresh` | 최근 24시간 이내 | 며칠 전 → 자정 하트비트·앱 실행이 없었음(제조사 제한 or 앱 미실행) |
| `pendingOsRetryIds` | `[]` | ID가 남아 있음 → OS 예약 실패 후 재시도 대기 중(권한 거부가 흔한 원인) |
| `restoreLocked` | `false` | `true` → 백업 복원이 중간에 멈춤(앱을 열어 복원 마무리 필요) |
| 다음 알람 10개의 `os=` | 전부 `true` | `os=false`인 줄 → **DB엔 있는데 OS에 예약이 없음**: 권한 거부(`exactAlarm=false`)면 권한, 권한이 정상이면 **앱 결함** |
| `lastBackupManual` / `lastBackupAuto` | 자동 백업이 최근 | 자동이 오래됨 → 아래 백업 절 |

## 2. 기록 줄 형식

```
2026-09-23T06:59:58.120+0900 | ALARM_FIRED | id=1234 delayMs=1880 decision=RING screenOn=false
시각(기기 시간대 포함)          | 이벤트       | key=value ...
```

### 이벤트 목록 ↔ 기록하는 코드 위치

| 이벤트 | 뜻 | 주요 필드 | 기록 위치 |
|---|---|---|---|
| `SCHEDULE_OK` | OS에 기상 알람 예약 성공 | `id`, `at`(예정 시각), `verified=false`면 DB 확인 없이 우선 예약 | `AlarmWakeScheduler.scheduleIfCurrent` / `scheduleUnverified` |
| `SCHEDULE_FAIL` | OS 예약 실패(재시도 목록에 남음) | `reason=exact_alarm_permission`이면 권한, 그 외 예외 이름 | 같은 곳 |
| `SCHEDULE_SKIP` | 예약하려던 알람이 DB에 없음(이미 삭제됨 — 정상) | `why=no_row` | `AlarmWakeScheduler.scheduleIfCurrent` |
| `CANCEL` | OS 예약 취소 | `id` | `AlarmWakeScheduler.cancelIfGone` |
| `ALARM_FIRED` | 알람 수신 → 울림 | `delayMs`(예정 대비 늦은 ms, 음수=일찍), `screenOn` | `CustomAlarmReceiver.onReceive` |
| `ALARM_STALE_IGNORED` | 수신했지만 안 울림(DB에서 지워졌거나 시각이 바뀜 — 정상 방어) | `decision=SKIP_NO_ROW`/`SKIP_RESCHEDULED` | `CustomAlarmReceiver.onReceive` |
| `ALARM_END` | 울림 종료 | `type`=`swiped`(끔)/`snoozed`/`timeout`(무응답) 등 | `AlarmActionHelper.insertHistory` |
| `REFRESH_DONE` / `REFRESH_FAIL` | 10일치 알람 갱신 완료/실패 | 실패 시 `error`, `msg` | `AlarmRefreshEngine.refresh` |
| `SYSTEM_EVENT` | 부팅·업데이트·정확한 알람 권한 변경 수신 | `action`(`LOCKED_BOOT_COMPLETED`, `BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`, `ACTION_SCHEDULE_EXACT_ALARM_PERMISSION_STATE_CHANGED`) | `DirectBootReceiver.onReceive` |
| `CUSTOM_ALARM_ASSIGN` | 커스텀 알람 할당 시도 결과 | `result`(`scheduled`/`past`/`duplicate`/`dailyLimit`/`scheduleFailed`), `id` | `calendar_tab.dart _assignCustomAlarm` |
| `BACKUP_WRITE_OK` / `BACKUP_WRITE_FAIL` | 백업 파일 쓰기 결과 | `kind`(manual/auto), `bytes` / `reason`(`insert_null`=저장소가 거부, `write_or_verify`=쓰기·재확인 실패, 예외 이름) | `MainActivity.writeBackupFile` |
| `BACKUP_SKIP` | 백업을 일부러 건너뜀 | `reason`=`same_content`(내용 동일 — 정상), `empty_schedule`, `restore_in_progress` | `backup_watcher.dart _run` |
| `BACKUP_EXCEPTION` | 백업 준비 중 예외 | `error` | `backup_watcher.dart _run` |
| `RESTORE_STEP` | 복원 단계 결과 | `step`, `result`=ok/fail, `error` | `restore_coordinator.dart _advance` |
| `SHARE_SYNC_FAIL` | 친구 공유 업로드 실패 | `op`, `error` | `friend_sync_service.dart` |
| `DIAG_EXPORTED` | 이 진단 파일을 만든 시점 | `bytes` | `DiagReport.export` |

## 3. 증상별 판정 순서

### A. "알람이 안 울렸어요" (날짜·시각을 사용자에게 물어볼 것)

1. 그 시각 근처에 **`ALARM_FIRED`가 있다**
   - 있다 → 수신은 됐다. `ALARM_END type=timeout`이면 울렸는데 응답이 없었음(소리 설정·무음 모드·볼륨 확인). `type=swiped`면 사용자가 껐다.
   - `delayMs`가 수 분 이상 → **제조사·OS 절전**(스냅샷의 `batteryOptimizationIgnored=false`, `standbyBucket=RARE` 등으로 확인).
2. `ALARM_FIRED`가 없고, 그 알람의 **`SCHEDULE_OK`가 있다**
   - 스냅샷 `backgroundRestricted=true` / `standbyBucket=RESTRICTED` / 종료 사유 `FREEZER`·`USER_STOPPED` → **제조사·OS 백그라운드 제한 or 강제 중지**.
   - 그 사이 `SYSTEM_EVENT BOOT…`가 있는데 뒤에 `SCHEDULE_OK`가 다시 없음 → 부팅 후 재예약 누락 = **앱 결함**(`DirectBootReceiver` → `AlarmRefreshEngine`).
   - 위 어느 것도 아니면 → OS가 예약을 버림(드묾). 같은 기기에서 반복되면 제조사 이슈로 분류.
3. **`SCHEDULE_FAIL reason=exact_alarm_permission`** → **권한**(정확한 알람 허용 안내).
4. 그 알람의 `SCHEDULE_OK`가 아예 없다
   - 고정 알람: 그 날짜가 갱신 창(10일) 안이었는데 `REFRESH_DONE`만 있고 예약이 없음 → 근무표·템플릿·예외(skip) 확인 후 **앱 결함** 의심(`alarm_generation_service.dart` ↔ `AlarmRefreshEngine.kt` 계산).
   - `REFRESH_FAIL`이 반복 → **앱 결함**(`msg` 확인).
   - 커스텀 알람: `CUSTOM_ALARM_ASSIGN result=scheduled`가 없으면 애초에 안 만들어진 것(결과 값 확인).
5. 스냅샷 다음 알람 목록에 `os=false`가 있다 → 권한 정상이면 **앱 결함**(재시도 목록 `pendingOsRetryIds` 확인).

### B. "백업이 안 돼요"

1. `BACKUP_WRITE_OK kind=auto`가 최근에 있나 → 있으면 정상(파일은 `Download/ShiftBell`의 `..._auto_...json`).
2. `BACKUP_SKIP reason=same_content`만 반복 → 내용이 안 바뀌어 새로 쓸 필요가 없던 것(정상).
3. `BACKUP_WRITE_FAIL reason=insert_null` → 저장소가 파일 생성을 거부(저장 공간 부족·제조사 저장소) — **환경** 문제.
4. `BACKUP_WRITE_FAIL reason=write_or_verify` 반복 → 쓰기 뒤 다시 읽기 확인 실패 = **앱 결함 or 저장소 손상** 의심.
5. `BACKUP_SKIP reason=restore_in_progress`가 계속 → 복원이 멈춘 상태(`restoreLocked=true`) — 앱을 열어 복원을 마무리하도록 안내.
6. 백업 관련 기록이 전혀 없음 → 트리거(앱 시작·재개·배경 전환)가 안 불렸음 = **앱 결함**(`main.dart`의 `BackupWatcher.backupNow` 호출부).
7. "재설치했더니 백업이 안 보여요" → 사양(안드로이드가 옛 설치본 파일을 새 설치본에 안 보여줌). 첫 화면 "불러오기"로 직접 선택 안내.

### C. "친구 공유가 안 돼요"
- `SHARE_SYNC_FAIL error=…FirebaseException`(permission-denied) → 규칙·가입 설정(Firebase Auth "생성 사용 설정(가입)"이 꺼져 있지 않은지 — CLAUDE.md 참고).
- 네트워크 오류 이름 → 사용자 네트워크. 앱이 재개 때 자동 재시도함.

## 4. 판정 요약표

| 판정 | 대표 신호 |
|---|---|
| **권한** | `exactAlarm=false`, `SCHEDULE_FAIL reason=exact_alarm_permission`, `notifications=false`, 낮은 `alarmChannelImportance`, `overlay=false`, `fullScreenIntent=false` |
| **제조사·OS 제한** | `backgroundRestricted=true`, `standbyBucket=RARE/RESTRICTED`, 종료 사유 `FREEZER`/`EXCESSIVE_RESOURCE_USAGE`, 큰 `delayMs`, 오래된 `lastAlarmRefresh` |
| **사용자 조작** | 종료 사유 `USER_STOPPED`(강제 중지), `ALARM_END type=swiped` |
| **앱 코드 결함** | `REFRESH_FAIL`, 권한 정상인데 `os=false`, 부팅 뒤 재예약 없음, `BACKUP_WRITE_FAIL reason=write_or_verify` 반복, 종료 사유 `CRASH`/`ANR` |

## 5. 유지보수 규칙
- 새 이벤트를 추가하면 **이 문서의 이벤트 표에 같이 추가**(이름 = 코드 문자열 그대로).
- 필드에 개인 내용을 넣지 말 것(개인정보처리방침 "문제 신고용 진단 파일" 문단과 일치해야 함).
- 기록 파일 상한은 `DiagLog.MAX_FILE_BYTES`(파일당 256KB × 2).

GAME-01 / 06 구현 실행·작업 인계
현재 상태: 설계 문서만 작성. 아래 작업은 후속 게임 구현 지시를 받은 뒤 실행한다.
최종 사용자 제약: 기존 앱 무영향. 12_기존앱무영향_격리계약.txt가 모든 작업 범위를 제한한다.

0. 실행 원칙
기존 dev/prod 앱을 고치지 않고 독립 실험 앱과 패키지만 만든다.
기존 미커밋 변경을 reset/checkout/clean/stash하거나 통째로 format하지 않는다.
main/prod 병합, 커밋/푸시, release 빌드, 설치/배포는 이 설계서가 지시하지 않는다.
코드를 새로 만들 때 한 번에 큰 UI를 만들기보다 규칙→엔진→입력→재생→12레벨 순서로 진행한다.
같은 검증을 불필요하게 반복하지 않는다. 실패·변경 영향이 있는 범위만 재검사한다.
소규모 문구/색 변경마다 구현을 그대로 복제한 테스트를 만들지 않는다.
충돌/Goal/최대 N/입력 상태/호스트 격리처럼 결과가 깨질 수 있는 계약을 검증한다.

1. 명령 실행 안내
명령은 각 패키지/lab 디렉터리를 working directory로 지정하여 실행한다.
SDK 경로가 조사 때와 같다면 Dart 실행 파일:
C:\tools\flutter\bin\cache\dart-sdk\bin\dart.exe
PowerShell 예:
  & 'C:\tools\flutter\bin\cache\dart-sdk\bin\dart.exe' pub get
  & 'C:\tools\flutter\bin\cache\dart-sdk\bin\dart.exe' analyze
  & 'C:\tools\flutter\bin\cache\dart-sdk\bin\dart.exe' test
순수 Dart 패키지에만 위 dart 명령을 사용한다.
Flutter 패키지/lab은 해당 SDK의 flutter pub get / flutter analyze / flutter test를 사용한다.
lab Android flavor dev를 구성했다면 flutter build apk --debug --flavor dev.
빌드 타깃/경로는 반드시 lab 기준. 기존 앱을 working directory로 두지 않는다.
필요하지 않은 SDK 업그레이드, 전역 설정 변경, 기존 앱 pub upgrade는 하지 않는다.
위 명령은 후속 작업 지침이며 현재 수행 증거가 아니다.

2. 기존 앱 통합이 추후 따로 허용되는 경우의 메모
이 항목은 현재 작업 목록이 아니다.
먼저 12의 격리 경계를 다시 검토하고 변경 파일·실험 진입·회귀 범위를 별도 합의한다.
기존 AGENTS.md의 P0/언어 리소스 영향이 생기면 tools/check_critical_release.ps1 필수.
빌드가 필요한 허용된 변경은:
  powershell -ExecutionPolicy Bypass -File tools/check_critical_release.ps1 -Build
이 실행기는 기존 앱의 dev debug와 웹을 검사/빌드하며 -Release를 붙이지 않는다.
정적/호스트/빌드 결과를 실기기 잠금 알람 PASS로 쓰지 않는다.
실기기 알람·권한 검증은 docs/next_version/후속재점검_2026-10-05/권한_P0_회귀기준.txt.
레이아웃/실험 탭 가독성은 별도 검사이며 실행기 PASS로 대체하지 않는다.
UI 변경 기록은 docs/UI 완성도 개선/의 새 원장. 기존 기록은 보존한다.

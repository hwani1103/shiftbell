GAME-01 / 12 기존 앱 무영향을 위한 격리 계약
최종 추가 사용자 지시(2026-10-13): 기존 앱 사용에 영향이 있어서는 안 된다.
기존 dev 앱도 보호 대상이다. prod만 보호하고 dev를 자유롭게 바꿔도 된다고 해석하지 않는다.
이 지시로 앞선 '설정 우측 탭 실험'은 현재 구현 범위에서 보류한다.

1. 지금 수행하는 작업
신규 설계 문서와 문서용 JSON fixture만 작성한다.
생산 코드/앱 구성/데이터/설치 상태/서버/알람/광고/권한을 바꾸지 않는다.
게임 구현·앱 빌드·기기 설치·실행·배포는 현재 하지 않는다.

2. 후속 게임 구현을 지시받았을 때의 기본 허용 범위
신규 packages/sync_path_core/
신규 packages/sync_path_tools/
신규 packages/sync_path_ui/
신규 examples/sync_path_lab/
새 게임 작업 문서·검증 산출물의 독립 하위 폴더.
해당 경로가 이미 있으면 사용자 작업인지 확인하고 무단 덮어쓰지 않는다.
각 패키지/lab의 자체 pubspec/lockfile만 관리하며 기존 앱은 이들을 참조하지 않는다.
기존 앱 root pubspec에 path dependency를 추가하지 않는다.
독립 lab은 기존 dev/prod와 다른 applicationId, 자체 데이터 디렉터리, 자체 진입점을 사용한다.
소스 폴더가 같은 저장소에 있다는 이유만으로 기존 앱 런타임에 로드되는 구조를 만들지 않는다.
새 프로젝트의 자동 생성 명령은 지정한 새 디렉터리 안에서만 실행한다.
기존 root에서 flutter create/format/pub upgrade를 실행하지 않는다.

3. 현재 변경 금지 대상
기존 lib/main.dart 및 bootstrap/route/tab/body/back 처리.
기존 일정·근무표·알람·정확한 알람·전체화면·오버레이·알림 채널·권한 설정/복귀.
기존 providers/services/DB/백업/환경 설정/저장 키.
기존 AdMob 설정/광고 생명주기/대시보드/서버/네트워크 기능.
기존 테마/온보딩/공통 UI/스플래시/다국어 리소스와 생성 규칙.
기존 root pubspec/lockfile/asset 등록, Android manifest/Gradle/flavor/signing,
기존 공개 web viewer의 entry/설정/언어 범위.
기존 CI/출시 검사/설치된 앱의 데이터와 권한.
기존 미커밋 변경과 과거 원장.
게임 때문에 필요한 것처럼 보여도 이 경계를 자동으로 넓히지 않는다.
먼저 신규 모듈/독립 harness 안에서 해결한다.

4. 독립 실행 검증
앱 ID는 기존 dev/prod 실제 ID와 대조하여 다름을 확인한다.
기존 앱 ID를 재사용해 기존 dev 설치를 덮어쓰는 방식은 금지한다.
기존 앱의 SharedPreferences/DB/백업을 가져오거나 정리하지 않는다.
로그인·서버·광고·알람·백그라운드 서비스·추가 권한은 game lab에 넣지 않는다.
기존 앱을 게임 검증을 위해 재설치/초기화/force-stop하거나 설정을 바꾸지 않는다.
설치 없이 가능한 host/unit/widget/독립 debug build부터 진행한다.
기기 설치는 사용자가 요청한 경우 별도 앱임을 확인한 뒤 진행한다.

5. '영향 0'의 정확한 보고
기존 앱에 코드를 연결하거나 같은 기기에서 자원을 소비하면서 모든 영향이 수학적으로 0이라고
검증 없이 약속하지 않는다. 기능 보존 테스트 PASS도 모든 영향 0의 증명은 아니다.
이번 범위는 기존 앱의 코드·구성·데이터·실행 동선을 바꾸지 않는 구조로 한정한다.
보고할 때 '기존 앱 연결 없음', '이번 작업의 기존 앱 파일 수정 없음'을 증거로 표현한다.
설치/실기기 공존을 검사하지 않았으면 그대로 미검증으로 남긴다.
다른 동시 작업으로 이미 바뀐 파일을 이번 게임 작업 탓으로 되돌리지 않는다.

6. 향후 연결을 원할 경우
사용자가 독립 게임 검증 후 기존 앱 연결을 명시적으로 다시 요청할 때만 재검토한다.
그때 03의 실제 앱 조사 자료를 사용하되 최신 파일을 다시 확인한다.
연결 방식·실험 범위·회귀 검사·철회 방법을 별도 작업으로 구체화해야 한다.
이 문서의 작성이나 '게임 구현 시작'만으로 탭 추가 승인이 생기지는 않는다.
기존 앱 보호보다 게임 진입 편의가 우선해서는 안 된다.

GAME-01 / 07 검증 명세와 증거
현재 문서의 수학 검증과 향후 구현 테스트를 구분한다.

1. 실제 수행한 수학 검증
대상: 08의 12레벨, shared-goal-v1, Unit 2~3, N=2~3, 5×5~6×6.
작성 세션의 임시 JavaScript 계산으로 수행했다. 제품 엔진/실행 스크립트를 작성한 것은 아니다.
A 방식:
  Goal 종착 ray 그래프, 거리 가지치기 DFS, Unit 도메인의 호환성 CSP,
  상대 위치/속도의 유리수 분석 충돌.
B 방식:
  최소 거리 가지치기를 사용하지 않고 맵에서 직접 ray DFS로 길이 1..N을 열거,
  Unit별 경로를 정렬하여 A와 정확히 비교,
  전체 경로 조합의 안전성은 독립 유리수 후보 전수 검사로 비교.
각 Unit 경로 집합, 모든 경로 쌍의 최초 금지 충돌, 레벨별 전체 해답 수가 일치했다.
전수 공간 조합 359개, 안전 조합 47개. 도메인/안전 조합 모두 09에 보존했다.
L01/L03을 제외한 10레벨의 실패 계획은 각각 독립적으로 합법인 경로이며 실제 충돌한다.
L09 실패 예의 동시 세 Unit 접촉은 A-B/A-C/B-C 세 쌍을 모두 기록했다.
모든 맵의 "." 연결성, 모든 witness의 벽/Goal/횟수 조건을 검증했다.
10의 수학 벡터 20개도 분석 결과와 기대값을 대조했다.
fixture 표현: expected=null은 None, interval=true는 Step 전체 [0,1] CoincidentInterval,
time/position 객체는 InstantContact다. 분수 [p,q]는 기약 유리수이며 실제 Dart 타입으로 대응한다.
이것은 정적 설계 데이터의 검산이다. Dart 구현 테스트나 실기기 테스트 PASS가 아니다.

2. 독립 유리수 전수 검사의 완전성
보드 한 변 최대 크기 M, 끝점은 0..M-1의 정수.
어느 축의 상대 속도가 0이 아니면 그 절댓값 <=2(M-1).
접촉 시각은 t=-r/v이므로 기약 분모 q<=2(M-1)이다.
각 q에 대해 정수 p=0..q를 전부 검사하면 [0,1] 안의 모든 고립 접촉 후보가 포함된다.
좌표 비교는 q*S+p*(E-S) 정수끼리 한다.
이는 임의 FPS 샘플링이 아니라 이 유한 입력 범위에서 완전한 유리수 후보 집합이다.
r=v=0이면 전체 구간 접촉. 유효 v1 경로에서는 Goal에서 출발할 수 없으므로
이 경우의 비Goal 겹침은 t=0에서도 검출된다. 기하 단위 테스트는 interval 결과 자체도 확인한다.
각 Unit이 완료된 뒤에는 비교를 중단한다. Goal에서 정지한 Piece를 추가하지 않는다.
이 증명은 v1 정수 endpoint/단일 선형 Step에 한정한다.
포탈/임의 가속/분할 유리수 시간 궤적에 그대로 재사용하지 않는다.

3. 엔진 구현 필수 검사
E01 분수 정규화: 부호, gcd, 0/1, 분모 0 거절, 비교의 추이성.
E02 같은 시각 교차/다른 시각 교차.
E03 정면 접촉 t=3/8, Q=(15/8,0).
E04 같은 방향 추월 t=1/3, Q=(4/3,0).
E05 같은 속도로 떨어져 이동하면 접촉 없음.
E06 인접 칸 교환 t=1/2, 칸 사이 Q=(1/2,0).
E07 t=0/t=1도 검사. 시작점 중복은 LevelValidator에서도 별도로 거절.
E08 정지-이동 접촉, 정지-정지, 동일 궤적 interval은 geometry 층에서 정의.
    playable MoveCommand로 제자리 이동을 허용하는 테스트로 바꾸지 않음.
E09 x/y 후보 시각이 다르면 접촉 없음. 후보가 [0,1] 밖이면 없음.
E10 Goal 끝점 동시 도착 허용. Goal 중간 통과는 route 오류.
E11 먼저 Goal 도착한 Unit은 다음 Step에서 없음.
E12 최대 3회에서 A 1회/B 3회 도착 성공: 10의 earlyArrivalCase.
E13 모든 Unit이 N 이전에 끝나면 즉시 성공. 남은 Step을 기다리지 않음.
E14 같은 방향 분할·왕복 경로를 원형대로 보존.
E15 세 Unit 접촉을 빠짐없이 묶음. 같은 시각 별도 위치 두 충돌도 보존.
E16 다른 쌍의 금지 충돌과 Goal 도착이 같은 시각이면 전체 collision.
E17 (k,1)/(k+1,0) 중복 사건 제거. 금지 끝점 충돌 누락 없음.
E18 Unit 배열/쌍 검사 순서 변경해도 결과와 가장 이른 시각 동일.
E19 같은 입력 재실행 결과 동일, trace immutable, 실제 시계/랜덤 불사용.

동시 다른 위치 충돌 geometry 예:
A (0,0)→(2,0), B (2,0)→(0,0);
C (0,2)→(2,2), D (2,2)→(0,2).
t=1/2에서 (1,0),(1,2) 두 사건을 모두 반환해야 한다.
이는 Step/geometry fixture이며 전체 완성 레벨 인증을 대신하지 않는다.

4. 유효성 오류 검사
V01 잘못된 rows 길이/문자/치수/정수 타입.
V02 지원하지 않는 schema/ruleSet/mechanic은 명시 거절.
V03 ID/시작 중복, 시작=Goal, 벽 위 배치, 범위 밖 배치.
V04 이동 영역 비연결과 Goal-stopping 그래프에서의 개별 도달 불가.
V05 diagonal, zero-length, blocked 중간 통과, 맵 바깥.
V06 Goal 너머 endpoint 및 Goal 이후 명령.
V07 empty/missing/extra/duplicate Unit route, m>N, 최종 Goal 미도달.
V08 draft는 저장 가능하나 실행 불가. complete 여부는 데이터에서 재계산.
V09 레벨 버전 변경 시 옛 draft 재검증 및 결과 캐시 폐기.
V10 거대한/비정상 JSON 입력을 상한 확인 전에 거대한 자료구조로 전개하지 않음.

5. Solver/Generator 검사
S01 12레벨 개별 도메인과 09의 전체 safeAssignments 경로 집합 일치.
S02 exactCount와 capped lowerBound 구별. 시간/노드 초과는 UNKNOWN.
S03 왕복/분할 제거 테스트는 별도 제한 분석이며 기본 Solver에는 금지 조건 없음.
S04 Goal에서 ray 중단, reverse BFS 간선 방향 확인.
S05 방문 셀 재방문 금지 가지치기/기하 경로 분할 합치기 금지.
S06 동일 state에 도달하는 서로 다른 prefix를 무심코 합쳐 해답 개수 축소하지 않음.
S07 생성 witness를 독립 route 검증+전체 simulate로 재검사.
S08 seed뿐 아니라 generator/solver 버전과 정렬 순서 기록.
S09 mutation으로 벽/시작/Goal/N 변경 시 연결성·해답·통계 모두 재계산.
S10 조기 도착 포함 해답/레벨을 거부하지 않음.
랜덤 property test는 실패 seed를 저장한다. 예상 개수를 외부 정답 계산 없이 동일 코드로 재생성한 뒤
그 코드와 비교하는 자기복제 테스트만으로 정확성을 주장하지 않는다.

6. 변환 검증
- 두 Unit 교환: 접촉 시각/좌표 동일, Unit ID 집합만 대응.
- 맵과 경로의 회전/반사: 접촉 시각 동일, 좌표가 같은 변환을 따름.
- geometry 두 Segment의 시작/끝 동시 뒤집기: 고립 접촉 t→1-t.
  게임 전체의 시간 역전은 Goal 흡수 규칙 때문에 같은 성질이 아니다.
- 전역 재생 속도/FPS/캐릭터 크기 변경: SimulationTrace는 동일.
- 같은 방향 명령 합치기는 불변 변환이 아니다. 결과 변경이 가능해야 정상이다.

8. 기존 앱 무영향 검증
현재 문서 작업은 신규 docs 파일만 추가한다.
향후 독립 구현은 12의 allowlist 밖 수정이 없어야 한다.
기존 root pubspec/lockfile, lib, android, web, 기존 assets, providers, DB가 변경되면
그 변경을 해결하지 않은 채 '독립 구현 완료'로 인계하지 않는다.
기존 미커밋 변경 자체를 없애라는 뜻이 아니다. 시작 기준과 이번 작업 변경을 구별한다.
lab package ID/저장소를 기존 dev/prod와 분리하고 기존 앱에 게임 import/초기화/asset 등록을 하지 않는다.
같은 기기에서 두 앱을 동시에 실행하면 OS 자원 경쟁까지 0이라고 보장할 수는 없다.
따라서 기존 앱의 무영향을 '영향을 측정할 필요가 없다는 주장'으로 확대하지 않는다.
현재는 앱 내부 연결 자체를 하지 않는 것으로 직접 변경/기능 회귀 경로를 차단한다.
실기기 설치/실행/알람 공존 검증은 현재 미수행이다.

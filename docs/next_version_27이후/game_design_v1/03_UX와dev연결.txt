GAME-01 / 03 모바일 UX와 dev 연결
규칙 기준: 01 / 논리 데이터: 02 / 이 문서는 실행 전 설계이며 화면 구현 증거가 아님.
최종 추가 지시 적용: 기존 dev/prod 앱 무영향이 최우선이다. 실제 첫 구현은 독립 lab에서 한다.
이 문서의 기존 앱 연결 조사와 host adapter 설명은 후속 검토 자료이며 현재 수정 지시가 아니다.

1. 한 판의 흐름
허브 → 새 판/이어하기 → Unit A 선택 → 직선 종점들을 탭 → Goal로 완성
→ 다음 미완성 Unit 자동 선택 → 모든 Unit 완성 → 동시 시작 → 성공/실패.
성공: Goal 도착 연출 후 '다음 판', '다시 보기', '나가기'.
실패: 최초 충돌 위치/관여 Unit을 보여 주고 '경로 고치기', '다시 보기', '나가기'.
'경로 고치기'는 기존 경로를 유지한다. 맵 위에서 충돌 관여 Unit을 바로 선택할 수 있다.
'이 판 다시'는 현재 판의 모든 경로를 지우고 첫 Unit부터 계획한다.
레벨 1로 이동, 전체 진행도 초기화, 앱 종료를 같은 버튼으로 섞지 않는다.
이미 푼 레벨은 허브의 레벨 선택에서 다시 열 수 있다.

2. 경로 편집의 상세 계약
보드 아래 엄지 범위에 Unit 선택 카드/남은 명령 점/되돌리기/다시하기/실행을 둔다.
선택 Unit은 색+형태/문자 A,B,C로 식별한다. 색만으로 구별하지 않는다.
계획 중 Unit 선택은 보드 아래 카드로 한다. 보드 탭은 현재 Unit의 종점 입력을 우선한다.
다른 Unit의 시작 마커가 있는 칸도 합법 종점일 수 있으므로, 그 탭을 무조건 Unit 선택으로
가로채면 안 된다. 실패 검토 화면에서 충돌 Unit을 눌러 선택하는 동작은 별도 모드다.
유효 종점은 현재 초안 끝점에서 같은 행/열의 보이는 WalkableCell이다.
Goal 뒤는 강조하지 않는다. 막힌 칸을 지나 선택할 수 없다.
현재 위치 탭은 명령을 추가하지 않는다. 대기로 해석하지 않는다.
막힌 칸·대각선·Goal 너머 탭은 입력 거절+짧은 이유 안내만 한다. 기존 경로를 변경하지 않는다.
pointer down/up이 같은 칸의 탭일 때만 명령을 확정하는 방식을 첫 기본값으로 사용한다.
드래그 중 자동 꺾임/자동 최단 경로/근처 칸으로 큰 범위 스냅은 첫 버전에서 하지 않는다.
드래그 입력은 후속 UX 실험 대상이다.

유효 종점 탭 → endpoint 추가 → 명령 점 갱신.
Goal이면 해당 경로 complete → 다음 미완성 Unit 자동 선택.
마지막 Unit까지 완료되면 선택을 강제로 바꾸지 않고 실행 버튼을 활성화한다.
Goal 미도달 상태에서 N회를 쓰면 실행 불가, '되돌려서 길을 바꿔 주세요' 안내.
다른 Unit을 눌러 미완성 초안을 임시 보관하는 것은 허용한다.
이는 경로를 완료 처리하는 동작이 아니다.

완성 경로 수정:
카드 선택 시 기존 경로를 보여 주고 '되돌리기'와 '이 길 지우기'를 제공한다.
되돌리기는 해당 Unit의 마지막 endpoint 하나를 제거한다. Goal 제거 시 미완성으로 돌아간다.
자동 다음 Unit 선택 직후 전역 undo는 방금 확정한 이전 Unit의 Goal 명령을 되돌리고 그 Unit을 선택한다.
자동 선택 뒤 아직 새 명령을 넣지 않았고 수동으로 다른 카드를 고르지 않았을 때 이 예외를 적용한다.
그 밖에는 현재 선택 Unit의 마지막 명령을 되돌린다. 명령이 없으면 비활성이다.
선택만 바꾼 동작은 명령 undo 이력에 넣지 않는다.
임의 중간 endpoint 수정은 해당 위치 이후 명령을 폐기하는 명시 동작으로 후속 추가 가능하지만,
첫 버전은 마지막 되돌리기와 Unit별 초기화만으로 모든 경로를 수정할 수 있으면 충분하다.
삭제 후 남은 Goal 표시나 complete 캐시가 실행을 잘못 열지 않도록 complete는 경로에서 계산한다.

3. 보드 위 표시
Unit 원래 시작 위치는 식별 가능한 시작 마커로 유지한다.
초안 끝점에는 작은 선택 마커를 두어 현재 어디서 다음 명령을 잇는지 알 수 있게 한다.
이것은 두 번째 논리 Unit이 아니다.
선택 Unit의 경로는 선명하게, 나머지는 낮은 강조로 모두 유지한다.
차선처럼 경로를 옆으로 밀어 실제 궤적을 왜곡하지 않는다.
겹친 선은 선택 순서/대비/외곽선으로 구분하고 탭한 Unit을 맨 위에 그린다.
반투명 선의 겹침이 새 Unit 색처럼 보이지 않도록 조합을 점검한다.
같은 방향 분할은 전체 길 그림이 같을 수 있다. 보드에는 거리/시간/숫자 마커를 추가하지 않는다.
필요한 명령 편집 정보는 보드 밖 선택 카드의 방향 화살표 목록과 점 표시로 제공한다.
그 목록도 칸 수·분수·속도 계산을 표시하지 않는다.
벽은 확실한 채움/패턴/외곽선으로 표시한다. 장식 배경과 혼동하지 않는다.
Goal은 문/도착점 형태로 표현하여 '통과해서 그 뒤로 갈 수 없음'을 전달한다.
Goal 주위 1~4 진입 방향의 실제 벽 구조는 항상 보인다.
색상·형태·선·선택 강조·벽·Goal의 스타일은 공통 GameSkin 토큰으로 관리한다.

4. 재생과 실패 표현
실행 버튼은 모든 경로 완성 여부만으로 활성화한다.
충돌할 계획이라는 이유로 실행을 미리 막지 않는다. 시도하고 배우는 흐름을 유지한다.
실행 시 route snapshot을 core에 전달하여 전체 결과를 먼저 계산한다.
그 결과를 단일 전역 재생 커서로 표현한다.
Step 길이는 기본 650ms, 모든 Unit에 같은 t를 선형 적용한다.
개별 Unit에 easeInOut, 속도에 따른 시간 연장, 목표에서의 지연을 넣지 않는다.
탭/카드/결과 패널의 짧은 전환은 공통 AppUiMotion을 따른다.
현재 독립 lab에서는 그 원칙을 GameSkin의 모션 토큰으로 표현하고 기존 앱 파일에 직접 의존하지 않는다.

모든 Unit의 논리 중심에는 작은 점/코어를 표시한다.
장식 몸체는 작고 반투명하게 하여 외곽이 스치는 것과 중심 충돌을 구별한다.
비충돌 시 스쳐 지나가는 장면에 진동·붉은 효과를 내지 않는다.
충돌 시:
- 재생 커서를 정확한 최초 충돌 시각에 고정.
- 해당 분수 좌표에 공통 충돌 마커를 표시. 가장 가까운 타일 중심으로 옮기지 않음.
- 관여 Unit의 중심과 경로만 강조하고 나머지는 낮은 강조.
- '이 둘이 같은 순간에 만났어요' 같은 짧은 설명. 숫자 시각/분수는 개발자 검사 화면에만.
- 같은 시각 여러 충돌 위치가 있으면 모두 표시하고 선택으로 확인.
- 전역 시간 슬라이더 또는 짧은 충돌 전후 다시 보기로 원인을 확인 가능.
  첫 버전 슬라이더는 숫자 라벨 없이도 된다. 판정은 슬라이더가 다시 계산하지 않는다.

화면 프레임이 충돌 시각을 건너뛰면 다음 tick에서 충돌 시각으로 되돌려 고정한다.
이미 계산한 실패보다 뒤의 성공/도착 UI를 먼저 표시하지 않는다.
30/60/120FPS, 느린 프레임, 일시정지/재개에서 결과와 이벤트 순서는 같아야 한다.
Goal 도착 제거는 논리 시각에 즉시 일어난다. 작은 잔광은 별도 장식 객체다.
성공은 마지막 Unit 도착 시점에 확정하며 남은 N Step을 빈 애니메이션으로 재생하지 않는다.

5. 중단·복귀·저장
상태: hub / planning / replaying / paused / failureReview / successReview.
planning↔Unit 선택/undo는 draft revision만 갱신한다.
replaying에서는 경로 편집을 잠그고 나가기/일시정지만 허용한다.
앱 background, 다른 탭 선택, native navigation으로 화면을 떠나면 재생을 멈춘다.
보이지 않는 화면에서 Ticker/Timer/진동을 계속 돌리지 않는다.
복귀 시 계획은 유지한다. 재생 중이었다면 paused로 돌아와 사용자가 이어보기를 누른다.
프로세스가 죽었다가 돌아왔을 때는 저장한 경로를 planning으로 복구하고 재생은 자동 시작하지 않는다.
완료한 레벨 진행도와 진행 중 draft를 별도 버전 키로 관리한다.
권장 키 prefix: devPuzzle.v1. 기존 SharedPreferences 전체 clear, 일정 DB 테이블 추가는 하지 않는다.
저장 오류는 게임 내부 안내/재시도로 처리하며 앱 시작·알람 기능을 막지 않는다.
비동기 저장은 revision 순서를 보장하여 오래된 draft가 최신 것을 덮지 않게 한다.
잘못된/옛 규칙의 저장 데이터는 해당 게임 draft만 무효화한다. 다른 앱 데이터는 건드리지 않는다.
진행도 초기화 버튼은 첫 버전의 일반 화면에 넣지 않는다.

6. 화면 크기와 접근성
5×5를 입문, 6×6을 첫 확장으로 사용한다.
320 logical px 화면에 좌우 20px 여백이면 보드 가로 280px:
5칸 pitch=56px, 6칸 pitch≈46.7px. 추가 칸 간격을 넣으면 실제 hit 크기를 다시 계산한다.
44px 이상 셀 터치를 설계 목표로 삼는다. 작은 화면에 8×8을 그대로 줄여 배치하지 않는다.
controls는 최소 48px 터치 영역을 확보한다. 작아 보이는 탭도 터치 영역은 줄이지 않는다.
높이가 부족하면 설명/보조 영역을 스크롤하거나 줄이고 실행/되돌리기 접근은 유지한다.
광고를 넣어 보드 크기를 강제로 줄이는 변경은 이번 범위에 없다.
스크린리더에 Unit 선택, 장애물/Goal, 선택 가능한 목적지, 경로 완료 상태를 제공한다.
화면에는 수치 경로를 표시하지 않아도 접근성 탐색용 행/열 위치 설명은 제공할 수 있다.
색각 차이를 고려한 형태/문자 병용 및 선택 외곽선 대비를 검토한다.
앱의 고정 글자 크기 계약과 공통 타이포 역할을 따르며 임의 폰트 배율 분기를 추가하지 않는다.
동작 줄이기에서는 강조 맥동/잔광을 줄이고 Step 정지 화면+실패 위치 확인 방식으로 제공한다.
애니메이션을 생략해도 실패의 원인과 Unit 식별은 남겨야 한다.

7. 실제 저장소 연결 조사 (2026-10-13)
lib/main.dart의 MainScreen:
- _tabs의 안정 ID: 0 알람, 1 근무 관리, 2 달력, 3 컨디션, 4 설정.
- _visibleTabIndices가 언어/기능에 따라 표시 목록을 구성한다.
- native openTab/condition sentinel 및 날짜 이동 경로가 별도로 있다.
- body는 _tabs[_currentIndex]를 직접 표시한다. IndexedStack으로 모든 화면을 보존하지 않는다.
  따라서 게임 controller를 GameScreen State에만 두면 탭 이동으로 계획이 사라질 수 있다.
- root PopScope는 달력 이외에서 Back을 달력 이동으로 처리한다.
- 기존 배너 표시는 특정 탭 ID에 묶여 있다.
lib/providers/tab_visibility_provider.dart:
  근무/컨디션 옵션은 저장과 native 동작에 결합되어 있다. 게임 등록용으로 재사용하지 않는다.
android/app/build.gradle.kts: prod/dev flavor가 구분되어 있다.
lib/web_main.dart: 기존 공개 다국어 일정 뷰어이며 게임 웹 진입점이 아니다.
lib/theme/app_ui_theme.dart, lib/widgets/app_ui_components.dart:
  AppUiPalette/Typography/TextRole/TextTone/Metrics/Motion, AppUiText/Button/Card 등을 사용한다.
구현 시작 때 파일이 다른 작업으로 바뀌었는지 재확인한다. 이 조사 위치를 고정 line number로 믿지 않는다.

8. dev 실험 진입의 설계
게임 화면과 허브는 기존 앱과 별도인 examples/sync_path_lab에서 동작하게 만든다.
기존 앱 pubspec, main, 탭, theme, 저장소, Android 설정은 변경하지 않는다.
lab의 첫 화면 자체가 게임 허브다. 설정 옆 탭이 없어도 시작/종료/다시하기를 시험할 수 있다.
아래는 연결을 추후 별도로 허용했을 때 검토할 후보이다. 지금은 실행 작업으로 잡지 않는다.
host 진입점은 adapter 하나로 분리한다.
설정 우측 탭 실험을 적용한다면 기존 ID를 재정렬하지 말고 새 안정 ID=5를 끝에 추가한다.
이것은 실험안이며 제품 탭 배치 최종 확정이 아니다.
기본 gate: Android host에서 appFlavor == "dev"일 때만 실험 진입 표시.
prod/null/기존 웹 뷰어에서는 숨기고 직접 진입도 거절한다. kDebugMode만으로 구분하지 않는다.
이 gate는 진입 제한이다. prod 산출물에서 모든 게임 바이트가 제거됨을 보장하는 표현은 하지 않는다.
appFlavor 공식: https://api.flutter.dev/flutter/services/appFlavor-constant.html
게임용 광고는 추가하지 않고 기존 배너 대상 탭 집합을 유지한다.
게임 controller는 host가 lazy 소유하거나 게임 전용 session scope에서 유지한다.
일정 Provider/서비스에 controller를 넣지 않는다.

Back 처리 책임은 하나:
- 게임 판 화면에서 Back: 허브로, 계획 보존 및 재생 중단.
- 게임 허브에서 Back: 기존 host 동작에 위임.
- native 알람/날짜 링크 진입: 기존 기능을 우선하고 게임은 중단/보존.
중첩 PopScope 두 개가 동시에 pop/달력 전환하도록 구현하지 않는다.
현재 native ID 0/1/2/-2 및 기존 설정 ID=4의 의미는 바꾸지 않는다.
한국어 등 최대 6개 탭 노출, 숨김 기능 조합, 320px 폭을 실제 배치 검사한다.
새 탭을 숨겼을 때 currentIndex가 존재하지 않는 화면을 가리키는 상태도 방어한다.

9. 공통 테마와 언어
GameSkin에는 boardSurface, blocked, goal, routeByUnit, selection, collision,
textPrimary/Secondary, disabled, control 역할을 둔다.

10. 최소 UX 수용 기준
모든 경로는 Goal로 끝나야 실행 가능, 1회 도착도 완료로 표시.
벽/Goal 너머 입력 불가, 같은 방향 분할/왕복 입력 가능.
Unit 변경/실패/탭 전환/앱 복귀에서 경로 보존.
한 번의 undo로 자동 완료 직전 상태까지 정확히 복구.
실패 위치는 분수 좌표에 표시, 수치 계산은 보드에 미표시.
작은 화면에서 실행/되돌리기/나가기 접근 가능.
실기기 QA 전에는 '한 손 조작 검증 완료'라고 기록하지 않는다.

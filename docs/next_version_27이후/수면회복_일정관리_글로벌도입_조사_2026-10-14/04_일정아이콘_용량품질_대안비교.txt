1. 현재 실제 구조
lib/services/memo_category_classifier.dart: 한국어 키워드 우선 → char_wb 2~3gram TF-IDF → LogisticRegression → softmax top1-top2 margin<0.08이면 기타. 단어/문장 의미를 이해하는 LLM이 아니다. 가족/친구/스포츠 규칙의 우선순위와 예외어가 많아서 학습 데이터를 늘려도 앞단의 잘못된 규칙이 우선하면 개선되지 않는다. '누구와'와 '무엇을' 중 어느 것을 아이콘으로 표현할지도 라벨 정책에 따라 달라진다.
앱에 포함되는 모델: assets/ml/memo_category_model.json.
- 원본4,407,402bytes =4.407MB(4.20MiB).
- gzip 참고치1,124,892bytes. APK 압축/Play 다운로드 증가량과 동일한 실측은 아님.
- 특징21,462개, 학습클래스19개, 계수407,778개.
- 화면 의미카테고리25종 중 라켓/축구/농구/야구/구기/격투6종은 키워드 규칙 추가이며 학습모델19종에 없음.
- 기타 도형10종을 순환. iconIndex를 DB에 저장하므로 기존 아이콘 배열 순서를 바꾸면 과거 기록 아이콘이 바뀐다.

- user_batch1 500행 파일은 train.py가 직접 읽지 않음. pilot로 이미 반영됐는지와 별개로 파일이 존재한다고 학습 반영을 주장하면 안 됨.
- holdout은19종, 종별3~7문장 수준. 새로운6개 스포츠를 포함한 실제 전체25종의 글로벌 품질 보증셋이 아님.
- pubspec은 모델 JSON과SVG를 포함하며 ml/data 원문/모델joblib은 포함하지 않음. 학습 문장을 지운다고 앱 용량이 그만큼 줄어들지 않는다.

2. 사용자 제안 비교
안1: 현 방식으로4언어 추가, 증가10MB 이내
판정: 기술적으로 충분히 검토할 가치가 있다. 다만 현 JSON4.41MB를 언어별4개 단순복제하면 추가17.63MB여서 비압축10MB 초과. 실제 언어별 특징수는 다르므로 단순예산 비교다.
개선: Float32/Int8 binary weight,어휘상한/가지치기,언어별지연로딩. 현재 계수만Float32면1.63MB,Int8이면0.408MB(어휘/idf/scale/구현 제외). 25클래스×20,000특징×4외국어를Int8로 잡으면계수2.0MB. 어휘/idf·런타임을 포함해10MB 내 목표 설계는 가능하지만 실제 export/build 측정과 품질평가 전 보장 불가.
언어별2MB 목표×4=8MB+공통추가1MB+여유1MB 같은 예산으로 시작. 한국어 모델은 그대로 유지할 수 있다. 언어팩을 나눠도 일반 Flutter assets는 자동으로 Play 언어분할 대상이 되는 것이 아니므로 배포설계 없이 용량이 공짜로 줄지는 않는다.
품질: 데이터가 많다고 좋아지는 문제보다 라벨정의/짧은명사/혼합언어/경계사례가 중요. 영어영역의 국가별 어휘, 독일어 합성어, 포르투갈어 굴절·악센트, 힌디어·로마자힌디어·영어혼용을 각각 평가.

안2: 외국어 도형 순환만 사용
판정: 첫 출시의 가장 확실한 저비용안. 추가모델0,오프라인,예측지연/오매칭없음. 일정 내용/시각/알림 본체 가치가 유지된다. 대가:한눈에 의미 파악/한국어와 기능동등성은 낮다. '순번'을 새 숫자 아이콘으로 하려면 별도 UI결정이고 현재 있는 것은10개 기하도형순환이다.
주의: 현재 _handleSave 3616행에서 외국어면return. 주석의 영어순환 구현을 이미 완성된 것으로 믿으면 안 된다. capability허용+foreign 저장분기+도형순환을 실제 구현/검사해야 한다. 수정 저장할 때마다 새 도형이 도는지, 기존iconIndex유지 정책도 정한다.

안3: 한국어 학습데이터 삭제 후 내장 LLM
판정: 이번 기능에는 비추천. 학습 원문 삭제는 APK 절약이 없고, 배포 JSON 제거가 약4.41MB 절약의 실체다.
A. 앱이 모델을 함께 배포: Gemma3 270M 같은 작은 기반 모델도270M×4bit/8=135MB의 가중치 단순 이론량(실파일/혼합정밀도/토크나이저/런타임 제외)이라10MB 예산과 차원이 다르다. 특정 모델이 '가장 가성비'라고 판정할5언어25분류 실측이 없다. 작은 모델도 fine-tuning/분류 제약/검수가 필요하고 한국어 현재 품질보다 좋다는 보장이 없다. 공식270M 소개 역시 전용 작업 fine-tuning에 초점을 둔다.
https://developers.googleblog.com/en/introducing-gemma-3-270m/
B. OS 공유 Gemini Nano: ML Kit Prompt API는 기기 내 텍스트 분류가 가능하고 공유 모델을 써서 앱이 전체 가중치를 번들하지 않아도 된다. 하지만 지원 기기/모델 준비/버전별 지원·언어 품질·다운로드 상태를 확인해야 하며 모든 Android에서 기본 기능을 대체할 수 없다. 현재 공식 문서상 beta. 사용 불가 시 기존 분류 또는 도형 fallback이 필수라 한국어 모델 전면 삭제의 근거가 되지 않는다.
https://developers.google.com/ml-kit/genai
https://developers.google.com/ml-kit/genai/prompt/android
C. 서버 LLM: 앱 모델 용량은 작지만 일정 원문 외부 전송, 네트워크/비용/대기/고지 변경이 생긴다. 현재 로컬 처리 계약을 바꾸면서까지 아이콘 하나를 맞힐 가치는 낮다. 이번 추천에서 제외.

안4: 추천 — 보수적인 하이브리드
1차: 한국어 현행 보존, 외국어 도형 순환을 기본으로 출시. 또는 명확한 소형 다국어 키워드 사전만 추가하고 확신 없는 문장은 도형으로 둔다. 키워드도 품질 검증을 통과한 언어만 사용한다.
2차: 사용자가 아이콘을 바꾸는 작은 선택 UI+기기 내 재사용 기억. 현재는 아이콘 선택 UI가 없고 isUserCorrected=false로 저장하므로 이미 있는 기능이 아니라 새 기획이다. 저장된 categoryKey와 수정 출처를 유지하고 수정한 아이콘을 재분류로 덮지 않는다. 정확히 같은/보수적으로 정규화한 텍스트만 재사용하며 원문 클라우드 수집은 하지 않는다.
3차: 필요가 확인되면 양자화 소형 분류기. 범주 혼동이 큰 가족/사교/활동은 정답 정책부터 고정한다. 예를 들어 '친구와 치과'는 사람 우선인가 병원 우선인가. 한 문장에 여러 일정이 있으면 어떤 모델도 사용자의 우선순위를 자동으로 알 수 없다.
LLM은 사용자 기기 추론보다 개발 단계의 다국어 훈련문장 초안 생성에 쓰고 사람이 검수하는 편이 경제적이다. 학습/평가 템플릿을 분리한다. 현재 한국어 학습자산을 먼저 삭제하지 않는다.

3. 다른 기술 후보
- fastText 같은 작은 지도학습 분류기의 양자화도 실험 후보. 공식 분류 데이터셋의 압축 모델1.4~1.7MB 사례가 있다. 이 수치는 우리 앱의4언어25종 성능/용량 보증이 아니다. 현재 Dart 선형 분류기의 binary 전환보다 FFI/ABI/런타임 비용이 클 수 있어 우선순위는 후순위.
https://fasttext.cc/docs/en/supervised-models.html
- 외국어→한국어 온디바이스 번역→기존 분류기는 추천하지 않는다. ML Kit는 언어모델 약30MB를 안내하므로10MB 목표와 맞지 않고 번역 오류+분류 오류가 누적된다.
https://developers.google.com/ml-kit/language/translation/android
- 국가별 모델8개 대신4언어 기본+지역 동의어 사전. 기기 locale와 입력언어가 항상 같지는 않으므로 한국어 UI의 영어 일정, 힌디어 UI의 영어 일정도 다룬다.

4. 품질·용량을 판정하는 구체적 실험
새 코퍼스 학습 전 라벨 우선순위를 확정한다. 각 언어25종×최소30개 독립 평가문장=750개+애매함/오타/짧은 명사/혼합언어250개를 제안한다(언어당1,000개,4언어4,000개). 숫자는 제안 예산이며 통계적 품질 보장선은 아니다.8국가 어휘 변형을 배분하고 문장 템플릿 가족 단위로 학습/평가를 분리한다.
도형 기본/사전/현행 TF-IDF(binary 또는 양자화)/소형 분류기를 같은 holdout으로 비교한다. macro-F1, 종별 precision/recall, 잘못된 의미 아이콘 비율, 기타 fallback 비율, 의미 아이콘 부여율을 함께 본다. 전부 기타로 보내 점수를 좋게 보이게 하거나 부여율만 높여 오매칭을 늘리지 않는다.
잠정 제품 목표 예: 의미 아이콘을 부여한 건의 precision95% 이상, 부여율60% 이상. 목표 및 언어별 최저 성능이 현재 한국어 독립 평가보다 낮으면 그 언어는 도형 모드 유지. 이는 조정할 제품 기준이며 현재 달성한 측정값이 아니다.
저가 실기기에서 cold/warm 시간,RAM,타이핑 중 프레임,저장 반응을 확인한다. 예를 들어 warm P95 50ms 이내를 목표로 두되 분류 실패와 무관하게 저장은 성공해야 한다.5언어 모델을 한 번에 모두 로드하지 않는다.
10MB 정의는 우선 추가 번들 자산의 비압축 bytes로 보수적으로 관리하고 같은 기준 빌드의 APK 압축/설치/Play 다운로드 증가량을 따로 기록한다. 디버그 APK 전체 크기로 모델 효율을 판정하지 않는다. 이번은 모델 raw/gzip 참고치만 실측했고 새 APK/release는 빌드하지 않았다.

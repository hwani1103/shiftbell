수면·회복 / 일정관리 번역 계획
2026-10-14. 이번은 전수 조사와 계획, 실제4개 언어 번역본 완성/앱 반영 단계 아님.

결론
'가능한 화면 문장을 전부 목록화하여 의미 단위1:1로 번역한다'가 맞다. 다만 날짜/시간/일수/사용자 근무명이 들어가는 문장은 완성 문자열이 무한히 생기므로 모든 결과 문장이 아니라 모든 메시지 ID+분기+변수 계약을 목록화한다. 한국어 문장 조각을 순서대로 번역한 뒤 이어 붙이는 방식은 쓰지 않는다.

1. 현재 확보한 원문 목록
- 공통문구_5언어_대조.tsv: 현재 앱의 공통 설명/정책/백업/도움말 등 관련 ko/en/de/pt/hi 원문과 참조.
- 한국어전용_전체키_범위.tsv:196개 키 전체, 두 기능 이관 대상과 친구 공유 등 제외 범위, 변수 metadata.
- 수면일정_하드코딩_문구후보.tsv:30개 관련 Dart/Kotlin 파일의446개 한글 문자열/템플릿 후보 행. 로그·데이터 키·주석/인접 문자열 혼입 가능성과 여러 줄 조립 때문에 아직 번역 단위 개수는 아님.
- Android_한국어전용_원문.xml:10개 native 문자열. 리시버의 Toast 하드코딩은 TSV에 별도 포함.
- 전체_언급_검색.tsv / 전체_언어게이트.tsv: 다른 화면에 있는 두 기능 언급과 기능 조건을 역추적할 자료.
목록은 grep만으로 UI 완전성을 증명하지 않는다. 다음 구현 단계에서 사용자 표시 여부와 동적 분기별 템플릿을 확정한 뒤 '미분류0'을 완료 조건으로 삼는다.

2. 번역 단위 확정
필드: message_id / 원본파일:행 / 기능 / 노출화면 / 원문전체 / 발동조건 / 변수명·형 / 복수분기 / 근거ID / UI길이제약 / ko / en / de / pt-BR / hi / 검수상태 / 사례ID.
가령 sleep.last24h.low와 sleep.last24h.enough, sleep.last24h.withPreShift.low 등은 한국어의 suffix 조립 대신 의미가 완결된 별도 템플릿 또는 ICU select/plural로 표현한다. 번역 개수는 중복 라벨을 공통키로 합치고 문장 분기를 분리한 뒤 고정한다.
recoveryBriefing engine은 최종 한국어 String 대신 message ID와 typed argument를 반환하도록 경계를 정리하는 것이 가장 안전하다. 판단 로직은 동일하고 renderer에서 ARB로 문장 생성. 기존 테스트의 한글 substring 판정은 규칙 ID/arguments 검사와 실제 렌더링 검사로 나눈다. 한 번에 엔진과 수면 귀속 규칙까지 바꾸지 않는다.

4. 핵심 용어 계약(영어는 제안 초안)
수면·회복 → Sleep & recovery.
주 수면 → Main sleep. '밤잠/night sleep'으로 번역하면 야간근무 뒤 낮에 자는 주 수면이 잘못 설명된다.
낮잠 → Nap. 현재 앱에서는 근무중/야간전의 긴 수면도 이 칸에 들어갈 수 있으므로 '항상 짧은 낮 수면'이라는 정의를 덧붙이지 않는다. 도움말에는 보충수면을 포함하는 화면 분류라고 설명.
수면 추정 → Estimated sleep. Detected/Measured sleep로 확정 측정을 암시하지 않음.
확정 → Confirmed. 사용자 확인이며 의료/센서 인증 의미 아님.
회복시간 → Time between shifts / recovery time 문맥별 구분. 모두 실제 잔 시간이라고 번역하지 않음.
컨디션 → 단독 Condition은 질병/상태로 모호. 제목은 Recovery overview 또는 현재 제품명에 맞춘 용어; 본문은 schedule-based guidance.
일정관리 → Personal planner 또는 Events. shift schedule(근무표)와 구별.
일정 알림 → Event reminder/notification. 기존 wake-up alarm/full-screen alarm과 구별.
이 앱의 판단 → App-defined rule. 근거 논문이 직접 검증한 절대 기준처럼 강화하지 않음.
독일어/포르투갈어/힌디어 용어는 이 의미 정의에서 검수한다. 한국어→영어 초안을 참고하되 영어만 보고 중간 번역하여 한국어 조건을 잃지 않도록 원문·조건·사례를 함께 제공.

5. 문장 예시
원문: 지난24시간 수면 {duration}, 권장7시간보다 적어요.
영어 초안: You recorded {duration} of sleep in the past 24 hours, below the 7-hour reference used in this app.
검토점: 수면 기록 기반임을 유지하고 의료적 진단/실제 미기록 수면 부정으로 읽히지 않도록 한다. 원문 의미를 더 명료하게 고치는 경우 한국어도 승인된 공통 의미 계약으로 관리한다.
원문: 확인하지 않은 자동 수면 기록 {count}건은 반영하지 않았어요.
영어 초안: {count, plural, one{1 unconfirmed sleep estimate was excluded.} other{{count} unconfirmed sleep estimates were excluded.}}
원문: {shift} 근무 마친 지 {duration} · 다음 근무 {nextShift} {when}
완성 템플릿의 어순은 언어별 자유. shift/nextShift 사용자 입력을 번역하거나 이름으로 근무유형을 추측하지 않음.

6. 지역 처리
8개 국가마다 동일 텍스트를 복제하지 않는다.4개 언어 번역+지역별 날짜/주 시작/12·24시간/숫자/공휴일 표시를 분리. en-US를 모든 외국어에 강제하는 코드 제거 대상. Flutter와 Android 알림 시간 형식 일치, 자정 넘는 일정의 실제 날짜 표시 검증. 독일어 긴 합성어·힌디어 결합문자·pt-BR 줄바꿈/복수형을 실제 화면으로 확인.
주아체는 힌디어용 글꼴이라는 보장이 없으므로 적절한 fallback/선택을 확인하고 폰트 전환으로 한국어 저장 fontIndex의 의미를 바꾸지 않는다. 문자열 길이만으로 임의 잘라 의미를 손상시키지 않음.
건강 근거의 EU 법제 설명은 EU 출처임을 유지하고 미국/인도 등 모든 국가의 현행 법률 의무로 번역하지 않는다.14자료의 원문은 번역 검수 때 재확인하고 출처/앱 규칙을 분리한다.

7. 실행 순서와 완료 기준
① 메시지 ID·분기 목록 확정, 두 capability와 제외 기능 합의.
② 수면 로직을 바꾸지 않고 문자열 렌더링 경계/공통 ARB/native resources 준비.
③ 영어 전체1:1 초안→조건·숫자·부정문·의료표현 검수.
④ de/pt-BR/hi 전체 번역,모국어 검수 또는 해당 언어 전문가 검수 권장. 미검수는 완료로 표기하지 않음.
⑤ 모든 message ID에5언어 존재/빈값0/변수동일/ICU문법/생성파일최신 검사. 남은 한글 노출0(사용자 근무명·고유명·인용 제외).
⑥ 스냅샷 사례:단일야간/연속2·4일,주간/오후/휴무,시각미입력,기록0/1/3일,2시간경계,12:30경계,겹침/다수낮잠,현재진행,자동확정/거부,알림권한·채널차단,탭OFF/ON,언어전환,복원.
⑦ 5언어 화면의 좁은/넓은 화면,접힘/펼침,버튼 접근/줄넘침/고정텍스트배율 계약 확인. 공통 AppUiPalette/타이포/컴포넌트로 연결하며 화면별 색상 하드코딩 추가 금지.
⑧ tools/check_critical_release.ps1 -Build(dev debug+웹). native 위젯/알림/복귀는 실기기 별도. 앱 전용 기능과 공개다국어웹 의존성 회귀.
이번 번역 계획의 목표는 현행 한국어 기능의 의미 동등성이다. 불확실한 수면 규칙을 번역 작업 속에서 몰래 변경하지 않는다.

글로벌 출시 판단 — 수면·회복 / 일정관리
2026-10-14

권고: 두 기능 모두 글로벌 제공 방향에 찬성한다. 기본은 선택형 유지. 일정관리부터 상대적으로 가볍게 도입하고, 수면·회복은 번역과 날짜/시간 검증을 마친 뒤 제공하는 순서가 좋다. 지금 소스의 한국어 제한만 일괄 해제해서 바로 출시하는 것은 권하지 않는다. 아이콘 AI 개선을 두 기능의 출시 선행조건으로 두지 않는다.

1. 수요에 대해 확인된 것과 미확인인 것
'적은 사람이지만 꾸준히 사용하는 것 같다'는 사용자의 관찰은 충성 사용자용 기능의 가능성을 보여준다. 이번 작업에서 실제 사용자 코호트/언어별 기능 유지율을 조회하지 않았으므로 재사용률이 높다고 수치로 확정하지 않는다.
코드에는 일정 생성/수정/삭제/알림 변경, 수면 저장/수정/삭제/추정 거부 이벤트가 있다. 이벤트 수가 곧 고유 사용자 수나 반복 사용자 수는 아니다. 위젯 native 기록은 Dart notifier 저장 이벤트와 경로가 다르므로 수면 저장 이벤트만으로 총 사용량을 세면 누락 가능성이 있다. 일괄 확정 경로도 개별 저장 이벤트와 동일하게 계측되지 않는다.
해외 수요를 국내 비율×8로 추정하면 안 된다. 국가 수보다 교대근무 사용자 수, 근무 패턴, 기능 발견률, 언어 품질, 기기 성능이 중요하다. 현재 미제공 국가에서 사용량0인 것은 수요0의 증거가 아니다.

2. 사용자 가치와 비용
수면·회복 장점:
- 별도 수면 앱과 달리 이미 입력한 근무표·출퇴근·OT에 연결된다. 야간 뒤 수면을 근무일에 묶고 다음 출근에 맞춘 안내를 제공하는 점이 앱의 본업과 맞는다.
- 기록·일부 통계만 쓰는 사용자도 받을 가치가 있다. 친구 공유 서버처럼 기능 자체를 위한 원문 서버 저장은 추가되지 않는다.
대가:
- 문구가 많고 건강 안내의 의미를 엄밀히 유지해야 한다. 번역이 잘못되면 기록없음/수면부족, 회복시간/실제수면, 참고기준/법률·진단이 혼동된다.
- 자동 감지는 실제 수면 센서가 아니다.20분 샘플/5시간 기준/후보확인/9시간 cap을 정확하게 안내해야 한다.
- DST·여행·위젯·정확한 알람·백그라운드 등 검증 범위가 넓다. 유지보수 비용은 탭을 숨겨도 남는다.
일정관리 장점:
- 근무 사이 약속/할 일을 같은 앱에서 관리하고 시간 알림을 받을 수 있다. 이미 있는 메모와 역할이 다르다.
- 의미 아이콘은 편의장치이며 핵심은 내용·시각·저장·알림이다. AI 없이도 유용하다.
대가:
- OS 캘린더와 기능이 겹쳐 누구나 사용할 기능은 아닐 수 있다. 잘못된 아이콘은 신뢰를 낮춘다.
- 알림 채널/권한/언어전환/재부팅/탭 숨기기와 저장 날짜 처리 비용. 다국어 시간축·폰트·좁은 화면 검증도 필요.

3. '설정에 숨겨져 있으므로 리스크가 작다'는 판단
대체로 맞는 부분: 불필요한 하단 탭 증가, 처음 배우는 부담, 쓰지 않는 사람의 화면 복잡성을 줄인다.
남는 부분: 앱 용량은 사용 여부와 무관하게 증가한다. 비활성 상태의 native 예약/위젯과 앱 preload 정책이 정확해야 한다. 번역/정책/지원/데이터 복원은 계속 관리해야 한다.
특히 현재 initializeTabVisibilityDefaults는 기존 근무표 또는 permissions_requested가 있으면 missing pref를true로 저장한다. 외국어 사용자는 capability 때문에 안 보였더라도 이미true가 저장됐을 수 있다. 새 capability만 열면 업데이트 순간 탭이 저절로 나타날 수 있어 '선택형이니 자동노출없음'은 아직 성립하지 않는다.
출시 때 새로 가용해진 사용자와 실제 선택한 사용자를 구분하는 versioned opt-in 이관을 설계한다. 한국어 사용자의 기존 선택과 복원된 선택은 보존. 과거 실제 사용 이력/언어 이동까지 고려해 모든true를false로 덮지 않는다. 새 제공 알림은 설정에서 한 번만 가볍게 안내하고 강제 활성화하지 않는다.
수면 OFF이면 자동 감지 예약을 취소하고 앱 복귀/언어전환/재부팅에서도 재활성화되지 않는지 확인. 현재 native missing pref=true인 경로와 Flutter 신규설치false 초기화를 함께 확인해야 한다.

4. 출시 전 우선순위
G-01 [필수] supportsSleepRecovery/supportsPersonalSchedule 기능 경계. 친구공유/기존 달력 테마 등 미제공 유지, 공개웹뷰어 회귀.
G-02 [필수] 모든 실제 표시 문구5언어/변수/분기 완결, 한국어fallback없음. 도움말·앱privacy·공개privacy·첫실행/설정·native 알림/위젯 정합.
G-03 [필수] 기존 외국어 사용자 opt-in 이관과 OFF 상태 동작. 데이터/기존 한국어 선택 보존.
G-04 [수면 출시 전] DST 지역의 날짜 귀속·근무시각·자동추정창. Dart/native 계산 불일치의 정적 근거가 있으므로 수정 또는 기능 범위 결정 후 실제 timezone 시나리오 검증. 여행과 중복시각 처리의 제품 계약을 정함.
G-05 [일정 출시 전] 외국어 저장 실행 가능, 도형순환 fallback, 편집 시 아이콘 보존 정책. iconIndex 배열 순서/기존 DB 보존.
G-06 [필수] 알림 차단/개별채널 차단/정확한알람 미허용/복귀/언어전환/재부팅/탭OFF/ON. tools/check_critical_release.ps1 -Build 후 실기기 별도.
G-07 [수면 고지/일관성] 자동5h/위젯확정2h 및9h cap 경로 차이. 어느 정책을 유지할지 결정하고 도움말을 실제 동작과 일치.
G-08 [출시 운영] 건강 기능 신고/스토어 설명/개인정보 방침의 기존 등록 내용과 실제 제공 범위 일치 확인. Google Play 안내에서 Sleep Management는 건강 기능 신고 항목이다. 기존에 수면 기능을 신고했을 수 있으므로 '새 규제 미준수'라고 단정하지 않음. 이번에는 Console 현황 미조회.
공식 근거: https://support.google.com/googleplay/android-developer/answer/14738291?hl=en

5. 단계 제안
단계A: 문구표/기능 계약 확정. 이번 산출물로 완료한 것은 조사와 권고다. 실제 번역 구현은 별도 작업.
단계B: 일정관리4언어. 도형순환으로 시작하고 의미 AI는 선택적 후속. 수면 기능 검증이 늦어져도 일정관리 출시를 묶어 지연하지 않는다.
단계C: 수면·회복 영어로 먼저 검증한 다음 de/pt-BR/hi를 같은 로직에 연결. 날짜/시간·전체 메시지 검증 후 선택형 공개. 영어만 먼저 실제 공개할지4언어를 함께 공개할지는 검수 준비도에 따라 결정; 언어별 제공 상태를 capability로 명시.
단계D:28일 정도 초기 관찰. 기능이 좋은데 안 발견되는 것인지, 켜지만 다시 안 쓰는 것인지 분리. 이후 AI 아이콘 투자 결정.
모든 단계는 dev debug가 기본. 현재 release 빌드/Play 배포를 요청받은 것이 아니므로 이번 실행하지 않음.

6. 측정 계획 — 새 기획이며 구현 안 함
가능하면 기존 앱 실행/화면/기능 사용 이벤트를 활용하고 필요한 최소한만 추가.
- 발견: 설정의 기능 설명 노출 고유 사용자 수 / 기능이 가용한 활성 사용자.
- 활성화: 탭 활성화 고유 사용자 / 설명 노출 사용자.
- 첫가치: 활성화7일 내 첫 일정 저장 또는 수면 확정 사용자.
- 반복사용: 활성화 코호트 중 첫 사용 후 둘째 주에도 저장/조회한 사용자.7·28일 기준을 분리하고 사용일수도 확인.
- 중단: 탭 다시숨김,추정거부비율,예약실패,수동수정. 숨겼다는 사실만으로 불만족 확정하지 않음.
- 품질: 수면추정 제시→확정/수정/거부,일정알림설정→예약성공. 실제 울림은 예약성공과 구분.
- 언어×앱버전×기능가용/활성화 상태를 기준으로 비교. 원문/근무명/수면시각/일정내용 전송 없이 카운트와 범주로 구성. 위젯/일괄확정 누락을 먼저 계측 경계로 다룬다.
매출/리뷰/유지율 상승을 이번 단계에서 약속하지 않는다. 앱 전체 유지율 차이는 자발적으로 기능을 켠 사람의 성향 차이가 섞이므로 바로 인과효과로 해석하지 않는다.
초기 성공선은 '전체 사용자의 많이 쓰는 기능'보다 '켜 본 사람에게 반복 가치가 있고 알람·성능·지원 부담을 악화시키지 않는가'. 사용자 모수가 적으면 몇 주 수치로 폐지하지 말고 텍스트 피드백과 함께 판단.

최종 판단
출시 방향 YES, 지금 즉시 제한만 해제해서 공개는 NO.
수면은 교대근무 특화 가치가 있어 유지할 이유가 충분하다. 일정은 기본 저장/알림 품질을 우선하면 낮은 모델비용으로 확장할 수 있다. 한국어 데이터를 지우고LLM을 넣는 대공사는 지금 하지 않는 편이 좋다. 조건이 충족되면 선택형 글로벌 공개 후 실제 재사용을 보며 투자 범위를 키운다.

수면 기록·매칭·회복 로직 정밀 분석
2026-10-14 / 현재 실행 코드 기준. 의도는 주석·기존 회귀 사례로 복원하되 현재 동작과 구분.

1. 핵심 설계 의도
수면을 민간 날짜의 자정마다 잘라 놓는 것이 아니라 '어느 근무일을 위한 수면인가'로 묶는다. 야간 전에 보충한 잠은 당일 낮잠, 야간 근무 중 잠도 당일 낮잠, 퇴근 뒤 회복수면은 전날 야간 근무일의 주 수면으로 보이게 한다. 연속 야간에서는 아침 회복수면과 다음 출근 전 수면을 분리한다. 반면 지금 충분히 잤는지 안내할 때는 달력의 날짜 배정과 별개로 최근 실제 24시간을 센다. 이 두 개념이 핵심이다.
DB에는 주 수면/낮잠/귀속 날짜를 저장하지 않는다. 시작·종료·source·status·confidence만 저장하고 근무표/근무시간을 읽어 매번 재분류한다. 따라서 근무표를 바꾸면 과거 수면의 표시 날짜/분류도 바뀔 수 있다. 사용자가 '주 수면 칸'을 눌러 넣어도 시간을 저장한 후 계산상 낮잠으로 이동할 수 있다.

2. 근무일과 근무 종류
shift_pattern_analyzer.dart:107: 날짜별 실제 근무명(규칙/불규칙/날짜 변경)을 가져오고 휴무명 또는 미배정/출퇴근 미설정을 구분한다. 사용자가 야간이라고 이름 붙였는지가 아니라 시작 시각으로 분류한다.
05:00~10:59 시작 = 주간 / 11:00~16:59 = 오후 / 17:00~04:59 = 야간. 예를 들어 17~23시도 야간이다. 근무시간을 모르면 야간 후 회복 예외를 적용할 수 없다. 휴무명은 한국어 '휴', Off/Rest/Holiday/Leave/Vacation/PTO, Frei/Urlaub, Folga/Férias, 힌디어 휴무 표기를 인식하는 휴리스틱이다.
출퇴근 같은 시각/자정 넘김은 ShiftTimeRange 계약을 따르며 근무 시작 날짜가 배정 날짜다. 임의로 새벽 근무를 전날 근무로 해석하지 않는다.

3. 정확한 날짜 귀속 알고리즘
원본: lib/services/condition/sleep_day_slots.dart의 attributedSleepDay / _attributedDay.
S=실제 취침, E=기상, D=취침 날짜, P=D-1.
(1) analyzer가 없거나 P가 시각을 아는 야간 근무가 아니면:
    S의 시각이 00:00 이상 06:00 미만이면 P, 06:00부터는 D.
    기상 시각/수면 길이는 이 단계의 날짜 귀속에 관여하지 않는다.
(2) P가 야간이면 종료 보정 T = P의 실제 설정 퇴근 -60분.
    S<T이면 즉시 P. 이 가지는 수면 중간 시각을 보지 않는다.
(3) 그 밖에는 경계 B = D일 21:00.
    D에도 시각을 아는 근무가 있고 그 출근이 T보다 늦으면
    B=min(D일 21:00, T와 D 출근 사이의 중간 시각).
    D 근무는 반드시 야간일 필요가 없다.
(4) 완료된 기록의 중심 C=S+floor((E-S)의 분/2)분.
    진행 중이면 C=S.
    C<B이면 P, C>=B이면 D. 경계에 정확히 닿으면 오늘 쪽.
주의: 일부 주석은 아직 '시작 시각' 또는 13:00 경계를 설명하지만 실제 코드는 위 규칙이다.
19:00~다음 07:00 / 다음날 19:00 재출근이면 T=06:00, B=12:30이다.
21시는 개인 데이터로 학습된 취침 시각이 아니라 고정 앵커다.

4. 날짜 결정 뒤 주 수면/낮잠 배정
원본: sleep_day_slots.dart _isMainSleep, buildSleepDaySlots.
- status==confirmed인 기록만 달력 슬롯에 들어간다.
- 근무와 겹치면 아무리 길어도 낮잠. 근무 구간은 시작~보정 종료로 비교한다. 야간 마지막 60분은 근무 겹침에서 제외한다.
- 취침한 날이 야간이고 기상이 당일 출근보다 늦지 않으며 이미 전날에 귀속된 수면이 아니면 길이와 무관하게 낮잠이다. 연속 야간 아침 회복수면은 전날 귀속이므로 이 규칙에서 제외.
- 그 밖에는 120분 이상 주 수면 후보, 120분 미만 낮잠.
- 완료 안 된 수면은 임시로 20:00~05:59 시작이면 주 수면 후보. 기상 후 길이·중간 시각이 생기면 날짜/종류가 바뀔 수 있다. 근무 겹침과 출근전 조건은 먼저 적용.
- 같은 날짜에 후보가 여럿이면 가장 긴 1개만 주 수면, 나머지는 낮잠. 동일 길이 tie-break는 명시 계약이 없으므로 '항상 먼저 잔 잠'이라고 설명하지 않는다.
- 낮잠은 시작순. 화면은 2칸만 표시하지만 naps 목록과 napMinutes에는 세 번째 이후도 들어간다. 하루 3건을 DB에서 강제하지 않는다.
- 다른 함수 sleep_shift_relation.dart는 비근무 수면을 180분으로 main/nap 라벨링한다. 실제 달력 120분 기준과 다르다. 현재 주 화면의 근무별 평균은 슬롯 120분 기준을 사용한다. 구형 sleep_stats 통계/이력 함수를 현행 UI와 혼동하면 안 된다.

7. 일반 주간·오후·휴무·미설정
주간/휴무 뒤 00:30~08:00은 전날 주 수면. 06:00 이후 시작은 당일. 당일 주간근무 중2h/6h 수면은 낮잠. 오후근무가22시에 끝나면 자동추정창은21시 대신22시 이후지만 표시 날짜는 별도 알고리즘이다.
휴무일 낮4h와 밤7h가 같은 귀속일에 있으면 밤7h가 주 수면, 낮4h는 낮잠. 휴무일에 낮4h만 있으면 그 잠은 주 수면이다. 낮에 잤다는 사실만으로 낮잠이 되지 않는다.
근무시간 미설정이면 근무와 겹치는지 판단할 수 없어 길이/새벽06시 규칙만 쓴다. 미입력=휴무=수면0시간으로 치환하지 않는다.

8. 수동 입력·편집·삭제·조회
SleepRecord source: MANUAL / WIDGET_MANUAL / AUTO_DETECTED. status: CONFIRMED / PENDING_CONFIRMATION. 종료 null이면 진행 중. 시간은 로컬 yyyy-MM-ddTHH:mm:ss, UTC offset/timezone ID 없이 저장된다.
수동 편집 UI: 종료>시작, 시작/종료가 미래 아님. 날짜 picker 2000년부터 내일까지이지만 미래 기록 저장은 막는다. notifier는2분 미만을 조용히 버린다. UI에서1분 입력이 valid인 것과 실제 저장 최소2분은 별개이므로 사용자 피드백 개선 후보.
입력/편집/자동 후보 확정 시 겹친 confirmed 기록(진행 중 포함)을 찾고 중복 입력을 막는다. pending 후보는 수동 입력을 막지 않고, 나중에 후보 확정 시 겹침을 검사한다. end==다음 start는 겹침 아님. provider의 addManual/updateTimes 자체는 겹침을 강제하지 않고 UI가 검사한다. DB 전역 제약은 아니다.
일괄확정은 앞서 확정한 기록도 검사해 겹친 것은 건너뛰며 건수를 반환한다. 자동 기록 거절/삭제는 native 시간대별 거절 힌트로 전달한다.
미니 달력은14일. 기본 provider는 최근60일 범위 기록. 전체보기는 getSleepRecords() 무제한 조회 후 월 표시이므로60일 이전 기록을 삭제하는 정책은 아니다. 손상된 행은 행별 decode를 건너뛰며 전체 로딩을 실패시키지 않는다.
빈 슬롯 기본시각: 주 수면22~다음06, 낮잠1 14~14:30, 낮잠2 16~16:30. 야간에 맞춘 기본 입력값은 아니다. 표시 슬롯을 고른 사실은 저장된 분류를 고정하지 않는다.

9. 위젯 기록
SleepWidgetActionReceiver:
수면 버튼→MANUAL/CONFIRMED/종료null 생성. 이미 수동/자동 진행 중이면 새 기록을 만들지 않음. 기상 버튼→진행 중 수동 우선, 없으면 자동을 종료. 수동 종료는2분 이상이면 WIDGET_MANUAL로 출처 전환. 자동 종료는2시간 이상이면 CONFIRMED, 미만이면 삭제한다. 따라서 앱의 자동추정 제시5시간 기준과 다르다. 자동 수면 위젯 확정이 현재5시간 규칙을 따르는 것은 아니다.
위젯 자동 종료 경로 자체에는9시간 cap이 없다. 추정 리시버의9시간 종료보다 위젯 기상 이벤트가 먼저 처리되는 예외에서는9시간을 넘는 자동 출처 확정 기록 가능성이 있어 native 회귀로 확인할 대상. 이번 수정 안 함.
수면 위젯의 한국어 제한/탭 OFF/복원 중 차단은 native의 별도 조건이며 화면만 번역하면 안 됨.

10. 자동 추정 창과 후보 생명주기
sleep_opportunity.dart와 SleepScheduleResolver.kt가 대응한다. 개인 평균 취침시각을 학습해 감지창을 정하지 않는다. sleep_expected_bedtime DB는 과거 구조로 남아 있고 현재 개인 취침 학습 기능의 근거가 아니다.
야간 회복창: 퇴근-60분부터 최대9시간, 다음 근무 출근이 더 이르면 종료.
야간 출근전창: 출근-6시간부터 출근까지. 연속 야간이면 전날 회복창 종료 이후로 시작을 미룬다.
그 외 창:21시~최대9시간(통상06시), 해당 근무가21시 뒤에 끝나면 실제 퇴근부터. 야간 근무일21시에는 일반창을 만들지 않는다.
활성 창 여러 개면 시작이 가장 늦은 창, 없으면 가장 가까운 미래창을 선택한다.
19~07 연속 야간의 회복창은06~15, 출근전창은15~19. 날짜 배정 경계12:30과는 다르다. PRE_SHIFT_NAP 창이라는 이름이 짧은 낮잠 자동기록을 보장하지 않음. 수신기는 종류별 최소시간을 달리 하지 않고5시간 기준을 쓰므로15~19 창 안의 짧은 잠은 앱 제시 대상이 못 된다. 후보가 창 끝을 넘어 지속되면 후보 시작 기준9시간까지 이어질 수 있다.
SleepDetectionScheduler: 한국어+사용자 잠금해제+condition_tab_enabled일 때 동작. 대략20분마다 setExactAndAllowWhileIdle로 한 번씩 조회; 실제 OS 전달 주기는 지연될 수 있으므로 수면 측정 오차가 반드시±20분 이내라고 보장할 수 없음.
화면꺼짐 첫 샘플을 저장하고 다음 꺼짐 샘플에서 첫 시각으로 소급해 AUTO_DETECTED/PENDING 생성. 이 사이의 모든 화면 사용을 연속 관찰하는 센서가 아니다. 창에 이미 시작한 기록이 있거나 첫 꺼짐을 덮는 기록이 있으면 중복 생성 억제. 진행 중 MANUAL 있으면 자동 처리 skip.
화면 켜짐을 관측하면5시간 미만은 삭제, 이상은 종료 후 확인대기. 충전 상태로 신뢰도 MEDIUM/HIGH 계산. 후보 시작9시간에 도달하면 종료를9시간으로 잘라 LOW로 남김. Dart provider도 만료된 미종료 후보를 정리한다. 사용자 확인 전에는 통계/브리핑의 확정수면으로 쓰지 않는다.
같은 취침 시(hour) 자동후보를2회 거절하면 최근 거절로부터60일간 그 시간대 생성 억제. 근무명별 의미 학습이 아니며 시간 단위 카운터다.

11. 합계·평균·회복 안내는 서로 다른 질문
A. 달력/근무 유형 평균
확정 기록→슬롯→주 수면+모든 낮잠. 근무별 평균은 오늘 제외 최근30일, 데이터 있는 날만 분모, 같은 유형3일 이상이면 표시. 미입력 유형 제외, 주 수면·낮잠 각각 평균 후 반올림. 기록 없음=0시간 아님.
B. 현재 브리핑
근무 중→3시간 내 출근→퇴근16시간 이내 회복중→휴무→오늘 늦은 근무→미확정 순서. current는 오늘/어제 근무, next는 최대14일 앞. 시각 미입력 근무가 사이에 있으면 관계를 끊는다.
출근전/근무중/오늘대기: 지금 기준 지난24시간 확정·종료 수면의 구간 합집합. 겹친 시간을 이중계산하지 않고 창 밖은 잘라낸다. 출근전 수면만 따로7시간과 비교하지 않는다.
회복중: 보정퇴근~지금 합집합. 휴무/미확정: 어제 귀속일 슬롯 합. 최근7일 평균: 오늘 제외 기록있는 날3일 이상. 개인 비교: 어제/그제의 최근 기록일을 그 이전30일 같은 근무유형 평균과 비교,1시간 이상 부족 시 보조 안내. 개인비교가 기본 상태 등급을 올리지는 않음.
사실 최대6개, 추천행동 최대3개. topic/ID 중복 제거 후 우선순위. 통근안전·수면확보·야간전 낮잠·카페인·식사·누적근무·기록요청 등. 한계는 최근2주 기록없음,7일 표본부족,출퇴근 미입력,미확정후보 건수로 별도 표시.
진행 중 수면은 아직 확정 길이가 없으므로 완료된 합계에 안 넣는다. sleepingNow 판정은 source/status를 제한하지 않아 자동 pending 진행 중도 '수면 중' 메시지에 영향.
C. 기본 상태 ConditionRuleEngine
기본 NORMAL/ATTENTION/HIGH_LOAD는 근무표+출퇴근시각+OT로 결정하며 실제 수면량으로 직접 점수를 매기지 않는다. 11시간 미만 회복,개인주간기준선보다 근무증가,역방향패턴,야간3일+,연속근무7일+가 attention 신호.2개 이상이면 high. 야간4일+,연속근무10일+,심한 주간증가 또는 장시간연속 후 부족한 휴식은 단독 high 가능.
주간증가: 기준선 대비15%이상 및6시간이상 증가→주의,25% 및12시간이상→높음. 규칙패턴은 주기평균×7, 불규칙은 이전60일 중 알려진21일 이상 기준.12시간 근무 하루만으로 자동 high가 되지 않음. 48/60h 절대값은 배경 부하 설명과 현행 상대증가 판정을 구분.
이것은 앱의 참고용 규칙 판정이며 의학적 진단·개인의 안전 보증이 아니다. 번역에서도 건강상태 '측정/진단'으로 강화 금지.
D. 남아 있는 과거 함수
sleep_history.dart는56일 이력, 퇴근후16h 검색+같은 귀속일+근무중/야간전 수면의 합 등을 사용. sleep_stats.dart는3h 기준의 첫 회복잠을 고르는 별도 함수. lib 검색상 이 함수들은 현행 provider에서 호출되지 않으며 테스트/과거 개발 코드 성격이다. 현재 UI 평균이 '3시간 이상 잠만 센다'고 설명하면 잘못이다.

12. 발견한 후속 검토 항목(이번 미수정)
SL-01:12:30 실제 경계와13시 주석 차이. 정책 변경보다 문서 정합성 먼저. 경계 근처 늦은 회복수면의 사용자 의도 확인 필요.
SL-02:자동추정5h/위젯자동확정2h,위젯9h cap 경로 차이. 도움말의 '항상 맞아요 확인'도 위젯 기상 확정을 포함하도록 설명.
SL-03:slot2h/relation3h 이중 기준. 죽은 코드/외부 호출 여부 구분한 후 정리, 이번 임의 통일 안 함.
SL-04:최근24h 합집합과 달력/평균의 단순합이 다름. legacy/native/복원된 겹친 확정기록은 달력평균에 중복분이 들어갈 수 있다. 정상 UI 중복방지 검사 PASS와 DB 전 경로 무중복 보장은 다름.
SL-05:global DST/여행. Dart analyzer는 현지 시각 필드로 근무를 생성하나 native SleepScheduleResolver는 dayStartMillis+minutes로 근무를 생성(245행 전후). DST 전환일에 같은 근무가 다르게 계산될 정적 근거. sleep_day_slots의 전일/다음일도 Duration(days:1) 연산이 남음. offset 없는 수면 DB는 여행/DST 중복시각을 구별하지 못함. 독일/영국/미국 등의 전환일을 실제 timezone으로 재현해야 함. 글로벌 출시 차단 후보이지 이번 실기기 재현 PASS/FAIL로 기록하지 않음.
SL-06:낮잠3개 이상은 합계에 있지만 첫2개만 표시해 숨은 기록 수정 접근성이 부족할 수 있음.
SL-07:빈 야간 주수면 칸의22~06 기본값은 해당 근무와 겹쳐 저장 후 낮잠으로 바뀔 수 있음. 미래시각은 저장 불가여서 기본값부터 수정해야 하는 날도 있음.
SL-08:1분 수동 입력 UI valid/notifier 무저장, 같은 길이 후보 tie-break, 오래된 겹침 탐색 범위(start-2일) 등 경계는 별도 개선 후보.

검증: 기존 관련13파일144검사 PASS. 추가17경계 사례는 별도 로그/JSON 참조. 호스트 검증이며 잠금/제조사/DST 실기기 PASS가 아님. 앱 코드 변경/빌드/release/배포 없음.

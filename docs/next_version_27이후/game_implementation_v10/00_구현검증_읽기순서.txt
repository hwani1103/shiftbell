현행 포탈 규칙
- 단방향 IN → OUT. IN을 한 이동의 끝점으로 선택했을 때만 발동.
- IN을 이동 중 그냥 통과하면 발동하지 않는다. 선을 쪼개 IN에 멈추는 것은 의도적인 포탈 활성화이므로 일반 직선 분할과 다르다.
- 출구로 즉시 이동. 추가 이동 횟수/시간 없음. 다음 선택은 OUT에서 시작한다.
- 실제로 지나가는 모든 칸은 동일한 속도(기본재생1.5배), 긴 이동은 더 오래 걸린다.
- 전이 순간 IN/OUT 양쪽 위치에서 다른 공과 만나면 충돌. 둘 사이의 공간에는 움직이는 선분이나 충돌이 생기지 않는다.
- IN에서 충돌한 공은 입구에 표시하고 전이 효과를 실행하지 않는다. 세 공이 같은 시각 IN/OUT 양쪽에서 접촉하는 경우도 입구의 실패 위치를 우선 표시한다. OUT에서 충돌하면 OUT에 표시한다.
- 포탈은 Goal·시작점·스위치·문·다른 포탈과 겹치지 않는다. 현재 레벨마다1쌍. 모델/파서는 최대2쌍으로 제한.
- 이번 포탈은 다회용(∞)만 채택. 1회용을 닫힌 뒤 일반 타일로 처리하면 다른 공의 선점 시각에 따라 이미 작성한 다음 경로의 기준 위치가 바뀐다. 현행 정적 경로 UI의 예측성과 설명 부담 때문에 이번에는 제외. 1회용 상태를 넣은 척하거나 단순히 장식으로 닫지는 않는다.

레벨링
51~53: 2공, 포탈의 끝점 선택/출구 타이밍 학습.51은 의도적으로 쉬운 새 장치 입문.
54~59: 3공. 최단 조합으로 해결 불가, 최소2칸 이상의 총 우회 필요. 포탈을 쓸 수 있어도 포기해야 하는 공, 포탈을 쓸 공을 바꿔도 되는 대안, 출구 교차를 혼합.
60~62: 3공+포탈+협동 문1개.
63~65: 4공+포탈+협동 문1개.
66~70: 4공+포탈+협동 문2개. 각 문은 정답에서 반드시 방문되고 다른 공의 스위치가 필요하며, 문을 하나 빼면 추가 정답이 생김.
모든 새 레벨의 모든 안전한 해답이 실제 포탈을 사용함. 일부 공만 장식적으로 쉬운 길에 두지 않도록 단독 최단 이동>=3, 시작-Goal 맨해튼>=3, 후반 모든 공의 충돌 선택 참여를 확인.
55: A 또는 C가 포탈을 맡는 서로 다른 해법이 있다.
56: A도 포탈 경로를 만들 수 있지만 안전한 정답에서는 B/C가 사용한다.
63: A 또는 D가 포탈을 맡는 대안이 있다.
68: 네 공 모두 포탈/일반 경로를 선택할 수 있지만, 안전한 포탈 사용자 조합은 A/D 또는 A/B/D.
점수는 후보 선별 휴리스틱이며 사람의 체감 난이도를 수치로 증명한 것은 아니다. 후반은 높은 난이도 대역을 유지하되 레벨별 전략을 바꿔 배치한다.

구조
- PortalPair/afterEndpoint는 논리 모델. 파서/유효성 검사/최소 명령 BFS/편집기/Solver/생성기가 같은 끝점 의미를 사용.
- MotionCompiler는 전이 전후의 양의 시간 선분과 PortalEvent만 출력. 순간이동 구간에 가짜 이동/가속/0시간 선분을 만들지 않음.
- 충돌 엔진은 기존 Rational 절대 시간 선분 판정. 문은 기존 시각 이벤트 계약을 유지.
- PortalVisual은 Canvas의 링/IN·OUT/∞ 표시 및 전이 펄스만 담당. 이미지나 게임 엔진 패키지 추가 없음.
- 경로는 입구에서 끊어 출구에서 다시 시작. 공 회전은 실제 이동 선분에만 적용.
- ReplayCursor는 정수 마이크로초를 누적하고 표시 좌표를 계산. 프레임별 double 덧셈으로 동일 경과 시간의 Goal/전이 표시가 한 프레임 달라지는 경계 문제 수정.
- 첫 포탈 도움말 확인 여부만 기존 저장에 선택 필드로 추가. 기본/문/포탈 도움말은 각각 최초 한 번. 메뉴로 재열람 가능.
- 실행 중 메뉴가 일시정지시킨 뒤 '다시 시작'이 무시되던 조건도 수정.

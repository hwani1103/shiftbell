날짜 이동과 실제 경과시간 분리
- 달력 이전/다음날: 현지 연월일 필드를 이동. Duration(days:1)은24시간이므로 날짜 이동에 사용하지 않음.
- 근무 시작/종료: 현지 시계 필드로 생성. Android도 자정+분 계산 제거.
- 수면 길이/9시간 자동 후보 상한: 실제 instant 차이 사용.
- 새 수면 시각: ISO8601 오프셋 저장. 기존 오프셋 없는 local 기록은 계속 읽음.
- 조회와 중복검사: 문자열 순서 대신 시각 정규화 비교.
- 검증 중: 수동 입력의 존재하지 않는 시각/두 번 존재하는 시각 선택, 기기 시간대 변경, native/Dart 경계 일치.
공식 근거(2026-10-14 확인)
https://api.dart.dev/dart-core/DateTime/add.html
https://api.dart.dev/dart-core/DateTime/parse.html
https://developer.android.com/reference/java/util/Calendar

근무 시각 정책 보완: Dart DateTime 생성자의 암묵적 중복 시각 선택과 Android Calendar 선택이 달라질 수 있어 양쪽 모두 기존 알람 정책을 명시적으로 재사용한다. 반복되는 근무 시각은 두 번째, 사라진 근무 시각은 전환 폭만큼 앞으로 이동한다. 이는 반복 근무표의 기본 해석이며 실제 수면 입력은 반복 시각을 직접 선택하고 사라진 시각은 입력을 거부한다. 한국의 일반 날짜 결과는 변하지 않는다.

오프셋 없는 과거 기록은 현재 기기 시간대로 해석하는 기존 계약을 유지하되, 반복되는 시각의 선택은 Native와 Dart 모두 두 번째로 통일했다. 과거 실제 첫 번째/두 번째를 복원했다고 주장하지 않는다. 새 기록은 오프셋으로 구분하므로 이 모호함이 없다.

[실기기 검증과 발견한 결함]
- SM-X400/API36에서 한국 및 출시8개국/아일랜드의 실제 시스템 시간대로 모델 검증. 각 시간대43시나리오·192조합×5언어 PASS. NY/Berlin/London/Dublin은 봄7h·가을9h 수면, 반복2/누락0시각, 현지 날짜 이동, 근무 종료시각과 legacy DB 조회를 포함.
- SQLite julianday(legacy,'utc')는 뉴욕 반복 시각을 앱과 다르게 해석함을 실제 기기에서 재현. 과거 오프셋 없는 기록의 SQL 변환에 의존하지 않도록 Dart는 legacy 포함 조회 후 명시 파싱/필터, native는 SleepRecordQueries의 같은 파서로 비교. 실패 보고서는 before_legacy_fix로 보존.
- 실제 일반 앱 UI: 2025-11-02 뉴욕 01:30 첫 번째(UTC-04:00)→두 번째(UTC-05:00) 입력, 1시간 표시·저장 확인.
- 실제 일반 앱 UI: 2026-03-08 뉴욕 02:30 입력 거부와 기존 입력 유지 확인. 오류 SnackBar가 바텀시트 뒤에 가려지는 결함 발견, 최상단 대화상자로 수정하여 후속 후보 재검증 진행.
- 새 오프셋 기록의 instant는 여행/이주에도 보존하지만, 표시와 근무 귀속은 현재 기기 시간대로 재계산된다. 한국에서 만든 합성 기록을 뉴욕으로 바꾸자 근무별 평균도 달라짐을 관측. 과거 근무의 원래 시간대를 고정하는 여행자 기능은 이번에 제공하지 않는다. 도움말에 현재 기기 시간대 기준 명시.
- 시간대 시험 뒤 Asia/Seoul/자동시간대1 복구. 충전 중 화면 유지15는 유지.

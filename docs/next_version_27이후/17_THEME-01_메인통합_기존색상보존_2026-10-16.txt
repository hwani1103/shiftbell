THEME-01 — 메인 통합, 기존 선택/근무색 보존 (2026-10-16)

요청
- 사용자는 메인 다크의 보이는 선택을 없애고 메인 화이트를 '메인'으로 통합하되, 기존 사용자에게 화이트/다크를 고정하여 업데이트 전 밝기를 보존하는 것을 최우선으로 지정했다.
- 적용 브랜치 dev, 이번 추가 작업 APK/웹 빌드·설치 없음. 초기 UI60 수정 APK와 이번 소스 변경을 구분한다.

저장 계약
- calendar_theme_id는 mainWhite로 통합. mainDark 파싱 enum은 과거 자료 호환용으로 남긴다.
- calendar_main_before_merge: 최초 원래 mainWhite/mainDark 선택.
- app_ui_preview_theme: originalWhite/originalDark 고정. 시간 자동5색상과 별도의 고정 선택이며 설정에서 화이트/다크로 보인다.
- calendar_main_merge_v1: 마지막 쓰기로 완료 표시. 완료 후 사용자의 자동/다른 고정 선택을 다음 실행에서 덮어쓰지 않는다.
- 저장 성공 여부를 매 쓰기마다 확인. 중단되면 원래 선택 기록으로 이어서 실행. 저장 오류 때도 앱 색상 provider는 확인된 원래 메인의 고정색을 반환하도록 보완.
- mainDark가 남아 있는 옛 백업은 완료 표시가 있어도 다시 다크로 이관. 백업 복구 정책은 이3개 설정과 색상 선택을 타입 검사하며 일반 preference 백업/복원 범위에 포함.
- 원래 백업에 새 표시가 없으면 일반 복구의 미존재 preference 제거 정책에 따라 지워져 다음 초기 로드에서 이관한다. 실제 백업 덮어쓰기/기기 재설치로 검증하지 않았으므로 호스트 설정 이관 검사와 구분한다.
- 기존 앱에서 명시 theme ID가 없지만 permissions_requested/welcome_popup_shown이 true이면 해당 로케일의 기존 기본값을 사용. 한국어 mainWhite는 고정화이트, 해외 기본 Periwinkle은 기존 자동/선택 유지.
- 완전 신규 설치와 메인 외 테마는 색상 선택을 강제하지 않는다.
- 실제 main 초기화는 CalendarThemeNotifier.loadInitial을 기다린 다음 앱을 시작하며 여기서 로케일 기본값을 전달. 화면색상 provider에서도 이관을 확인하여 옛 선택을 놓치지 않음.

데이터 보존
- DB 스키마/근무 데이터 변경 없음. 메인 색상 조회에서 saved shift_colors와 customShiftColors를 유지. 메인다크→메인 ID 변경 때문에 새로운 기본색으로 덮어쓰지 않는다.
- 테마 선택기에서 이미 선택된 메인을 적용해도 기존 색상 유지. 다른 테마를 새로 선택하는 기존 사용자 동작은 기본색 적용 규칙을 유지.
- 전체근무표 및 미니게임 세션의 코드/백업키 보존.

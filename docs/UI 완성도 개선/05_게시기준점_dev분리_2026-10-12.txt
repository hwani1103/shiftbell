브랜치 운영
- dev는 다음 UI 완성도 개선을 이어갈 개발 브랜치로 계속 사용한다. 브랜치를 이름 변경하거나 지울 필요 없음.
- v1.0.24+27 태그는 게시 기준 커밋에 고정한다. dev가 나중에 앞으로 진행해도 이 기준점은 바뀌지 않는다. 이미 게시한 태그는 옮기거나 덮어쓰지 않는다.
- 이번 main은 변경하지 않는다. origin/main에는 별도 운영 대시보드/GA4 커밋(최신4d87bca)이 있으므로 dev로 강제 덮어쓰거나 이름만 바꾸지 않는다.
- main을 앞으로 배포 기준 브랜치로 통일하려면 최신 main 운영 이력을 보존한 정상 병합/검토를 별도 작업으로 수행한다. 이번 게시 앱 기준은 위 태그가 명확한 기준점이다.
- 게시 버전 긴급 수정은 해당 태그에서 hotfix 브랜치를 만들고, 반영된 수정은 다음 dev에도 합친다.
- 다음 UI 업데이트가 출시될 때 실제 버전/code에 맞춘 새로운 태그를 만든다. 앱 flavor(prod/dev)와 Git 브랜치(main/dev)는 별개다. 지금 버전 번호나 flavor 설정은 변경하지 않았다.

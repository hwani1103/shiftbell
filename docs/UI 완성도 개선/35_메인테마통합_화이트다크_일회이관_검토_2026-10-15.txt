메인 화이트/다크 통합 및 기존 선택의 고정색 일회 이관 — UI35
작성: 2026-10-15
상태: 가능성/영향 조사 완료. 제품 코드·팔레트·저장값 변경 없음. 구현/실기기 PASS 문서가 아님.

사용자 구상
- 시간별5색 중 앞4개는 현재 유지, 마지막 밤 팔레트는 검정으로 변경.
- 흰색은 별도 고정 선택으로 제공.5색 모두 현재처럼 고정 선택 가능. 자동 선택도 유지하는 구상으로 검토.
- 달력의 메인 화이트/메인 다크를 메인 테마1개로 통합. 이후 배경 선택은 설정의 공통 색상 선택에서 변경.
- 업데이트 직후 기존 메인 화이트 사용자는 흰색 고정, 메인 다크 사용자는 검정 고정으로 바로 시작하고 싶다는 요청.
- 이번 요청은 가능성 조사로 수행하며 실제 변경을 선행하지 않음.

현재 코드 근거
1. lib/providers/calendar_theme_provider.dart
   SharedPreferences calendar_theme_id에 enum.name 문자열을 저장. mainWhite/mainDark를 각각 식별할 수 있음.
   main.dart의 _initializeApp가 앱 트리 구성 전 loadInitial로 달력 테마를 읽음.
2. lib/providers/app_ui_theme_preview_provider.dart
   app_ui_preview_theme에 dawn/morning/daytime/evening/night/originalWhite/automatic 저장.
   키 없음과 명시적 automatic은 서로 구분할 수 있으나 현재 provider의 최종 표현은 모두 자동(null)으로 통합됨. 이관은 raw 저장값을 읽어 구분해야 함.
3. lib/theme/app_ui_time_palettes.dart 및 widgets/app_ui_theme_preview.dart
   시간별5색과 각각의 고정 선택은 이미 구현됨. originalWhite도 한국어 전용 고정 선택으로 이미 존재함.
   현재 night는 #172434 네이비이므로 사용자 구상의 검정은 아직 적용되지 않음.
4. lib/models/calendar_theme.dart
   mainWhite와 mainDark는 단순 배경만 다른 것이 아님. assignShiftColorsForTheme가 각각 kMainLightPalette/kMainDarkPalette를 사용함.
   예: 첫 기본 근무색 #4771D1 / #7FA8C9. customShiftColors가 없는 근무는 디자인 기본값을 따름.
5. lib/services/backup_policy.dart
   calendar_theme_id는 백업/자료형 검증 대상. app_ui_preview_theme는 백업 제외 목록에는 없지만 자료형 맵에는 아직 등록되지 않았음.
   기존 백업의 구 테마값 및 이관 완료 표식의 복원 정책까지 함께 확인해야 함.

권장 이관 규칙
- 메인 화이트 → 화면에 보이는 달력 디자인은 메인1개 + 공통 originalWhite 고정.
- 메인 다크 → 화면에 보이는 달력 디자인은 메인1개 + 공통 night(새 검정) 고정.
- 자동 시간 선택으로 두면 업데이트한 시각에 따라 색이 바뀌므로 기존 명시적 화이트/다크를 보존하려면 고정 선택으로 기록해야 함.
- 이관은 설치별 최초1회만 수행. 이후 사용자가 바꾼 자동/고정 선택을 앱 실행 때마다 옛 달력 선택으로 덮어쓰지 않음.
- 이미 새 공통 색상 선택을 명시적으로 저장한 dev 사용자는 그 선택을 우선 보존하는 정책을 권장. automatic도 명시적 선택으로 취급. 이것은 구현 전 확정할 우선순위이며 사용자의 기존 화이트/다크 매핑 요청을 바꿨다고 간주하지 않음.
- raw 구 테마를 읽기 전에 두 값을 메인으로 정규화하면 어느 쪽이었는지 사라짐. 순서는 반드시 기존값 읽기→목표 고정색 결정/저장→통합 디자인 처리→이관 완료 기록.
- 저장 실패/중간 종료 시 완료로 표시하지 않고 재시도할 수 있도록 설계. 초기화 단계에서 색상 이관을 마쳐 첫 실제 화면부터 해당 팔레트를 읽게 함.
- 구 mainWhite/mainDark 식별자는 즉시 삭제/이름 변경하지 말고 구 저장값·구 백업의 호환 입력으로 수용. 사용자에게 보이는 디자인 선택 목록만1개로 통합할 수 있음. enum 저장을 index로 바꾸지 않음.
- calendar_theme_id가 없던 기존 한국어 기본 화이트 설치와 완전 신규 설치는 구분. 기존 구성 자료/기존 설치 표식을 근거로 이관 대상을 판단하고 신규 설치의 기본 자동/선택 정책을 별도로 유지.
- 다른 달력 디자인 사용자의 팔레트 및 선택을 화이트/검정으로 일괄 덮어쓰지 않음.

함께 보존할 계약/미결정 영향
- 기존 두 메인의 근무 기본색이 달라, 디자인 ID만 합치면 사용자 지정이 없던 근무색이 바뀔 수 있음. 기존 화면의 유효 근무색 유지 방식과 새 통합 메인의 기본 팔레트 정책을 구현 전에 결정해야 함. 배경 이관이라는 이유로 근무표/사용자 지정색을 임의 재작성하지 않음.
- 검정은 배경 한 값만 바꾸지 않고 AppUiPalette의 표면/텍스트/보조 텍스트/버튼/테두리/선택/비활성/오류 역할 및 Material brightness를 함께 맞춤. 앞4개 팔레트는 유지.
- 자동 시간 구간은 현재05~08/08~11/11~17/17~21/21~05를 그대로 두고 마지막 슬롯의 팔레트만 바꾸는 구상. 흰색은 자동 슬롯에 추가하지 않음.
- 시스템 스플래시 #EEF6FD 고정 계약 유지. 런타임 검정과 연결하지 않음.
- UI34의 달력 프레임 글자 치수 보존을 유지. 통합으로 셀 크기/메모 축소가 다시 움직이지 않도록 확인.
- 외국어 목록에도 mainWhite/mainDark가 있어 한글판 통합과 외국어 디자인/미리보기/공개 웹 영향은 별도 확인. 기존 전체 화면이 공통 팔레트로 중앙화되었다고 확대 표현하지 않음.
- 새 팔레트/이관 표식의 백업 자료형 등록, 표식의 기기 로컬 여부, 구 백업 복원 시 재이관/새 사용자 선택 우선순위를 함께 정함.

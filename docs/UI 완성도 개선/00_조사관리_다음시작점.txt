현재 결론
- 제품 코드는 수정하지 않고 정적 전수 목록을 작성했다. 실제 기기 진입·레이아웃·권한/알람 PASS는 이번 작업에서 미실시.
- 독립 페이지 수가 아니라 관리 ID 184개다. 공통창은 여러 사용처를 연결하고 중첩 선택·오류창을 별도로 기록했다.
- 알람 고정시각 선택은 AlarmTimePicker/TappableNumberPicker 조작 유지가 기준. 온보딩과 설정에 별도 AlertDialog 부모/중복 경고가 있으므로 양쪽 사용처를 확인한다.
- 일정 생성/수정은 showGeneralDialog 기반 하단창(220ms slide), 삭제는 동일 창 하단의 인라인 확인이다. showModalBottomSheet 목록만 검색하면 빠지는 범위다.
- 복원은 자동발견/온보딩 수동 push/설정 덮어쓰기/중단재개로 나뉜다. 복원 진행 중 Back 차단·알람 종료 대기·재시작을 보존한다.
- native 잠금 알람/다른 앱 오버레이/앱 안 축소아이콘·펼침/플립커버/알림 조작/홈 위젯을 별도 ID로 관리한다. 앱 안 Back은 펼침을 접는 동작이며 해제와 다르다.
- UMP는 SDK 폼이다. 앱 진입·안내·복귀와 SDK 소유 표면을 구분했고, AdMob 메시지 편집 범위는 이번에 외부 공식 문서나 콘솔로 확인하지 않았다.
- 시스템 권한/설정·SAF 파일·공유/진단 chooser·Play/브라우저·PWA/런처는 외부 소유 UI다. 앱 연결부와 실제 허용상태/복귀만 정비할 수 있다.
- 한국어 전용 일정/컨디션/앱 공유와 공개 다국어 웹 뷰어를 구분한다. 현재 main 생성에서 EnglishConditionTab은 쓰이지 않는다.
- SplashScreen/AlarmTestScreen/EvidenceLibrarySection은 활성 생성 사용처를 찾지 못한 잔존 코드다. CalendarThemeLabScreen은 테마 선택 IgnorePointer 미리보기로 표시되며 샘플 팝업은 현재 비도달이다.

설계 확정 전 잔여
1. 사용자 원장 확인. 누락/범위에 대한 판단을 새 원장 후속 기록으로 연결한다.
2. 공통 페이지/중앙 확인창/선택형/긴 편집창 유형, 폭·높이·스크롤·닫기/X·Back·바깥탭·스와이프·미저장 입력 정책을 확정한다.
3. 세이지 기본 형태·여백·카드의 요소별 시안을 확인한다. 색상3종은 공통 구조의 역할 토큰 변형 검토안이며 제공여부·기본값 확정 전이다.
4. 앱/달력/근무 의미 색상의 우선순위, 사용자 선택 저장, 시스템 글자 정책, 날짜·년월·기간 선택 방식을 결정한다.
5. 대표 팝업 조합으로 공통 요소를 확인한 뒤 온보딩부터 적용한다. 배경5단계/다음알람 요약/애니메이션은 뒤 단계다.

근무 변경 전후/날짜별 OT — 배치 검토만 (UI62, 2026-10-16)

상태
- 바탕화면 달력테마작업.txt의 두 검토 항목. 이번에는 제품 코드/DB/메모 개수/표시 옵션을 추가하지 않았다.
- 현행 근무 변경: CalendarTab의 패턴상 근무와 실제 근무 비교, ContractCalendarCell.isModified의 메인 근무칩 왼쪽 띠. 변경 전후 정보는 상세에서 확인 가능.
- 현행 OT: DateOvertime.minutes는 분 단위 값이고 이미 월 범위 provider를 읽는다. 새 DB 열은 필요하지 않지만, 하루의 값/날짜 키를 셀 입력에 연결하고 월 넘김의 조회 범위를 검증해야 한다.
- UI59/61은 공휴일·음력 한 슬롯과 메모3줄을 예약한다. 메모 한 줄을 빼거나 메모 수에 따라 전체 글자 크기를 줄이는 방식은 우선안에서 제외.

우선 검토안 A — 날짜 행을 작은 요약 행으로 사용
- 메인/심플라인/소프트카드: 날짜를 왼쪽으로 배치하고 날짜 행 오른쪽에 OT 8:30를 별도 작은 정보 텍스트로 표시. 근무명 칩/공휴일·음력/메모3줄의 세로 슬롯은 유지한다.
- 숫자8.5 대신 시:분의 기간 표기. OT 접두어와 안내/접근성 읽기 '초과근무8시간30분'으로 오전8시30분과 구분.0분은 미표시,30분은 OT 0:30,8시간은 OT 8:00처럼 규칙 일관성 유지가 가능하다. 실제 문구/최대값은 사용자 채택 후 결정.
- 장점: 메모가3개인 날짜에도 정보를 늘릴 수 있고 새 줄이 필요 없다. 이번 배치에서 날짜 영역은 가로를 전부 쓰지만 날짜 숫자 자체는 짧아 재배치 여지가 있다.
- 제한: 오늘의 테두리/배지와 OT를 동시에 넣으면 좁은 화면에서 가로 폭이 부족할 수 있다. 실제 폰트 측정으로 최소 폭을 정하고, 글자를 무한 축소하지 않는다. 현재 배치에서는 메인 날짜가 중앙이므로 정렬 변화의 시각 승인이 필요하다.
- 아래 수식으로 채택 여부를 판단할 수 있다: 날짜/오늘 배지 실측 폭 + 공통 간격 + OT 문자열 실측 폭 <= 날짜 슬롯 안전 폭. 세로는 현재 날짜 행 높이를 넘지 않아야 한다.

우선 검토안 B — 근무칩 내부에 변경 관계 표시
- 메인/심플라인/소프트카드에서 변경된 날만 기존 근무칩에 '주→야' 또는 실제 짧은 이름 '주간→야간'을 표시하는 후보. 현재 근무의 배경색/구분선은 유지하고 원래 근무는 약한 보조 역할로 표시.
- 메모3줄과 OT 날짜 행을 그대로 유지할 수 있다. 추가 세로 슬롯 없이 두 검토 항목을 함께 담는 방향이다.
- 현재 80% 글자 점유율과 좌우5% 안전 영역으로 실제 너비를 측정해야 한다. 임의 글자 수 분기/근무명 일괄 잘라내기를 하지 않는다.
- '주간1/주간2'처럼 첫 글자가 같은 경우가 있어 자동 첫 글자 약칭만으로는 정보가 틀릴 수 있다. 명확한 약칭이 있는 패턴에서만 관계 표기를 쓰고, 긴 사용자 지정 이름은 현재 근무명+변경 기호를 유지하며 상세에서 전후 전체 이름을 확인하는 쪽이 안전하다.
- 전후 전체 이름을 어떤 길이에서도 달력 한 칸에 항상 보여주는 목표는 기존 가독성과 메모3줄을 동시에 보장하기 어렵다. 선택형 '변경 보기' 모드로 칩 두 줄을 허용하는 별도 후보도 있지만 화면 밀도가 크게 바뀌므로 후순위.

테마별 적용 가능성(아직 구현/실기기 검증 아님)
- 메인/심플라인/소프트카드: 날짜 행 OT와 근무칩 관계 표시의 우선 시제품 대상. 여백 총량보다 해당 슬롯 실측 폭과 오늘 표시가 관건.
- 다이어리: 상단 날짜+근무칩이 이미30:70으로 묶여 있어 날짜 행 OT를 그대로 복제하기 어렵다. 별도 여유 행이나 선택형 정보 모드가 필요.
- 다크그리드: 날짜 오른쪽에 음력/공휴일이 이미 있으므로 OT를 그 자리로 넣으면 정보가 겹친다. 기존 두 정보의 행 재설계가 필요.
- 이벤트캘린더: 날짜가 독립된 행이므로 OT 후보 가능하나3개 메모 pill까지 있는 낮은 셀에서는 높이 여유가 적다. 메모 영역에서 공간을 빼지 않는 조건으로 검증.
- 컬러뱃지: 날짜 행 OT 후보는 가능하나 근무 변경 전후 이름은 원형 이니셜 디자인과 맞지 않는다. 변경 기호/상세 유지가 적절.
- 미니멀언더라인/매거진: 날짜 행 OT는 여지가 있으나 근무를 색선과 범례로 표현하므로 전후 이름을 셀마다 넣으면 테마 성격이 크게 바뀐다.
- Periwinkle/Soft Mosaic: 날짜 행 OT 가능성을 검토할 수 있으나 해외 긴 문자열/요일/폰트와 오늘 배지 실측이 필요. 현재 GlobalConceptCalendarCell의 높이 예산을 별도로 점검해야 함.

공통 후속 조건
- 사용자가 켤 수 있는 선택형 표시가 적절. 전체 테마 강제 적용은 하지 않는다.
- 2자리 날짜/오늘/공휴일/음력/긴 근무명/3메모/최대 OT가 동시에 있는 최악 조합, 좁은 화면과 넓고 낮은 화면, 밝은/다크 팔레트를 시제품으로 비교한 뒤 채택.
- OT가 있는 날과 없는 날의 날짜/메모 위치가 흔들리지 않도록 슬롯 자체는 고정한다. 근무 변경·OT 접근성 설명은 짧은 화면 표기와 별개로 전체 내용을 읽도록 설계.
- 단위 형식은 저장 데이터를 바꾸지 않으며, 월합계/상세의 기존 '8시간30분' 표시도 자동으로 변경하지 않는다.
- 이번 권고는 A+B 조합을 메인·심플라인·소프트카드부터 시제품으로 비교하는 것. 실제 적용은 아직 없음.

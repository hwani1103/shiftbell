OT 조건부 표시 / 공휴일·음력·메모 충돌 — UI63 (2026-10-16)

상태
- 사용자 요청에 따라 먼저 통합 dev debug 빌드를 시작. 이 문서는 그동안 수행한 표시 방식 검토이며 제품 코드에 OT 표시를 추가하지 않았다.
- 제약: 현재 근무칩/근무명 가독성, 날짜/빨간날/공휴일, 메모3개 유지. 음력은 우선순위를 낮춰 다른 날짜의 표본 표시로 조정 가능.

검토할 우선순위
1. OT 없음: 기존 공휴일/음력.
2. OT 있음·공휴일 없음: 기존 음력 슬롯에 +8h 30m. OT 표기가 h/m 단위를 포함하므로 8:30보다 기간 의미가 명확하다. '+'가 OT임을 알려주는 공통 안내/접근성 이름은 필요.
3. OT 있음·공휴일 있음·메모0~2개: 공휴일은 원래 자리에 유지, 마지막 빈 메모 슬롯을 OT 전용 표시로 사용. 실제 메모 데이터로 저장하거나 메모 개수에 합산하지 않는다. 사용자 메모의 원래 순서/내용은 보존한다.
4. OT 있음·공휴일 있음·메모3개: 공휴일과 OT가 충돌. 실제 글자 중첩은 권장하지 않는다. 먼저 날짜 주변 여백으로 정보 슬롯을2줄 높이로 늘릴 수 있는지 계산. 불가능한 화면까지 동일하게 보장하지 않으며, 무제한 글자 축소도 채택하지 않는다.
- 음력 표시를 화/목으로 옮긴다는 것은 수요일의 음력 값을 복사하는 것이 아니라 화/목 날짜의 실제 음력을 표본으로 보여준다는 의미여야 한다. 연속 OT/공휴일, 월 경계/음력 초하루 등 표본 후보가 없는 경우의 생략 규칙은 후속 결정.

결론
- 사용자 제안의 우선순위 방식은 기존 날짜행 OT 제안보다 현실적이다.
- 공휴일+OT+3메모 예외를 실제 중첩으로 처리하는 안은 제외 권고. 여유높이를 재분배한 두 줄을 먼저 검토하고, 극소 글자2줄은 최종 가독성 확인 없이 채택하지 않는다.
- 전체 OT UI 및 근무변경 전후 표시는 이번 통합 빌드에 미포함.

추가 비교 — 공휴일 이름 약칭
- 중첩/극소 글자 대신 충돌하는 날만 정해진 짧은 이름을 쓰는 대안: 대체공휴일→대체, 공휴일 약칭은 빨강/OT는 본문 대비색. 전체 공휴일 이름은 날짜 상세에서 유지하는 후보. 임의 글자 자르기 대신 승인된 명칭 매핑이 필요.
- ot_holiday_short_label_review.png의 대체+8h30m는7.7 글자 근사 폭46.5로, 예시 메인 텍스트 안전 폭 약48 안에 들어갈 가능성이 있다. 대체 +8h30m는49.25, 대체 +8h 30m는52.0으로 공통 inset을 고려하면 여유가 부족하다.

- 사용자에게는 공휴일 전체 이름을 약칭으로 바꾸는 trade-off를 제안하는 단계. 이번 빌드 적용 없음.

## 2. 구현 중 Claude가 정한 세부 정책

| 영역 | 선택 | 근거 |
|---|---|---|
| 작업 방식 | T17 통합(G1→G2→G3 병합, 충돌 0) 뒤 G4·G5는 worktree 없이 dev에서 직접 구현, 커밋을 그룹별로 나눔 | G4/G5는 순차 전용이고 다른 그룹 동시 작업이 없음. 빌드 캐시·RAM 절약 |
| 백업에 넣지 않는 설정 | 친구공유 7키(G2 계약), 자동백업 상태 3키, `permissions_requested`, 업데이트 안내 4키, 웹 뷰어 키 | 설치별 의미만 있는 값. 튜토리얼 표시 여부·테마·탭·근로시간 설정은 사용자 설정이라 포함 |
| 백업 alarms | 미래 custom만 포함(#9), snoozed 제외(D5), fixed는 원본에서 재생성 | v4 #9 계획 그대로 |
| 복원 시 백업에 없는 원본 테이블 | 비움(구버전 백업 → `alarm_overrides`·수면 기록 등 빈 상태) | 실행계획 G4 12번 "몰래 남지 않게". 복원 확인 화면에 백업 시각 표시는 기존 유지 |
| 검증 강도 | 형식·자료형·필수 컬럼·근무명(#11/#12)·패턴 범위·템플릿/예외 참조·수면 시각은 거부. 지금 근무 목록에 없는 템플릿 근무명(과거 rename 잔재)은 허용 | 정상 사용자의 오래된 백업을 거부하는 쪽이 더 나쁨. 갱신 엔진이 무시하는 무해한 상태 |
| 근무 일정 없는 백업 | 신규 설치는 기존처럼 안내 후 온보딩, **덮어쓰기는 거부**(지금 데이터 유지) | 빈 백업으로 사용 중 데이터를 통째로 지우는 사고 방지 |
| 중단된 복원 | 자동으로 이어하지 않고 앱 시작 첫 화면에서 "이어서 복원 / 지금 데이터로 계속" 선택 | 실행계획 G4 17번(중단 뒤 사용자 변경을 몰래 덮어쓰지 않음) |
| 복원 중 수면 위젯 버튼 | 입력을 저장하지 않고 "복원 중" 토스트 | 복원 수 초 동안의 드문 입력. pending 저장 구조를 새로 만드는 위험보다 작음 |
| 복원 잠금 알림 문구 | 네이티브 한국어 하드코딩(기존 알람 알림과 같은 방식) | G1 잔여 위험 (5)와 같은 범주 - G5 현지화 판단 대상 |
| 광고 ID(D2) | 실제 ID는 소스에 넣지 않고 빌드 시 주입: 배너 `--dart-define=ADMOB_BANNER_ID`, 앱 ID Gradle 속성 `ADMOB_APP_ID`. 주입 안 한 prod release는 광고 요청 안 함. dev·debug는 항상 테스트 ID, 틴트는 debug만 | D2 "실제 ID는 최종 배포 직전". 테스트 ID가 운영에 나가는 사고(L01) 구조적으로 차단 |
| 개인정보 안내(D3) | 코드 사실 기준으로 ko/en 전면 수정 + "사용 통계(Firebase Analytics)" 섹션 신설. 효력일 2026-09-14로 표기 | D3 "실제 수집 흐름 확정 후 최종 배포 직전" - Console·DebugView 확인(S12) 후 문구와 효력일을 배포일에 맞춰 최종 확인 필요 |

# 다시울림 시간 전역 설정 검토

2026-09-29. 검토만 진행했으며 스누즈 동작·설정·문구는 수정하지 않았다.

## 판단

5 / 10 / 15 / 20 / 30분 선택은 구현 가능하다. 실제 재예약은
`AlarmActionHelper.snooze(context, alarmId, minutes = 5)`에 모여 있어
알람 엔진을 다시 만들 필요는 없다. 다만 설정 UI와 숫자만 바꾸는 작업은 아니다.
난도는 중간이며, 아래의 문구·이력·재부팅·백업 처리까지 함께 구현해야 한다.

## 현재 경로

| 대상 | 코드와 현재 상태 |
| --- | --- |
| 잠금 화면 | `AlarmActivity.snoozeAlarm` → 공통 helper의 기본 5분 사용 |
| 화면 위 알람 | `AlarmOverlayService.snoozeAlarm` → 같은 helper 사용 |
| 제어 알림 | `AlarmActionReceiver.ACTION_SNOOZE_FROM_NOTIFICATION` → 같은 helper 사용 |
| 실제 예약 | helper가 현재 시각에 minutes를 더하고, 중복 검사 → DB 반영 → `AlarmWakeScheduler.scheduleIfCurrent` 실행 |
| 재예약 안내 | `NotificationHelper`의 8889 안내는 새 HH:mm을 받아 표시하므로 가변 시간과 호환 가능 |
| 표시 문구 | `activity_alarm.xml`, `overlay_alarm.xml`의 `+5m`, 한국어/영어 `alarm_snooze_label`, `notif_action_snooze`, 한국어 충돌 안내는 고정 문구 |
| 이력 | `AlarmHistory.dismissLabel`은 `dismissSnoozed5Min` 사용. 이력 화면 충돌 설명에도 5분 고정 문구 존재 |
| 저장 이력 | `alarm_history`에는 선택한 연장 분을 저장하지 않음. helper는 snooze_count에 0을 기록하므로 이 값으로 분 수를 복원할 수 없음 |

## 권장 구현

1. 설정 → 알람음 관리의 무음 아래에 ‘다시울림’ 단일 선택 영역을 추가한다.
   허용값은 5/10/15/20/30으로 제한하며 기존 사용자·설정 누락은 5분으로 처리한다.
2. Kotlin의 공통 설정 접근부를 두고 Flutter 설정 화면과 동기화한다.
   재부팅 후 최초 잠금 해제 전에도 필요한 값이므로 일반 Flutter preferences만
   직접 읽는 구조는 피한다. 현재 앱 DB는 Device Protected Storage에 있으므로
   전용 설정 저장 구조를 그곳에 두거나 같은 저장소의 preferences로 동기화한다.
   저장 실패 시 UI만 새 값으로 바뀌지 않도록 한다.
3. 울림 회차가 시작할 때 연장 시간을 확정하고 잠금 화면·오버레이·제어 알림에
   같은 값을 전달한다. 사용자가 알람이 울리는 도중 설정을 바꾸더라도 이미 표시된
   ‘10분 후’ 버튼이 다른 시간으로 작동하지 않게 한다. 다음 회차부터 새 설정을 쓴다.
4. helper가 확정된 값을 사용해 중복 검사와 실제 예약을 수행하도록 한다.
   이미 예약한 스누즈의 울림 시각은 전역 설정 변경으로 소급 변경하지 않는다.
5. 이력에 당시의 연장 분을 별도로 기록한다(예: nullable `snooze_minutes`).
   과거의 snoozed 이력은 기존 동작에 맞춰 5분으로 표시한다. 이후 설정을 바꿔도
   과거 이력의 표시가 바뀌면 안 된다. 충돌로 연장하지 못한 이력에도 당시 값을 남긴다.
6. Flutter/Kotlin DB 버전·마이그레이션·공통 계약을 함께 갱신한다.
   백업 설정 자료형과 허용값 검사, 이력의 구버전 누락 컬럼, 복원 후 네이티브 설정
   동기화도 포함한다. 오래된 앱이 새로운 컬럼의 백업을 읽는 경우 현재 검증기가
   거부할 수 있으므로 지원 방향을 명시해야 한다.
7. 리소스 문구는 분 수를 받는 형식으로 교체한다. XML의 숫자 TextView에는 ID를
   부여해 실제 설정값을 표시한다. 도움말·개인정보 안내의 ‘5분 연장’ 문구도 점검한다.

## 검증할 핵심 상황

- 5개 시간 × 잠금 화면/오버레이/알림에서 표시값·DB 예약값·실제 재울림 일치.
- 연장 목표 시각의 고정/원터치/다른 스누즈 알람 중복 차단.
- 자정 넘김, 재부팅 및 최초 잠금 해제 전, 예약 실패 후 재시도.
- 울림 도중 설정 변경, 이미 연장된 알람의 시각 보존, 오래된 알림 중복 탭 방지.
- 과거 5분 이력과 새 이력의 표시, 기존 백업 복원 시 기본값, 새 설정 백업·복원.
- 기존 `G1RingRoundTest`, `G1LocaleTest`, `G1WakeSyncTest`에 가변 시간 사례 추가.

## 함께 바꾸면 안 되는 ‘5분’

`AlarmGuardReceiver`의 재확인 주기, 다음 알람 화면의 갱신 주기,
일정 편집의 5분 조절 간격, 수면 감지 경계값은 스누즈 설정과 관계없다.
문자열 검색 결과를 일괄 치환하면 안 된다.

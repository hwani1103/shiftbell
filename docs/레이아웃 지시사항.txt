미니멀언더라인이랑 매거진은 그냥 이대로 고정.

여기까지 수정하고, 미니멀언더라인과 매거진은 제외하고 7가지테마를 개선한다음
(추가수정이있을수도있고 그 방향 또한 기록해)

이번 작업을 진행하면서 내가 최종적으로 괜찮다고 판단하거나 별도 수정 요청 없이 승인한 UI 결과를 기준으로,
**내가 선호하는 달력 UI의 디자인 규칙과 비율을 별도의 문서에 계속 누적해서 기록해.**

단순히 현재 코드의 `fontSize`, `height`, `padding` 같은 절대값만 기록하지 말고, 추후 다른 화면 크기나 Fold / 태블릿 레이아웃에서도 그대로 활용할 수 있도록 **상대적인 비율과 디자인 의도 중심으로 추상화해서 기록해야 한다.**

특히 아래 항목들은 빠짐없이 분석해서 기록해.

- 달력 셀 전체 높이와 너비를 기준으로 각 요소가 차지하는 비율
- 근무명 chip의 높이, 너비, 셀 대비 비율
- 근무명 텍스트의 chip 대비 크기와 디스플레이/셀 대비 상대 크기
- 1~4글자 근무명과 5~6글자 근무명에서 내가 선호하는 글자 크기 차이와 최소 여백
- 근무명 chip 내부의 상하좌우 padding 비율
- 날짜 숫자의 크기와 셀 내 위치
- 요일 텍스트의 크기 및 요일 영역이 차지하는 높이
- 음력, 공휴일, 메모 텍스트의 상대적인 크기 관계
- 공휴일과 메모가 셀 너비 기준 몇 글자 정도까지 자연스럽게 보여야 하는지
- 텍스트가 5~6글자일 때 확보되어야 하는 최소 좌우 여백
- 공휴일, 음력, 메모 사이의 세로 간격
- 메모와 메모 사이의 세로 간격
- 마지막 메모와 셀 하단 경계 사이의 여백
- 날짜 숫자와 그 아래 정보 사이의 간격
- 셀 내부에서 위쪽, 가운데, 아래쪽 정보가 차지하는 전체적인 세로 비율
- 각 테마별로 내가 선호하는 정보 밀도
- 너무 답답하다고 느끼는 상태와 너무 널널하다고 느끼는 상태의 경계
- 내가 "조금 더 크게", "이 정도가 한계", "여백은 유지", "최대한 6글자까지", "상하여백이 약간 타이트할 정도" 등으로 표현한 요구를 실제 구현 결과를 바탕으로 수치화한 기준
- 테마마다 일부 차이가 있더라도 공통적으로 반복되는 내 디자인 취향
- 각 요소 사이의 상대적인 시각적 우선순위

가능하면 각 항목을 다음 두 관점으로 모두 기록해.

1. **달력 셀 내부 기준 비율**
   - 예: 근무명 chip 높이는 셀 높이의 약 몇 %
   - 날짜 텍스트 높이는 셀 높이의 약 몇 %
   - 메모 영역 전체가 셀 높이의 약 몇 % 등

2. **전체 화면/디스플레이 기준 비율**
   - 예: 기본 스마트폰 세로 화면에서 해당 텍스트 크기나 영역이 전체 화면 대비 어느 정도인지
   - 화면이 커졌을 때 단순 비례 확대해야 하는 요소와, 크기를 거의 유지해야 하는 요소를 구분

그리고 반드시 **"현재 코드값"과 "사용자의 선호 규칙"을 분리해서 기록해.**

예를 들어 현재 값이 `fontSize: 11`이라고 해서 그것 자체를 디자인 기준으로 간주하지 말고,

- 왜 이 크기가 승인되었는지
- 셀 크기와 비교했을 때 어느 정도 비율인지
- 4글자일 때 어느 정도의 상하여백이 남는지
- 6글자일 때 어느 정도까지 허용되는지

를 기준으로 선호도를 추출해.

내가 이후에 추가 수정 요청을 하면 기존 기록을 버리지 말고, **새로운 수정 결과를 반영해 선호 규칙을 계속 업데이트해.**
내가 이전에 괜찮다고 했던 값과 이후 수정된 값이 충돌할 경우에는 가장 최근에 승인된 결과를 우선하고, 어떤 기준이 변경되었는지도 기록해.

최종 목적은 이 문서를 나중에 다시 읽었을 때,
새로운 테마를 만들거나 Fold, Fold 내부화면, 대형폰, 태블릿 등의 레이아웃을 처음 튜닝할 때도 **내가 어떤 크기, 비율, 여백, 정보 밀도를 좋아하는지 별도 설명 없이 상당히 근접한 초안을 바로 만들 수 있게 하는 것**이다.

따라서 단순한 변경 로그가 아니라, **사용자의 달력 UI 디자인 선호도 명세서**를 만든다는 관점으로 정리해.

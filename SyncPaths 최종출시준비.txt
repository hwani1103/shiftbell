Sync Paths 최종 출시 준비
작성일: 2026-10-15 (한국 시간)
대상: 독립 게임을 ShiftBell에 통합하여 출시하는 작업

1. 현재 판단
============================================================
게임 구현 및 최근 변경의 자동 검사·dev debug 빌드는 완료했다.
아직 출시 승인 완료 상태는 아니다. 테스트 기능 제거, ShiftBell 통합,
최종 실기기 조작·청음, 출시 AAB 확인이 남아 있다.
이 문서는 게임의 최종 준비를 위한 단일 인계 문서다.
ShiftBell 본체의 기존 출시 준비문서와 권한·알람 검증을 대체하지 않는다.
문서 작성은 출시 빌드·배포 실행 지시가 아니다.

상태 표기: [완료] 구현/명시된 검증 완료 / [대기] 출시 전 필요 / [판단] 사용자 결정 필요

2. 확정된 게임 구성
============================================================
[완료] 이름: Sync Paths. 스플래시 포스터에 게임 이름 포함.
[완료] 앱 시작 시 포스터를 약1.4초 표시한 뒤 레벨 목록으로 이동.
       목록으로 돌아올 때마다 포스터를 다시 보여주지는 않는다.
[완료] LV1~LV100. 목록 위쪽 LV100, 아래쪽 LV1. 신규 사용자는 LV1부터 보인다.
       시작하기/이어하기 버튼 없이 레벨 카드를 눌러 입장한다.
[완료] 게임 진입 시 파란 공 선택. 하단의 선택된 공 버튼을 다시 누르면 선택 해제.
       다른 공 버튼을 누르면 해당 공 선택. 보드 탭은 경로 입력에만 사용.
[완료] 공의 경로가 별까지 완성되면 다음 미완성 공을 자동 선택.
[완료] 되돌리기는 현재 선택된 공의 마지막 경로를 지운다.
       자동 선택 전의 공을 수정하려면 그 공 버튼을 먼저 눌러야 한다.
[완료] 되돌리기 아이콘 버튼과 출발 버튼을 약3:7로 배치.
[완료] 결과 화면: 나가기 왼쪽, 다음 판 오른쪽.
       실패/마지막 판의 재시작 버튼도 오른쪽.
[완료] 게임 화면 LV 카드에 레벨 목록과 같은 단계 색상 적용.
[완료] 열쇠·문 시간은 오른쪽 점으로 표시. 포탈에는 IN/OUT 표시.
[완료] 레벨 재입장은 무조건 초기 배치·빈 경로·파란 공 선택으로 시작.
       이전 재생 상태를 재개하지 않는다. 완료 기록·하트·충전 진행률은 보존.
[완료] 한국어/영어 3단계 힌트: 풀이 방향 → 힌트 → 모든 공의 완성 경로.

하트 규칙
- 레벨별3개. 출발 시1개 소모하며, 성공해도 소모된 하트를 즉시 돌려주지 않는다.
- 0개까지 모두 소모하면 회복 시작. 시작된 회복은3개가 될 때까지 계속된다.
- 앱 전경에서는1분마다1개, 백그라운드/종료 중에는1시간마다1개 회복.
- 회복 중 다시 사용해도 누적 충전 진행률은 초기화하지 않는다.
- 목록이나 다른 레벨에 있어도 회복 중인 레벨들의 시간은 누적된다.
- 다음 하트 내부가 아래부터 차오른다. 동작 줄이기에서는 보간을 생략한다.
- 기기 시각을 사용하는 오프라인 방식이며 서버 기반 부정 조작 방지는 구현하지 않았다.

3. 효과음 최종 상태
============================================================
[완료] 공 선택 / 경로 지정 / 되돌리기 / 출발 / 충돌 실패 / 전체 공 클리어, 총6종.
[완료] 부드러운 순음과 완만한 시작·종료. 배경음 없음. 외부 음원 사용 없음.
       음원은 165~523Hz 중심, 각0.14~0.91초, mono/16bit/22.05kHz.
[완료] 잘못된 입력·선택 해제에는 무음. 자동 선택과 경로 입력음을 겹쳐 내지 않는다.
[완료] 결과음은 결과 진입당1회. 매 프레임 반복 재생하지 않는다.
[완료] 게임 메뉴에서 효과음 켜기/끄기. 설정 저장. 기존 저장 자료는 기본 켜짐.
[완료] 나가기/백그라운드/음소거 시 정지. Activity 종료 시 SoundPool 해제.
[완료] Android 기본 SoundPool 사용. 외부 오디오 라이브러리 추가 없음.
[대기] 실제 휴대폰 스피커와 이어폰에서 음량·음색·지연 확인.
       자동 검사/파형 검사로 실기기 청음 완료를 대신하지 않는다.

주의: 현재 실제 효과음 재생은 독립 Android 호스트에 연결되어 있다.
공유 게임 패키지는 소리 이벤트만 전달한다. ShiftBell 이식 시 다음을 함께 연결한다.
- examples/sync_path_lab/lib/game_audio.dart
- 독립 MainActivity.kt의 sync_paths/effects 채널 및 SoundPool 처리
- android/app/src/main/assets/sync_paths_audio/의6개 WAV
- 세션 onSound/onSilence 콜백
웹은 현재 무음이며 웹 효과음 제공은 이번 완료 범위가 아니다.

4. 출시 전 체크리스트 — 실행 순서
============================================================
[대기] SP-01 테스트 기능 제거
  레벨 잠금 해제 및 무제한 하트 테스트 UI와 사용자 진입 경로를 제거한다.
  버튼만 숨긴 채 테스트 값이 켜져 있는 상태가 남지 않는지 확인한다.
  정상 잠금/해금과 하트 차감으로 실행되는지 확인한다.
  제거 후 영향 범위 검사만 재실행하고 결과를 아래 기록란에 남긴다.

[대기] SP-02 ShiftBell 통합
  게임 진입 메뉴, 게임에서 나가기, Android 뒤로가기의 도착 화면을 확정한다.
  본 앱 실행 시 게임 스플래시가 무조건 뜨지 않도록 게임 진입 범위를 확인한다.
  호스트 오디오 연결·수명주기·게임 컨트롤러 소유권/해제를 연결한다.
  진행 저장 키를 본 앱 데이터와 충돌 없이 정하고 필요하면 이관 방식을 정한다.
  독립 DEV 실험용 ID/라벨/allowedLab 차단 코드를 출시 진입점으로 복사하지 않는다.
  실제 출시 언어에서 게임 한국어/영어 선택·fallback 방식과 글꼴을 확인한다.
  기존 ShiftBell 설정·DB·진행 자료를 초기화하지 않는다.

[대기] SP-03 최종 실기기 회귀
  아래 각 흐름을 정상 하트 모드에서 확인한다.
  □ 첫 실행 → 스플래시 → LV1이 보이는 목록 → 레벨 진입.
  □ 공 선택/선택 해제/다른 공 선택 및 출발 칸 재방문 경로 입력.
  □ 별까지 경로 완성 → 다음 공 자동 선택 → 이전 공 선택 후 되돌리기.
  □ 성공 → 다음 판 / 성공 → 나가기 → 같은 판 재입장.
  □ 실패 → 재시작 / 실패 → 나가기 → 같은 판 재입장.
  □ 재생 중 일시정지·화면 잠금·앱 전환 및 복귀.
  □ 재입장 시 공/경로 초기화, 하트 잔량·회복 진행·클리어 기록 보존.
  □ 하트0개에서 출발 불가, 30초 부분 채움, 60초1개 회복 및 출발 가능.
  □ 다른 레벨 이동/앱 종료·재시작 후 레벨별 하트·진행 저장 유지.
  □ LV100 및 작은 화면에서 메뉴·출발·결과 버튼 접근 가능.
  □ 열쇠·문·포탈 동작과 IN/OUT 가독성.
  □ 효과음6종, 빠른 연속 입력, 음소거 저장, 나가기/잠금 후 소리 정지.
  □ 동작 줄이기 설정에서 게임 진행 가능.
  기기명/OS/빌드 해시/재현 절차/결과를 함께 기록한다.

[대기] SP-04 도움말·힌트 문구 정합성
  자동으로 다음 공이 선택되는 동작과 기존 수동 선택 안내를 맞춘다.
  되돌리기의 대상은 현재 선택된 공이라는 점을 이해할 수 있게 한다.
  마지막 힌트는 공 하나가 아니라 모든 공의 완성 경로라는 점을 확인한다.
  힌트 변경 시 한국어·영어와 루트 정답경로 문서를 함께 갱신한다.
  글꼴은 생성기로 재생성하고 누락 글자 검사를 수행한다.

[판단] SP-05 체감 난이도 수용
  초반 설명 없이 조작이 이해되는지, 중반 장치 규칙이 전달되는지 확인한다.
  후반의 왕복·긴 입력이 재미있는 도전인지 반복 작업인지 플레이로 판단한다.
  특히 LV100은4개 공 각각14회, 총56회 명령을 요구하는 설계다.
  해답 검증과 난이도 지표는 인간의 체감 난이도 검증을 대신하지 않는다.
  변경 없이 출시할 경우에도 현재 난이도 수용 판단을 남긴다.

[대기] SP-06 통합 빌드·출시 산출물 확인
  기본 기능 검증은 dev debug. 명시적인 출시 빌드 요청 전에는 release를 실행하지 않는다.
  본 앱 P0 또는 출시 언어 기능 범위/리소스 구조 변경 시
  tools/check_critical_release.ps1 -Build를 실행한다.
  명시적인 release 요청을 받은 경우에만 해당 검사의 -Build -Release를 사용한다.
  실제 출시 AAB에서 테스트 기능 제거, 음원/폰트/레벨 자산, 신규 권한 유무를 확인한다.
  동일 조건 통합 전/후 AAB로 게임 추가 용량을 확정한다.
  정적 검사·debug 빌드 성공을 실기기 또는 출시 AAB 검증 PASS로 확대하지 않는다.
  ShiftBell 본체의 기존 출시 잔여는 별도로 유지한다. 특히 UPDATE-01의
  Google Play 실제 업데이트 확인은 독립 게임 APK 검사로 대체할 수 없다.

5. 용량 — 실측과 추정 구분
============================================================
2026-10-15 dev debug AAB의 게임 전용 자산 엔트리 합계:
  효과음6개             압축 전109,418 bytes / AAB 저장92,896 bytes (약90.7KiB)
  게임 전용 자산 전체   압축 전467,461 bytes / AAB 저장185,240 bytes (약180.9KiB)

전체 자산은 레벨100개, 한·영 힌트, 부분 글꼴, 스플래시1장, 효과음6개다.
위 값에는 게임 AOT 코드, Native DEX, 아이콘, ZIP 메타데이터가 포함되지 않는다.
공유 Flutter 엔진을 게임 추가 용량으로 중복 계산하지 않는다.
debug APK/AAB 전체 크기는 출시 게임 크기의 근거로 사용하지 않는다.

ShiftBell 통합 후 복수ABI AAB 증가분의 보수적 계획치: 약1~3MB.
이 숫자는 코드 포함 실측값이나 보장 상한이 아니다.
정확한 최종 값은 SP-06의 통합 전/후 출시 AAB 비교로 확정한다.

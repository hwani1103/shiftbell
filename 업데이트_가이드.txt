[A] 구글 플레이 콘솔에 새 버전 업로드할 때
================================================================

총 2개 파일에서 숫자를 올려야 합니다.

----------------------------------------------------------------
파일 1:  pubspec.yaml
위치:    c:\Users\Administrator\Desktop\shiftbell\pubspec.yaml
----------------------------------------------------------------

이 파일을 열면 위쪽에 다음 줄이 있습니다.

   version: 1.0.11+13

이 줄의 의미는 이렇습니다.

   1.0.11   ← "사용자에게 보이는 버전 이름" (versionName)
   +13      ← "구글 플레이가 내부적으로 구분하는 번호" (versionCode)

업데이트 규칙:
   - 작은 수정 / 버그 픽스만 한 경우  → 마지막 자리만 +1
       예) 1.0.11+13   →   1.0.12+14
   - 기능을 추가/변경한 경우         → 가운데 자리 +1, 마지막은 0
       예) 1.0.11+13   →   1.1.0+14
   - 큰 변화 / 메이저 업그레이드     → 첫 자리 +1
       예) 1.0.11+13   →   2.0.0+14

★ 핵심: 어떤 경우든 "+ 뒤의 숫자(13)"는 반드시 +1 (14가 됨) 해야 합니다.
        구글 플레이는 이 숫자가 같으면 같은 버전으로 보고 거부합니다.


----------------------------------------------------------------
파일 2:  android/app/build.gradle.kts
위치:    c:\Users\Administrator\Desktop\shiftbell\android\app\build.gradle.kts
----------------------------------------------------------------

이 파일을 열면 중간쯤에 다음 두 줄이 있습니다.

   versionCode = 13
   versionName = "1.0.11"

★ 이 두 값은 위의 pubspec.yaml과 정확히 일치해야 합니다.

업데이트 방법:
   - pubspec.yaml에서 1.0.11+13 을 1.0.12+14 로 바꿨다면
       versionCode = 13   →   versionCode = 14
       versionName = "1.0.11"   →   versionName = "1.0.12"

   - 1.1.0+14 로 바꿨다면
       versionCode = 14
       versionName = "1.1.0"


----------------------------------------------------------------
요약 표 (참고용)
----------------------------------------------------------------

  pubspec.yaml의       =   build.gradle.kts의       =   build.gradle.kts의
  "version: A.B.C+D"       'versionName = "A.B.C"'      'versionCode = D'

  예시:
    1.0.11+13              versionName = "1.0.11"        versionCode = 13
    1.0.12+14              versionName = "1.0.12"        versionCode = 14
    1.1.0+15               versionName = "1.1.0"         versionCode = 15
    2.0.0+16               versionName = "2.0.0"         versionCode = 16

★ 두 파일에서 같은 값으로 맞추는 것만 기억하세요.

이 파일을 열면 위쪽(28번째 줄 부근)에 다음과 같은 부분이 있습니다.

   const Map<String, String> _lunarHolidays = {
     // 2025년
     '2025-01-28': '설날',
     ... 중간 생략 ...
     // 2029년
     '2029-02-12': '설날',
     '2029-02-13': '설날',
     '2029-02-14': '설날',
     '2029-05-07': '대체공휴일',
     '2029-05-20': '부처님오신날',
     '2029-05-21': '대체공휴일',
     '2029-09-21': '추석',
     '2029-09-22': '추석',
     '2029-09-23': '추석',
     '2029-09-24': '대체공휴일',
   };

마지막 } 바로 위에 새 연도를 추가하면 됩니다.

----------------------------------------------------------------
틀 (그대로 복사해서 쓰세요)
----------------------------------------------------------------

  // YYYY년
  'YYYY-MM-DD': '설날',
  'YYYY-MM-DD': '설날',
  'YYYY-MM-DD': '설날',
  'YYYY-MM-DD': '대체공휴일',
  'YYYY-MM-DD': '부처님오신날',
  'YYYY-MM-DD': '대체공휴일',
  'YYYY-MM-DD': '추석',
  'YYYY-MM-DD': '추석',
  'YYYY-MM-DD': '추석',
  'YYYY-MM-DD': '대체공휴일',


★ 사용 방법 ★

1. 위 틀을 복사
2. 'YYYY-MM-DD' 부분을 실제 날짜로 변경 (반드시 작은따옴표 ' ' 안에)
3. 필요 없는 줄(예: 그 해에 대체공휴일이 없으면)은 통째로 삭제
4. 마지막 } 바로 위에 붙여넣기


----------------------------------------------------------------
실제 예시 (2030년을 추가한다고 가정)
----------------------------------------------------------------

원래 모습:

   '2029-09-24': '대체공휴일',
   };

→ 다음과 같이 바꿉니다:

   '2029-09-24': '대체공휴일',
   // 2030년
   '2030-02-03': '설날',
   '2030-02-04': '설날',
   '2030-02-05': '설날',
   '2030-05-09': '부처님오신날',
   '2030-09-12': '추석',
   '2030-09-13': '추석',
   '2030-09-14': '추석',
   };

★ 주의사항 ★

  - 날짜는 반드시 'YYYY-MM-DD' 형식 (예: '2030-02-03')
  - 월(MM), 일(DD)이 한 자리 숫자면 앞에 0 붙이기 ('02-03' O / '2-3' X)
  - 각 줄 끝의 쉼표(,)는 반드시 있어야 함
  - 작은따옴표(') 사용. 큰따옴표(") 쓰면 에러
  - 마지막 } 는 그대로 두기

================================================================
[C] 자주 하는 실수와 해결 방법
================================================================

▶ "구글 플레이가 같은 versionCode 라며 거부함"
   → pubspec.yaml의 + 뒤 숫자와 build.gradle.kts의 versionCode가
     이전 업로드 때보다 커야 합니다. 둘 다 +1 했는지 확인.

▶ "두 파일의 버전이 다르다"
   → 두 파일을 다 저장했는지 다시 확인.
     pubspec.yaml: 1.0.12+14
     build.gradle.kts: versionName = "1.0.12", versionCode = 14
     이 세 곳이 항상 일치해야 합니다.

▶ "공휴일을 추가했는데 앱에서 안 보임"
   → 1) 새 버전을 빌드하고 폰에 다시 설치했는지 확인
     2) 날짜 형식이 'YYYY-MM-DD' 인지 확인 (하이픈 - 두 개)
     3) 줄 끝에 쉼표(,) 있는지 확인
     4) 작은따옴표(') 사용했는지 확인 (큰따옴표 안 됨)

▶ "flutter build appbundle 명령이 안 먹힘"
   → 명령창을 프로젝트 폴더에서 열었는지 확인
     cd c:\Users\Administrator\Desktop\shiftbell
     로 이동한 다음에 입력해야 합니다.

▶ "에러 메시지가 빨간 글씨로 잔뜩 뜸"
   → 당황하지 말고 마지막에 출력된 줄을 잘 보세요.
     보통 어떤 파일의 몇 번째 줄에 문제가 있다고 알려줍니다.
     쉼표(,) 누락 / 따옴표 짝 안 맞음 이 가장 흔한 원인입니다.

[D] AAB 빌드 파일 위치 및 구글 플레이 콘솔 업로드 절차
================================================================

----------------------------------------------------------------
AAB 파일은 어디에 만들어지나요?
----------------------------------------------------------------

빌드 명령:
   flutter build appbundle --release

빌드 성공 시 다음 위치에 .aab 파일이 생성됩니다.

   c:\Users\Administrator\Desktop\shiftbell\build\app\outputs\bundle\release\app-release.aab

★ 이 .aab 파일이 구글 플레이 콘솔에 올릴 파일입니다.
   파일 크기는 보통 40~50MB 정도입니다.

★ 빌드는 시간이 오래 걸립니다 (보통 5~8분).
   "Running Gradle task 'bundleRelease'..." 메시지가 뜨면 그냥 기다리세요.
   끝나면 "√ Built build\app\outputs\bundle\release\app-release.aab" 메시지가 뜹니다.


----------------------------------------------------------------
빌드 전 준비사항 (이미 다 되어 있어서 그대로 따라하시면 됩니다)
----------------------------------------------------------------

이미 설정 완료된 것들 (다시 안 해도 됨):
   ✅ 키스토어 (key.properties)
   ✅ 서명 설정 (build.gradle.kts의 signingConfigs)
   ✅ 패키지 이름 (com.hwani1103.shiftbell)
   ✅ 구글 플레이 콘솔 앱 등록
   ✅ 업로드 키 등록

매 업데이트마다 해야 할 것:
   1. [A] 섹션 보고 pubspec.yaml과 build.gradle.kts에서 버전 +1 (필수)
   2. (필요하면) [B] 섹션 보고 공휴일 추가
   3. 아래 빌드 절차 실행
   4. 아래 업로드 절차 실행


----------------------------------------------------------------
빌드 절차 (PowerShell에서)
----------------------------------------------------------------

1단계: PowerShell 열기 (Win+R → "powershell" 입력 → 엔터)

2단계: 프로젝트 폴더로 이동

   flutter pub get

   → 끝에 다음 메시지가 뜨면 성공입니다:
       √ Built build\app\outputs\bundle\release\app-release.aab

6단계: AAB 파일 위치 확인
   탐색기에서 다음 폴더 열기:
   c:\Users\Administrator\Desktop\shiftbell\build\app\outputs\bundle\release\

   → app-release.aab 파일이 보이면 성공.


----------------------------------------------------------------
구글 플레이 콘솔 업로드 절차
----------------------------------------------------------------

1단계: 구글 플레이 콘솔 접속
   주소: https://play.google.com/console
   → 로그인 → "교대종" 앱 클릭

2단계: 좌측 메뉴에서 "프로덕션" 클릭
   (또는 "테스트 → 내부 테스트" 등 원하는 트랙)

3단계: 우측 상단의 "새 버전 만들기" 버튼 클릭
   (또는 "새 출시 버전 만들기")

4단계: "App Bundle" 영역에 .aab 파일 업로드
   → "업로드" 버튼 클릭
   → 위에서 만든 app-release.aab 파일 선택
   → 업로드 완료까지 대기 (1~3분)

5단계: 출시명 (Release name) 입력
   → 자동으로 버전이 채워짐 (예: "1.0.12 (14)")
   → 그대로 둬도 OK

6단계: "이 버전의 새로운 기능" 입력
   → 사용자에게 보여질 변경사항 작성
   → 한국어로 적으면 됨
   → 예시:
       - 알람 정확도 개선
       - 자동 갱신 시스템 안정화
       - 일부 버그 수정

7단계: "다음" 버튼 클릭

8단계: 검토 페이지에서 "출시 시작" 버튼 클릭
   → 주의: 클릭하면 단계적 출시 시작됨
   → 한 번 출시하면 같은 버전으로 다시 못 올림 (그래서 [A] 섹션의 +1이 필수!)

9단계: 검토 대기
   → 구글이 자동 검토 (보통 2~24시간)
   → 검토 완료되면 사용자들에게 자동 배포 시작

중요한 주의사항
----------------------------------------------------------------

▶ 업로드 키 비밀번호를 잊었을 때
   → key.properties 파일을 열어보세요
   → 거기에 비밀번호가 평문으로 저장되어 있습니다
   → 위치: c:\Users\Administrator\Desktop\shiftbell\android\key.properties

▶ "이 APK는 이미 업로드되었습니다" 에러
   → [A] 섹션 다시 보고 versionCode가 이전보다 +1 됐는지 확인
   → 두 파일(pubspec.yaml, build.gradle.kts) 모두 +1 했는지 확인

▶ "App Bundle is signed with the wrong key" 에러
   → key.properties 파일이 올바른 키스토어를 가리키는지 확인
   → 키스토어 위치도 확인 (보통 android 폴더 안에)
   → 이건 정말 드물고, 한번 빌드 성공한 이후로는 안 일어남

▶ 빌드가 너무 오래 걸리거나 멈춘 경우
   → Ctrl+C로 중단
   → flutter clean 후 다시 시도

▶ 빌드 실패 메시지 (빨간 글씨)
   → 마지막 줄을 잘 보세요. 어떤 파일의 몇 번째 줄에 문제가 있다고 알려줍니다.
   → 보통 [A]에서 버전 올리다가 실수했거나 [B]에서 공휴일 추가하다가
     쉼표 / 따옴표 실수가 원인입니다.

▶ 출시 후 며칠 동안 사용자들에게 안 보이는 경우
   → 정상입니다. 구글의 단계적 배포로 1~3일 걸릴 수 있습니다.
   → 출시 직후 설치한 사용자도 자동 업데이트는 24시간~며칠 후에 적용됩니다.
   → 강제 업데이트는 사용자가 플레이스토어에서 직접 누르면 가능.

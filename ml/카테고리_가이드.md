# 메모 자동분류 카테고리 가이드 (Phase 0)

> `메모_자동분류_ML_계획.md`의 범주 설계를 데이터 생성/검수용으로 그대로 옮긴 것.
> 데이터를 만들거나 라벨을 검수할 때 항상 이 정의와 우선순위를 기준으로 판단한다.

## 카테고리 정의 (9개 + 기타)

| 카테고리 | 정의 |
|---|---|
| 업무 | 구체적 업무 이벤트(회의/보고/마감/출장). 근무 시간대 자체가 아니라 "근무 중 특정 이벤트"에 한정 |
| 공부 | 자격증/시험/강의/독서/스터디 등 학습 활동 |
| 운동 | 신체 활동 자체가 목적(러닝/헬스/요가/구기/등산). 강도·훈련 의도가 드러나면 이쪽 |
| 병원·건강관리 | 진료/약/검진/치과/헌혈 등 관리·치료 목적. 단련이 목적이면 운동, 관리/치료가 목적이면 이쪽 |
| 식사 | 끼니 관련, 사람을 만나는 게 목적이 아닌 경우 |
| 약속/사교 | 사람을 만나는 것 자체가 목적. 활동이 곁들여져도 만남이 핵심이면 우선 |
| 가족 | 가족 구성원(부모/형제/배우자/자녀/친족)이 대상이면 최우선 |
| 쇼핑 | 구매/장보기 |
| 여가/휴식 | 취미·영화·카페·나들이(능동) + 낮잠·늘어지기(수동) 통합. 목적이 힐링/기분전환/놀이면 이쪽 |
| 기타 | 위에 명확히 속하지 않거나(생활 잡무, 막연한 메모), 모델 확신도가 낮을 때 |

## 우선순위 규칙 (라벨 충돌 시)

**가족 > 약속/사교 > (운동/공부/식사/업무/쇼핑 등 활동 특정형) > 여가·휴식 > 기타**

⚠️ 이 순위는 "누구와 관련됐나"가 충돌할 때(가족 vs 사교) 쓰는 것이지, "무엇을 하나"가
명확한 활동(쇼핑, 운동 등)에는 가족 구성원이 언급됐다는 이유만으로 적용하지 않는다.
(아래 쇼핑↔가족 항목 참고)

## ⚠️ 라벨링 시 주의 (2026-08-26, 실사용 데이터로 발견)

**"형/누나/언니/오빠/동생"은 혈연이 아니라 친한 사람을 부르는 호칭으로도 매우 흔히
쓰인다.** "친한 형 가게 오픈해서 축하금 송금"은 친형이 아니라 가까운 지인을 뜻하며
가족이 아니라 사교로 분류해야 함. 문장만 보고 판단하기 어려우면 문맥(가게를 차린
사람이 나이 차이만 있는 지인인지, 실제 가족 행사인지)을 보고 정하고, 정 애매하면
기타로 두는 게 낫다.

## 자주 헷갈리는 경계 (판단 기준)

| 경계 | 기준 |
|---|---|
| 운동 ↔ 여가/휴식 | 강도·훈련 의도(땀날 정도, 왕복 횟수, 정상 정복 등)가 명시되면 운동. "살살", "바람쐬러", "슬슬" 등 힐링/놀이 뉘앙스면 여가 |
| 가족 ↔ 약속/사교 | 만나는 대상이 직계/친족이면 가족. 친족이 매개했어도 실제로 만나는 대상이 비친족이면 사교 |
| 식사 ↔ 약속/사교 | 문장의 핵심 목적어가 "먹는 것"이면 식사, "누구를 만나는 것"이면 사교 (식사가 곁들여져도) |
| 업무 ↔ 공부 | 회사 업무를 위한 산출물/보고 성격이면 업무, 개인의 학습·자격 취득이 목적이면 공부 |
| 쇼핑 ↔ 가족 | **핵심 동사가 "사다/주문하다/구매하다"면 대상이 가족(아이 옷, 부모님 선물 등)이어도 쇼핑.** "가족 우선" 규칙은 가족↔사교(누구를 만나느냐)에만 적용되고, 가족↔쇼핑(뭘 하느냐)에는 적용 안 됨 — 구매 행위 자체가 핵심이면 쇼핑 |

`data/boundary_cases.jsonl`에 위 4개 경계마다 실제 예문 + 판단 근거를 넣어뒀다.

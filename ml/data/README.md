# 학습 데이터

Phase 1 파일럿(400개, 사람이 손으로 쓴 것)에서 시작해 Phase 5(5,230개)를 거쳐
2026-09-01 카테고리 확장(Phase 8, `ml/generate_v2_data.py`로 신설 7종용
2,024개 템플릿 조합 생성 추가)까지 누적된 상태. 아래는 2026-09-03 기준 개수.

| 파일 | 개수 | 용도 |
|---|---|---|
| `pilot_dataset.jsonl` | 8,475 | 카테고리별 순수 예문 |
| `boundary_cases.jsonl` | 202 | 경계쌍(운동↔여가, 가족↔약속, 쇼핑↔가족, 문화생활↔여가/사교, 금융↔업무/기타, 집안일↔쇼핑/가족, 미용↔공부/쇼핑, 달리기·수영·등산↔쇼핑/사교 등) 각각 정답 라벨 + 판단 근거(`rationale`) 포함 |
| `eval_holdout.jsonl` | 102 | 학습에 절대 섞지 않는 평가 전용 세트. 범주당 6개 내외, 의도적으로 짧고 축약된 문체(타이핑하듯)로 pilot_dataset과 다른 스타일 |
| `user_batch1.jsonl` | 500 | 실사용자 문체 500개 - **구 10종 라벨 그대로**라 train.py가 안 읽음(카테고리 확장 대상에서 제외됨, `ml/카테고리_가이드.md` 참고) |

**학습에 쓰는 것**: `pilot_dataset.jsonl` + `boundary_cases.jsonl` (8,677개)
**평가만 하는 것**: `eval_holdout.jsonl` (102개) — 이 세트로 정확도가 크게 떨어지면
"학습 데이터 특유의 문체에 과적합" 신호로 본다.

⚠️ **eval_holdout.jsonl로 정확도를 잴 때는 `ml/evaluate.py`가 아니라
`ml/eval_e2e.py`를 쓸 것** - `evaluate.py`는 `keyword_router.py` 하드매핑을 안 거치고
순수 ML 모델만 테스트해서(실제 Dart 앱 파이프라인과 다름) 비관적인 숫자가 나온다.
`eval_e2e.py`는 `predict.py`와 동일하게 하드매핑 -> ML 순서로 돌려서 실제 체감
정확도에 가까운 숫자를 낸다(2026-09-03 - 이 차이를 몰라서 "정확도가 77%밖에
안 된다"고 오판할 뻔했다가 발견함. 하드매핑까지 합치면 eval_holdout 81%였음).

## 다양성 확보를 위해 넣은 것

- 직접 키워드형("헬스장 가서 웨이트") + 간접 표현형("퇴근하고 땀 좀 빼고 들어가기") 혼합
- 길이 다양화: 3~4어절 단문 ~ 긴 문장
- 시간 표현 다양화(오후 2시 / 아침 / 자기전에 / 새벽 / D-3 등)
- 구어체·축약형(GX, PT, 코테, 인강), 영어 혼용
- `기타`는 잡무·막연한 감정 메모·확신도 낮은 사례 위주로 다른 범주보다 많이 확보
- (2026-09-01 추가분) 신설 7종은 템플릿 슬롯 조합(시간 표현 x 활동 표현)으로
  생성하되, 직접 키워드형과 하드매핑 키워드가 아예 없는 간접 표현형("한강에서
  5km 뛰고 오기"처럼 "달리기"라는 단어 없이도 ML이 문맥으로 배워야 하는 문장)을
  섞어서 하드매핑에만 의존하지 않도록 함

- (2026-09-01 2차 추가분) 어미 다양성 보강 980개(`ml/generate_ending_variety.py`)
  - "OO하기"로 끝나는 기존 문장을 어간이 안전한 "하다" 활용형(하자/해야지/
    해야됨/할까/할거임/했음/한 듯)으로 바꿔서 같은 라벨로 추가. 실측해보니
    기존 데이터에 이런 캐주얼한 의지/예정 표현이 사실상 전무했음(5건 미만).
    "가기/사기/먹기"처럼 "하다"가 아닌 동사(불규칙 활용 포함)는 이번 스코프
    밖 - 필요하면 후속으로 진행.

- (2026-09-03 추가분) 짧은 노트 스타일 170개(`ml/generate_terse_style.py`)
  - `eval_e2e.py`(하드매핑+ML 실제 파이프라인)로 eval_holdout.jsonl을 돌려본 결과
    가장 큰 실패 패턴이 "동사 없이 명사만 던지는 축약 메모"("넷플릭스", "택배확인",
    "환전 얼마나"류 - eval_holdout이 의도한 스타일 그 자체)였음 - margin이 낮아서
    ML+margin 필터가 대부분 "기타"로 떨어뜨림. pilot_dataset이 "-하기"로 끝나는
    완결된 문장 위주라 이 스타일 표본이 부족했던 게 원인으로 보여서 17개 카테고리
    전부에 짧은 noun-phrase 예문을 새로 씀(eval_holdout과 안 겹치게 - 겹치면
    평가셋이 오염됨). 재학습 후 eval_holdout 81.4%→87.3%, boundary_cases
    83.7%→85.6%(둘 다 `eval_e2e.py` 기준 - 하드매핑 포함).

## 하드매핑(`ml/keyword_router.py`) 관련 발견 (2026-09-03)

- **조사가 여러 개 겹쳐 붙으면 매칭 실패하던 버그** - `_word_matches_token`이
  "어절에서 키워드를 뗀 나머지(rest)가 조사 목록의 항목 '하나'와 정확히 일치"할
  때만 통과시켰는데, 한국어는 "친구들과의"(친구+들+과+의)처럼 조사가 여러 개
  겹쳐 붙는 게 흔함 - rest="과의"가 되는데 "과"/"의" 개별로는 있어도 "과의"
  자체는 목록에 없어서 실패, "친구"라는 명백한 지인 신호를 놓쳐 "며느리
  친구들과의 모임"류가 가족으로 잘못 확정되는 실측 버그로 이어짐. 조사를
  재귀적으로 여러 개 벗겨내는 `_particle_suffix_ok`로 교체해서 해결(전체
  검증 net 3건 개선, 회귀 0건 - `_particle_suffix_ok` 자체를 이식할 때 "로"도
  같이 넣어봤으나 "등산로"/"조깅으로" 오탐이 발견돼서 뺐음, 자세한 내용은
  `keyword_router.py`의 관련 주석 참고). `memo_category_classifier.dart`에도
  동일하게 이식함.
- **"넷플릭스" 하드매핑을 시도했다가 뺌** - "넷플릭스"류 문장이 실측 데이터 자체에서
  문화생활 18건 vs 여가/휴식 8건으로 갈려 있어서(같은 "넷플릭스 정주행" 표현도
  양쪽에 다 있음) 하나로 단정할 만큼 명확하지 않다고 판단, ML+margin 판단에
  맡김(재학습 후에도 "넷플릭스 보기"는 문화생활로 예측 - 데이터 다수결과 일치).
- **"캠핑"도 시도했다가 뺌** - "캠핑용품/캠핑의자 주문·구매"처럼 장비 구매
  문장과 충돌(러닝화/등산화와 같은 "장비 구매는 쇼핑" 원칙 위반).
- **PURCHASE_MARKERS는 일부러 그대로 비활성 유지** - "아이 옷 사기"류가
  가족으로 하드매핑되는 게 데이터 다수 기준으로는 부정확해 보이지만, 2026-08-26에
  이미 "생신 선물 사기"처럼 기념일 맥락 구매는 가족이 맞다는 실사용 데이터
  근거로 의도적으로 비활성화된 것 - 재활성화하면 그 케이스들이 회귀함. 건드리지
  않음.
- 새 하드매핑: "코테"(공부, "인강"과 같은 원리) / "집콕"·"방탈출"(여가/휴식) -
  전체 검증(`check_keyword_regressions.py`) 충돌 0건 확인 후 추가.
